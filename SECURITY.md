# Security policy

## Supported versions

Omnora is still in the design phase and has no published source or runnable release. No version currently receives security updates.

## Current reporting status

The repository does not yet have a private vulnerability-reporting channel or a designated public security contact. Until one is enabled, the project cannot safely receive confidential vulnerability details.

- Do not post exploit code, credentials, personal data, or other sensitive details in a public issue or discussion.
- Non-sensitive mistakes in the public design documents may be reported publicly, provided the report does not reveal an exploitable technique or secret.
- Do not send a copyright-bearing patch while the contribution restriction in [CONTRIBUTING.md](CONTRIBUTING.md) remains active.

Before the first public source or runnable release, the maintainers must enable GitHub private vulnerability reporting or publish a monitored security email address, then update this file with the exact channel, encryption option, expected response window, supported versions, and disclosure process.

## Future reports

Once a private channel is published, a useful report should include the affected version, deployment conditions, impact, reproduction steps, and any known mitigation. Reporters should allow a reasonable remediation period before public disclosure and avoid accessing data that is not their own.

No response-time or remediation SLA is promised until a maintainer contact and supported release exist.
