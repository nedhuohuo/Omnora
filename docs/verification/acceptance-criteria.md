# Omnora 第一版验收标准

状态：账号—挂载目标模型发布门槛；MCP 契约已冻结
日期：2026-08-08

> 本文按已确认的账号—挂载模型验收；只有实际协议测试和在线脱敏证据可以证明对应门禁通过。

以下条件全部通过后，第一版才可以标记为可发布。详细业务和安全语义分别以[产品需求](../requirements/product-requirements.md)、[领域模型](../design/domain-model.md)、[技术架构](../design/architecture.md)和[安全模型](../security/security-model.md)为准。

## 1. 功能验收

- 系统初始化只创建一个受保护默认挂载，初始管理员个人目录自动可用；新增账号成功时自动获得且只获得一个个人目录，目录创建失败时没有可登录的半成品账号。
- 个人目录使用稳定账号 ID 命名；修改显示名称不改物理目录。账号删除后目录和物理文件保留，旧访问及派生能力失效，新账号不能继承。
- 账号只能访问默认挂载中的自己的个人根，猜测兄弟目录路径、文件 ID、搜索或 MCP 请求均不能访问其他账号个人文件。
- 默认挂载不能删除、由管理员主动停用、改根、转为共用挂载或写入普通挂载授权；底层故障则进入系统判定的 `unavailable`。
- 后续挂载全部是独立授权的外部共用挂载，允许零授权；注册直接使用所选 NAS 目录，不创建托管共用挂载或其他隐式业务子目录。
- 普通挂载由所有管理员治理；受限挂载只有初始管理员能从治理控制面直接发现、创建、配置、授权、重新验证和解除。
- 普通管理员不能从管理列表、直接 ID、索引任务、健康状态、统计、审计、备份清单或普通错误响应发现受限挂载，也不能给自己授权。创建或重命名普通挂载时，与隐藏挂载或其他不可用条件发生冲突均只返回通用 `mount_unavailable`，不暴露冲突类型、对象、名称、路径或治理类型，并验证限速和审计；验收不把主动候选资源占用探测列入隐藏承诺。
- 普通管理员获受限挂载 `viewer/editor` 后只能访问内容，不能治理；初始管理员未获内容授权时也不能浏览内容。
- 在成员内容面、文件 REST/MCP、搜索和成员可见审计中，未授权普通挂载 ID 与不存在 ID 的响应不可区分；管理员控制面仍按治理权限展示普通挂载。未授权或受限挂载不能通过搜索、MCP、命中数、过滤器、排除原因、缓存或过期索引泄露。普通管理员获受限挂载内容权后，成员 DTO 也不返回治理类型或授权名单。
- 普通/受限治理类型创建后不可切换；改变类型必须解除并使用新挂载 ID 重新注册，旧授权不恢复。
- 解除共用挂载要求精确输入规范化后全局唯一且忽略大小写的当前显示名称，使授权、索引、分享、Token boundary、Transfer Ticket、上传和任务失效，但服务器真实目录和用户文件保持不变；挂载 tombstone 永久保留，失效临时分片由幂等清理处理，同一路径可用新 ID 重新注册且不继承旧状态，审计记录 `dataDeleted: false`。
- 不加入索引的共用挂载仍可浏览和操作；全局搜索排除该挂载并明确提示。默认个人索引按账号根裁剪，“我的文件”可搜索但不会返回兄弟账号结果。
- `viewer`、`editor`、个人目录所有者和管理员治理权限的行为与权限矩阵一致；治理权限不自动授予内容权限。
- 支持分片上传、断点续传、Range 下载、复制、移动、改名和批量操作。
- 个人目录、外部读写共用挂载和收到协作中的删除统一执行个人回收站阈值规则：单个文件不超过 200 MB 且批次不含超限文件时进入删除者回收站；超过阈值时只能明确确认永久删除。外部只读挂载拒绝全部写操作。
- 跨挂载复制和移动具备成功、失败、重试和人工清理路径；移动源端要求 `editor+` 且可写。
- 图片、PDF、文本、Markdown 和浏览器原生音视频按设计预览；Office 文件始终走下载。
- REST 与 MCP 提供已定义的首版能力，并与 Web 使用相同授权结果。
- MCP Wire Protocol：implemented and protocol-tested（MCP Inspector Modern，`2026-07-28`；兼容性测试覆盖 `2025-11-25`）。
- Omnora AI Token Authorization：implemented, non-OAuth。
- MCP OAuth Authorization Profile：NOT IMPLEMENTED。
- MCP 工具目录包含 `files.update`，不含已移除的旧资源工具；工具、scope 和逐操作 MRTR 数量以当前 catalog 为准。
- 15 个 scope 必须逐项覆盖：`mounts:read`、`files:list`、`files:metadata`、`files:text`、`files:download_ticket`、`search:read`、`uploads:create`、`files:write`、`files:trash`、`trash:read`、`files:restore`、`files:purge`、`shares:read`、`shares:create`、`shares:revoke`。
- `mounts.list` 无输入且只返回账号实时获权的共用挂载；默认个人挂载的 ID、名称和兄弟账号目录不出现在工具结果、普通挂载管理 API 或 Token boundary。
- MCP 文件 locator 只接受显式 `personal` 或 `common_mount` 内容源，并拒绝账号 ID、默认挂载 ID 和目录协作标识。
- Token boundary 只允许 `all_account_content`、`personal`、`common_mount`。“当前账号全部内容源”动态覆盖账号自己的个人目录和全部获权共用挂载；新授权自动加入、撤销立即失效。
- 收到的目录协作始终不能进入 MCP locator、boundary、搜索或 Transfer Ticket；所有尝试均拒绝。
- 大文件只能通过短期 Transfer Ticket：`GET /mcp/transfers/{publicId}` 支持 Range/ETag，`PUT /mcp/transfers/{publicId}/parts/{partNumber}` 支持有界 multipart；每次请求重新验证 Token、实时内容权限、边界、挂载身份和对象指纹。

## 2. 个人目录、协作与分享验收

- 无目录协作的管理员无法浏览、搜索、预览、下载或修改其他账号个人目录内容；管理员账号恢复不授予内容权限。
- 个人目录所有者可以把整个个人根或任意子目录按接收账号授予 `viewer/editor`；根目录协作界面明确警告当前和未来内容都会可见。
- 收到的协作只出现在“协作 / 与我协作”，发出的协作只出现在“我发起的协作”，协作不生成共用挂载。
- 协作 `editor` 只能修改根内内容，不能改名、移动或删除协作根；同一接收账号的父子重叠授权被拒绝。
- 撤销协作、来源或接收账号停用/删除、来源对象失效或授权边界变化后，已打开页面、“保存到我的文件”和后续 Web/REST 请求立即失败。收到的协作禁止 MCP boundary、匿名公开分享和再授权第三人。
- “保存到我的文件”复制对象并保留所有者原文件，不能伪装成跨边界移动。
- Web 全局搜索包含当前有效的收到协作，标记来源、按对象去重并实时复核；“我发起的协作”不产生重复结果。
- Omnora 内部同挂载移动后分享保持有效。
- 跨挂载移动、外部移动、删除、替换对象或创建者失去公开分享创建资格后，原分享失效。
- 创建分享时一次性展示的可复制链接必须把秘密放在 URL `#fragment` 中；path 与 query 不得包含分享秘密；关闭一次性展示后不能再次显示完整秘密。
- 访客换票遵循 fragment → `POST` 交换分享会话的流程：无 fragment 不向服务端提交秘密；`password_required` 与换票失败不消耗访问次数；换票成功后立即清理地址栏 fragment，并按安全模型预占一次访问次数；同一分享会话内刷新不重复计数。
- 服务端拒绝通过 URL 路径、查询参数或 `Referer` 提交的分享秘密：此类请求不得建立分享会话，也不得计为成功访问；合法秘密只接受前端从 fragment 读取后放入 `POST` 请求体的提交方式。
- 分享密码、有效期、访问次数、下载次数和撤销立即生效。
- 个人文件只有所有者能创建公开分享；共用挂载默认允许 `editor` 创建且可由具有治理权的管理员关闭；收到的协作始终拒绝。
- 共用挂载 `viewer` 创建公开分享失败；关闭挂载公开分享开关立即使既有分享及派生会话失效。普通挂载开关可由任一管理员治理，受限挂载开关仅初始管理员可治理，获内容授权的普通管理员也不能修改受限挂载策略。
- 高并发请求不能突破分享次数上限；Range 和取消下载的计数策略与安全模型一致。

## 3. 凭证与权限验收

- 浏览器会话、AI Token、匿名分享和目录协作均按安全模型的统一公式验收：路由组、主体、凭证、实时内容权限来源、对应入口适用的 scope 与资源/目录边界、挂载状态/身份/模式、对象状态与保留命名空间规则、操作级配额/限速/并发限制任一不满足即拒绝。
- 成员只能管理自己的 Token；管理员只能查看元数据和撤销，不能读取明文。
- 普通管理员查看账号 Token 时，无权资源边界使用统一脱敏表示，字段存在性、列表数量和摘要均不能泄露受限挂载；撤销 Token 不要求获得其内容权限。
- 账号禁用、挂载授权或协作降级、Token 或分享撤销后，活动 MCP 会话、上传会话和短期下载地址立即失去对应权限。
- 两个并发初始化请求只能有一个成功；系统没有默认账号或默认密码。
- 管理员锁定恢复不会重新开放网络初始化入口，并使旧会话和旧 TOTP 失效；恢复后管理员可用新密码直接获得完整会话，不强制重新登记 TOTP。
- 管理员与成员的 TOTP 均为可选：未启用时可正常登录与管理；已启用后登录/重新认证需验证码；管理员可像成员一样停用 TOTP。
- 任一管理员可以把成员提升为普通管理员，停用、恢复或删除普通成员，并降级、停用、恢复或删除其他普通管理员；普通管理员不能操作初始管理员，任何管理员都不能提升、降级、停用或删除当前登录的自己。

## 4. 文件系统安全验收

- 挂载注册拒绝相同路径、双向父子路径、符号链接根或父组件、不同容器路径 bind 到同一来源，以及 bind 来源父子关系；路径组件比较不误判 `/data/a` 与 `/data/ab`。
- 无法读取或证明挂载身份时返回 `mount_identity_unverifiable`，管理员不能绕过。两个管理员并发注册冲突挂载时最多一个成功。
- 启动、恢复、重新启用或扫描前发现 bind 来源被替换、身份漂移或新冲突时，挂载进入 `unavailable`、搜索排除其索引，所有入口拒绝分享和文件访问。普通挂载可由任一管理员重新验证，受限挂载和默认个人挂载只允许初始管理员处理。
- 路径穿越、绝对路径、符号链接逃逸、magic link、挂载点越界和大小写混淆测试均被拒绝。
- 在权限检查与实际打开之间替换文件、符号链接、目录或挂载点时，Web、REST、MCP 和分享入口均不能越界。
- 用户不能创建、覆盖、移动、分享或通过 AI 访问 `.omnora` 保留命名空间。
- 单个文件不超过 200 MB 时进入删除者自己的个人回收站并计入其容量；超过 200 MB 时普通回收站操作被拒绝，只有明确永久删除确认可以继续。目录或批量选择中只要包含超过 200 MB 的文件，整批回收站操作也被拒绝。
- 回收站恢复优先写回原位置并实时复核 `editor`、挂载状态和路径边界；原位置不可用或已失权时，恢复到删除者“我的文件/从回收站恢复”，且不覆盖同名对象。
- 从共用挂载或协作进入个人回收站时按“预留个人配额、复制、校验、持久化 journal、删除源”执行；注入各阶段失败都不丢失唯一副本。进入回收站立即使公开分享、下载票据和活动写入失效，恢复后不自动恢复旧分享。
- 管理员角色本身不能清理或恢复其他账号的回收站；只有删除者本人，或当前对原目标仍有有效内容权限且被策略明确允许的主体可以操作。默认挂载的系统级故障恢复只能走初始管理员专用修复入口。
- 只读挂载即使应用配置错误或请求来自管理员也不能写入。
- HTML、SVG、XML、伪造 MIME 和未知主动内容不能在认证应用源执行脚本或读取 Cookie。
- 文件名不能通过响应头注入 CR/LF；未知格式默认作为附件下载。

## 5. 网络验收

- 应用只提供单一 HTTP 监听地址；局域网或公网访问范围由 Docker 端口发布、宿主防火墙、安全组和反向代理决定。
- 系统不提供额外的局域网或代理入口配置页/API，不根据来源 IP、私网地址、Host 或客户端提交的转发头自动判断信任。
- 合法代理 CIDR、Host、Origin、CORS 和 MCP Streamable HTTP Origin 校验通过正反向测试。
- 管理端、成员 Web、分享、REST、MCP 和 OpenAPI 可以独立控制是否暴露。
- 反向代理参考部署中，公网 `80` 仅执行 HTTPS 跳转，`443` 终止 TLS 后转发到 HTTP 后端；该后端端口无法从公网直连，Range、流式下载、WebSocket 和 MCP 长连接正常工作。

## 6. 索引与性能验收

- 使用百万级合成元数据验证 keyset 分页和文件名搜索，不使用深层 `OFFSET`。
- 全量扫描单并发、可暂停、可续跑、批次让出，不阻塞高优先级后台任务。
- 文件事件不可用时，对账最终收敛；连续两次全量对账不会重叠。
- 索引中的失效条目不能绕过实时文件系统复核。
- 在极空间 8 GB RAM 环境，空闲内存处于 100 至 300 MB 目标范围，普通操作不超过 500 MB。
- 大文件上传、下载和跨挂载复制使用固定缓冲区，内存不随文件大小线性增长。

## 7. SQLite 与可靠性验收

- WAL 检查点、并发读取、受控单写入和数据库忙状态不会无限阻塞请求。
- 扫描、上传、跨挂载移动和索引更新期间重启 Omnora，任务能够恢复到一致状态。
- 上传配额在并发场景不会超卖；异常退出后的临时分片可以安全回收。
- 挂载离线、权限变化、磁盘不足和外部文件变化均产生明确状态，不误删有效内容。
- 使用 SQLite Online Backup API 或等价方案完成备份和恢复演练，并通过完整性校验。
- 重装或容器重建后，保留原 SQLite/config/managed 数据目录并把外部目录重新挂载到原容器路径时，已注册挂载下的原文件仍可浏览、下载和按原权限使用。
- 从旧备份恢复后，旧会话、Token、公开分享、分享派生会话、下载票据和上传会话均不可继续使用；成员首次登录前必须重设密码。
- 外部挂载在恢复后未经有治理权的管理员重新验证不能自动启用；普通挂载可由任一管理员处理，受限挂载只允许初始管理员处理。
- 默认挂载离线、身份漂移、底层不可写、个人目录丢失和初始化部分失败均进入 `unavailable` 并停止相关访问、搜索、分享、Token 和写入，不静默创建空目录。仅初始管理员可以核对身份和映射、处理孤立准备状态并明确恢复原目录或创建替代目录；删除账号目录不得绑定给新账号。

## 8. 审计与发布验收

- 登录、系统角色、挂载授权与治理类型、目录协作、解除挂载、写操作、分享、Token、REST/MCP 敏感操作和恢复均进入审计；解除挂载审计明确记录 `dataDeleted: false`。受限挂载审计按方案 B 过滤，不能向无权普通管理员泄露对象存在。
- 审计日志不包含密码、Token 明文、分享密钥、文件正文或未脱敏的分享 URL。
- 达到审计保留上限或磁盘安全水位时行为明确，不能静默丢弃关键安全事件。
- `linux/amd64` 和 `linux/arm64` 镜像均构建通过。
- 极空间和普通 Linux Docker Compose 各完成一次部署验证。
- 首个公开源码或可运行版本发布前，[SECURITY.md](../../SECURITY.md) 中必须提供真实可用的私密漏洞报告渠道。
