## 1. 产品定位

Omnora（万境）是面向个人、家庭和小团队的轻量自托管文件管理系统。首版以 NAS 文件为核心，让用户能够在自己的设备上管理、查找、预览和分享文件，并通过受控接口允许 AI 客户端访问明确授权的内容。此处不再使用“数字空间”作为产品领域术语，避免与已移除的 `Space` 实体混淆。

首版优先服务低功耗 NAS，极空间是第一验证平台，同时兼容其他支持容器部署的 NAS 与普通 Linux 主机。产品支持局域网使用、成员账号访问和受控公网分享，但不以企业多租户、跨设备同步或内容智能分析为目标。

### 1.1 首版价值

- 将系统托管的个人文件与 NAS 已有目录统一组织为“我的文件”和独立授权的共用挂载。
- 在不暴露宿主机真实路径的前提下，为成员、访客和 AI 提供一致的授权访问。
- 提供带密码或无密码的文件、文件夹分享。
- 使用浏览器完成常见格式预览，不依赖 NAS 进行重型格式转换。
- 在约 100 万文件规模下提供可控、可暂停的元数据搜索能力。
- 保持安装简单和资源占用可预测，不影响 NAS 的主要存储职责。

### 1.2 首版规模边界

- 单台 NAS。
- 个人、家庭或小团队使用。
- 1 至 20 TB 文件数据。
- 约 100 万个文件和目录条目。
- 低并发成员访问，不承诺企业级高并发或跨节点扩展。

## 2. 核心概念

### 2.1 账号与个人目录

账号是身份和授权主体。系统初始化时创建唯一受保护的默认挂载；初始管理员和以后新增的每个账号，都在该挂载中自动获得一个隔离的个人目录。个人目录不是独立挂载，成员端显示为“我的文件”。默认挂载配置固定为 `read_write` 并使用按账号个人根裁剪的元数据索引；实际不可写、离线或身份异常时进入 `unavailable`。

账号本人对个人目录拥有隐式完整内容权限。管理员身份不会自动获得其他账号个人目录的访问权。个人目录所有者可以把整个个人根或任意子目录按 `viewer/editor` 授权给其他活跃账号协作。

个人目录物理名称使用稳定账号 ID；修改显示名称不改物理目录。账号删除后保留个人目录和全部物理文件，但立即撤销访问，且不得把保留目录自动分配给新账号。

### 2.2 共用挂载

除唯一默认挂载外，后续添加的挂载全部是接入既有 NAS 目录的外部共用挂载；Omnora 不创建托管共用挂载。每个共用挂载独立维护账号授权，不存在团队空间或跨挂载共享 ACL。挂载必须：

- 具有稳定显示名称；
- 明确设置为只读或读写；
- 由管理员单独决定是否建立元数据索引；
- 独立向账号授予 `viewer` 或 `editor`，并允许保持零授权；
- 在离线、权限不足或只读状态变化时显示独立状态；
- 注册外部目录时直接使用所选目录，不创建 `<space-id>` 或其他隐式业务子目录。

首版不允许不同挂载指向相同或重叠的物理目录。相同路径、双向父子路径、符号链接或 magic link、指向同一目录的 bind alias，以及 bind 源之间的父子关系均视为冲突。系统无法证明候选挂载与已有挂载相互独立时必须拒绝激活。

共用挂载分为普通挂载和受限挂载。普通挂载由所有管理员共同治理；受限挂载的治理信息只有初始管理员能够通过常规产品入口发现和治理。无论治理类型，管理员都必须获得显式内容授权才能浏览文件。

普通/受限治理类型在创建时固定，之后不能切换。需要改变时解除注册并以新挂载 ID 重新注册同一物理路径，旧授权和派生能力不恢复。活跃挂载显示名称规范化后全局唯一且忽略大小写。

### 2.3 文件对象与协作

用户、分享链接和 AI 使用稳定的内部文件对象标识访问文件。产品不得向外暴露 NAS 的真实绝对路径。

文件系统中的实际文件是内容的真实来源。元数据索引用于搜索和加速发现，不能代替文件在访问时的权限和存在性检查。

## 3. 用户与权限

### 3.1 用户类型

- 初始管理员：初始化系统，管理成员、普通挂载和全局治理，并独占受限挂载治理与初始身份保护能力。
- 普通管理员：管理成员、普通挂载、系统策略、索引任务，以及治理范围内的分享与凭证；可以操作其他普通管理员，但不能操作初始管理员身份，也不能提升、降级、停用或删除当前登录的自己。
- 成员：管理自己的个人文件和目录协作，并按挂载授权访问共用存储。
- 匿名访客：通过有效分享链接访问分享范围内的文件，不拥有系统账号。
- AI 客户端：不是独立用户。它使用绑定到成员账号的专用 Token，代表该成员执行有限操作。

### 3.2 内容权限

| 能力 | `viewer` | `editor` |
| --- | --- | --- |
| 浏览、授权范围搜索、预览、下载 | 是 | 是 |
| 上传、新建目录、复制 | 否 | 是 |
| 修改、移动、改名、删除 | 否 | 是 |

不再存在内容层 `manager`。只读挂载拒绝所有写入操作，即使操作者是 `editor` 或系统管理员。挂载治理、账号管理和内容访问是彼此独立的权限链。

### 3.3 管理员隐私边界

- 管理员默认不能查看其他账号个人目录或未获内容授权的共用挂载文件。
- 管理员只有获得个人目录协作或共用挂载 `viewer/editor` 后，才能按该权限访问内容。
- 管理员可以查看并撤销其治理范围内资源派生的分享，且所有管理员可以查看账号 Token 的通用安全元数据并撤销 Token，但不能查看明文密钥；普通管理员无权查看的 Token boundary 必须统一脱敏，不得从 Token 或分享元数据发现受限挂载。
- 普通管理员无法从常规产品入口或被动系统输出发现受限挂载的控制面信息；即使被授予内容权限，也不能管理该挂载授权。对已知候选资源的主动占用探测只适用 `FR-013` 的残余侧信道边界。

### 3.4 Token 权限

AI Token 的有效权限始终取以下条件的交集：

1. 对应 REST 或 MCP 路由组当前已启用；
2. 所属成员账号与 Token 当前有效，Token 未过期、未撤销且用途匹配；
3. 所属账号当前拥有的个人目录或共用挂载内容权限；
4. Token 明确配置的操作范围、挂载与目录边界；收到的协作不能建立 MCP Token boundary；
5. 目标挂载当前的只读或读写能力；
6. 目标对象状态与保留命名空间规则；
7. 当前操作的配额、限速和并发限制。

成员权限被收回或挂载变为只读后，相关 Token 必须立即降权，不得保留原授权。成员只能创建和管理自己的 Token；所有管理员可以查看账号 Token 的通用安全元数据并撤销 Token，但不能恢复或查看明文 Token，无权资源边界必须使用与“不存在该边界”不可区分的统一脱敏表示。

Token 可以选择动态的“当前账号全部内容源”，覆盖账号自己的个人目录和当前获权的所有共用挂载；新授权自动进入，撤销授权后立即失效，但不包含收到的协作。

首版只提供面向 AI、REST 和 MCP 的受限 AI Token，不提供通用 PAT 的成员自助创建或管理入口。文档中出现的 `PAT/AI Token` 表述用于覆盖当前 AI Token 及未来可能新增的同类长期凭证；不表示首版开放通用 PAT 产品能力。

## 4. 核心使用场景

### 4.1 初始化与接入 NAS 目录

初始管理员在局域网完成首次初始化。系统创建唯一默认挂载和初始管理员个人目录；新增账号时自动创建个人目录。任一管理员可以把 NAS 已有目录直接注册为普通共用挂载，只有初始管理员可以注册受限共用挂载；创建时设置读写、索引和账号授权，零授权挂载允许存在。

### 4.2 成员管理和查找文件

成员从“文件”进入“我的文件”或获权的“共用存储”，浏览、上传、下载、复制和整理文件；从独立“协作”入口访问收到或发出的个人目录协作。全局搜索覆盖自己的个人目录、获权且已索引的共用挂载和当前有效的收到协作，并对协作结果标记来源、实时复核和去重。

### 4.3 对外分享

个人文件所有者可以创建公开分享。共用挂载默认允许 `editor` 创建公开分享，但具有该挂载治理权的管理员可以关闭；收到的协作不能创建公开分享。分享仍受全局路由组、密码、有效期、预览/下载能力和次数限制约束。

### 4.4 AI 受控访问

成员创建限定资源、目录、操作和有效期的 AI Token。AI 客户端通过 REST 或 MCP 浏览目录、搜索文件、读取受限文本或发起上传，所有操作使用与 Web 相同的账号实时权限并进入审计。

### 4.5 低负载索引

管理员只为确实需要搜索的挂载开启索引。首次扫描和后续对账在后台低优先级运行，可暂停和恢复，不应阻塞目录浏览、上传或下载。

## 5. 功能需求

### 5.1 初始化、账号与会话

- `FR-001`：系统必须通过一次性初始化凭证创建首个管理员；初始化完成后不得再次开放无鉴权初始化入口。
- `FR-002`：管理员必须能够创建、停用和恢复成员账号；恢复只适用于被停用账号，已删除账号不可恢复。
- `FR-003`：管理员与成员均可自行启用或停用 TOTP；未启用时可以正常登录和管理，已启用时登录与近期重新认证必须验证 TOTP。
- `FR-004`：用户必须能够撤销自己的活跃会话；管理员可以撤销指定账号的全部会话。
- `FR-005`：没有其他可用管理员能够处置时，管理员丢失密码或已启用的 TOTP 时，系统必须提供需要 NAS 本地控制权的恢复流程，不得提供远程无鉴权重置。
- `FR-006`：任一管理员可以把成员提升为普通管理员，停用、恢复或删除普通成员，并降级、停用、恢复或删除其他普通管理员；普通管理员不能操作初始管理员，任何管理员都不能提升、降级、停用或删除当前登录的自己。

### 5.2 个人目录与挂载

- `FR-010`：系统初始化必须创建唯一受保护的默认挂载和初始管理员个人目录；新增账号必须自动获得且只获得一个个人目录。个人目录不是独立挂载，失败时不得留下可登录的半成品账号。默认挂载固定 `read_write`，并通过按账号根裁剪的元数据索引支持“我的文件”搜索。
- `FR-011`：默认挂载不得删除、主动停用、改根、改为共用挂载或接受普通挂载授权；发生故障时可以进入系统判定的 `unavailable`。在认证成员上下文中，账号不能访问其他账号的个人根，除非收到目录所有者发出的明确协作；匿名公开分享会话是独立访客边界，不给账号增加个人目录权限。
- `FR-012`：除默认挂载外，后续挂载全部为独立授权的共用挂载。每个挂载允许零授权，并只能向账号授予 `viewer/editor`。
- `FR-013`：系统管理员可以添加或修改普通挂载；受限挂载只有初始管理员可以从治理控制面直接发现和治理。添加时必须明确读写模式、索引模式和治理类型；未完成选择和身份验证前不得激活。激活后 `root_path`、`purpose`、`storage_kind` 和 `governance` 不可修改，变更这些字段必须解除并以新挂载 ID 注册；显示名称、应用读写模式、索引开关和账号授权可由有治理权的管理员修改。普通管理员提交的候选名称或路径与受限挂载或其他不可用条件冲突时，只返回通用 `mount_unavailable` 并限速、审计，不暴露冲突对象；系统不承诺抵御对已知候选资源的主动占用探测。
- `FR-014`：应用内权限不得高于 NAS 实际提供的文件权限。宿主机以只读方式提供的目录不能在应用内提升为读写。
- `FR-015`：系统必须识别并拒绝相同路径、双向父子路径、符号链接别名、bind alias 和 bind 源父子关系。无法可靠验证挂载身份时必须拒绝激活，并返回稳定错误 `mount_identity_unverifiable`；首版不提供管理员绕过。
- `FR-016`：挂载离线、身份漂移、身份无法验证、发生冲突、权限不足或变为只读时，系统必须停用不再安全的能力；过期索引不得继续参与搜索或文件访问。受限挂载的状态和错误不得向无权普通管理员泄露其存在。
- `FR-017`：注册外部目录必须直接使用所选目录，不得创建 `<space-id>` 或其他隐式业务子目录。
- `FR-018`：个人目录所有者必须能够把个人根或任意子目录按接收账号授予 `viewer/editor`；根目录授权必须强提示当前和未来内容都将可见。同一所有者与接收账号之间不得存在父子路径重叠的有效协作，创建或修改重叠授权时由服务端拒绝。
- `FR-019`：账号删除是不可逆身份删除。系统必须保留账号 tombstone 和 `personal_directories` 绑定及全部物理文件，同时撤销会话、`mount_grants`、发出与收到的协作、Token、分享、上传会话、Transfer Ticket 和内容访问；新账号不得自动继承旧目录。
- `FR-019A`：默认挂载离线、身份漂移、个人目录丢失或初始化部分失败时，必须停止相关内容访问、搜索、分享、Token 和写入，不能静默创建空目录。只有初始管理员可以重新验证身份和账号映射、明确恢复原目录或创建替代目录、处理孤立准备状态并完成审计；删除账号的保留目录不得绑定给新账号。

### 5.3 文件管理

- `FR-020`：成员必须能够浏览自己的个人目录、获权共用挂载和收到的目录协作。
- `FR-021`：具备写权限的成员必须能够上传文件和目录、新建目录，以及复制、移动、改名和批量处理对象。
- `FR-022`：大文件上传必须支持中断后继续，上传和下载不得要求将完整文件载入内存。
- `FR-023`：下载必须支持断点继续和浏览器原生音视频拖动播放所需的分段读取。
- `FR-024`：删除者使用自己的个人回收站；个人文件、共用挂载和收到协作中的单个文件不超过 200 MB（`200 × 1024 × 1024` 字节）时可以进入删除者回收站并计入其个人目录配额。
- `FR-025`：超过 200 MB 的文件不得进入回收站，必须转为明确的永久删除并再次确认；只读挂载拒绝删除。
- `FR-025A`：回收站恢复优先回到原位置并重验 `editor`；原位置或权限不可用时恢复到删除者“我的文件/从回收站恢复”，不得覆盖现有对象。目录或批量选择包含超过 200 MB 文件时，整批不能进入回收站。
- `FR-026`：跨挂载复制要求源端 `viewer` 或 `editor`、目标端 `editor` 且可写；跨挂载移动要求源端和目标端均为 `editor` 且可写，并使用复制、校验、删除源的可恢复流程。
- `FR-028`：收到的协作执行“保存到我的文件”必须复制对象，不得从所有者目录移除；协作 `editor` 只能修改根内内容，不能改名、移动或删除协作根，也不能创建公开分享或再授权第三人。
- `FR-027`：磁盘空间不足时必须拒绝新增内容，但仍允许浏览、下载，以及由符合实时内容权限与回收站策略的主体执行清理；管理员角色本身不授予他人内容的清理权。

### 5.4 索引与搜索

- `FR-030`：默认个人挂载使用按账号根裁剪的元数据索引；共用挂载的索引必须按挂载独立启用、暂停、恢复和关闭，不得自动为所有共用挂载开启全量扫描。
- `FR-031`：索引只处理文件名、相对路径、文件类型、大小和修改时间等元数据，不读取文件正文，不默认计算内容哈希。
- `FR-032`：已启用索引的挂载必须支持按文件名、扩展名、类型、大小、修改时间和所在目录搜索。
- `FR-033`：索引关闭或暂停的共用挂载仍必须支持当前目录浏览，但不得参与跨目录或全局搜索。
- `FR-034`：搜索界面和 API 只在当前账号已经获权且可发现的挂载集合内，明确列出因索引关闭、暂停、离线或尚未完成首次扫描而被排除的挂载；未授权挂载和不可发现的受限挂载不得出现在排除列表。
- `FR-035`：索引结果允许最终一致，但用户打开、下载、分享或通过 AI 读取文件时，系统必须回到文件系统重新确认对象仍存在且当前身份仍有权限。
- `FR-036`：发现过期搜索结果时，系统必须提示文件已变化或不存在，并安排清理对应元数据，不得返回另一个同路径替换文件的内容。
- `FR-037`：扫描与对账必须低优先级、可暂停、可恢复、不可重叠；长任务必须分批让出资源，避免阻塞其他后台维护任务。
- `FR-038`：成员 Web 全局搜索必须包含当前有效的收到协作，标记来源账号和协作类型，按对象去重并在打开时实时复核；MCP 搜索不得因此扩大到收到的协作。

### 5.5 文件预览

| 文件类型 | 首版行为 |
| --- | --- |
| 图片 | 浏览器直接显示；目录缩略图默认关闭，未启用前不生成、不请求；启用后仅对可见项目懒加载 |
| PDF | 在浏览器端预览 |
| 纯文本 | 限制读取大小后在浏览器显示 |
| Markdown | 清洗危险内容后在浏览器渲染 |
| 音频、视频 | 仅播放浏览器原生支持的编码 |
| Word、Excel、PowerPoint | 显示文件信息并提供下载，不提供预览 |
| 其他格式 | 显示文件信息并提供下载 |

- `FR-040`：预览失败不得影响有下载权限的用户下载原文件。
- `FR-041`：文本和 Markdown 预览必须限制最大读取量；Markdown 不得执行脚本、原始 HTML 或不安全链接。
- `FR-042`：首版不得为预览执行 Office 转换、视频转码、OCR 或内容分析。

### 5.6 文件分享

- `FR-050`：个人文件公开分享只能由所有者创建；共用挂载默认允许 `editor` 创建且可由有治理权的管理员按挂载关闭；关闭后既有分享及派生会话立即失效。收到的协作禁止公开分享。账号间个人目录协作不使用匿名分享秘密。
- `FR-051`：分享必须支持可选密码、有效期、预览开关、下载开关、访问次数上限、下载次数上限和主动撤销。
- `FR-052`：分享文件夹时，访客可以浏览授权子树并逐个下载允许的文件；首版不生成服务端压缩包。
- `FR-053`：关闭下载只隐藏直接下载能力，不得宣称能够阻止访客保存已经预览的内容。
- `FR-054`：分享创建者可以查看自己分享的访问记录并撤销分享；管理员只能查看和撤销其治理范围内的分享。个人目录分享的安全元数据可由管理员查看和撤销，但不得暴露路径、正文或秘密；受限挂载的分享元数据及策略仅初始管理员可见和治理。
- `FR-055`：对象在同一挂载内通过 Omnora 改名或移动时，原分享保持有效并跟随对象。
- `FR-056`：对象被 Omnora 移动到其他挂载时，原分享必须失效；目标位置如需分享，必须由在目标资源具有公开分享创建资格的账号重新创建。
- `FR-057`：对象在 Omnora 外部被移动、替换或删除后，原分享必须失效。即使原路径出现新文件，也不得让旧分享自动指向新内容。
- `FR-058`：分享创建者失去目标资源的公开分享创建资格、账号被停用或删除时，相关分享必须立即失效；恢复账号或权限不得自动恢复旧分享。
- `FR-059`：分享链接秘密必须放在 URL fragment 中，并由前端通过 `POST` 交换短期分享会话；交换完成后清理地址栏 fragment，服务端不得要求或接受 URL 路径、查询参数或 Referer 中的分享秘密。

### 5.7 REST、OpenAPI 与 MCP

- `FR-060`：系统必须提供版本化 REST API、可供客户端生成代码和调试的 OpenAPI 文档，以及通过 HTTP 访问的 MCP 服务。
- `FR-061`：Web、会话 REST 和 MCP 对共同支持的账号、个人目录、共用挂载和文件操作必须使用同一实时授权结果。收到的协作仅由 Web 和会话 REST 支持；MCP 对 `collaborationId`、协作浏览、搜索和写入必须一致拒绝。
- `FR-062`：目标 MCP 删除 `spaces.list`，将 `spaces:read` 改为 `mounts:read` 并移除 `spaceId`。工具、scope 和高风险工具数量以迁移完成后的运行时 catalog 为准，并通过 MCP Inspector 与协议测试验收；迁移前“25 个工具、15 个 scope、8 个高风险工具”只描述当前实现，不是目标契约。

为保证迁移前代码与文档契约可验证，当前 legacy scope 完整枚举保留为：

`spaces:read`、`files:list`、`files:metadata`、`files:text`、`files:download_ticket`、`search:read`、`uploads:create`、`files:write`、`files:trash`、`trash:read`、`files:restore`、`files:purge`、`shares:read`、`shares:create`、`shares:revoke`。

- `FR-063`：AI Token 默认只读；写入、回收站和分享必须单独授权，并且只对账号实时有权的个人目录或共用挂载生效。Token 可选择动态覆盖当前账号全部个人/挂载内容源，但不包含收到的协作。
- `FR-064`：迁移后 catalog 中标记为高风险的永久删除、移动、回收站清理、公开分享变更和文件内容覆盖等工具必须同时具备显式 scope，并在每次操作时通过 MRTR；具体清单和数量以迁移后的 catalog 为准。MCP 不提供管理员控制面工具。
- `FR-065`：MCP 不得直接内联返回大型二进制文件；大文件必须通过短期 Transfer Ticket 的 Range 下载或 multipart 上传路径访问。
- `FR-066`：MCP 使用 Streamable HTTP `2026-07-28`，兼容性测试覆盖 `2025-11-25`；OAuth 授权配置文件为 `NOT IMPLEMENTED`，只接受 AI Token Bearer。
- `FR-067`：所有接口必须限制单次结果数、文本读取量、并发请求和流量，超限时返回可识别的错误。
- `FR-068`：目标 REST 必须使用不可混用的账号作用域个人文件、`mountId` 作用域共用挂载和 `collaborationId` 作用域协作资源；客户端不得用可选 `mountId`、默认挂载 ID 或账号 ID 猜测资源类型。AI Token 可接受的 REST 路由必须白名单化，不能进入账号或管理接口。
- `FR-069`：解除共用挂载要求精确确认当前显示名称，只移除控制面注册并撤销全部派生能力；NAS 真实目录和文件不删除，挂载 tombstone 永久保留，审计记录 `dataDeleted: false`。受限挂载仅初始管理员可解除，同一路径重新注册必须使用新 ID 且不得继承旧状态。

### 5.8 配额、审计与治理

- `FR-070`：系统必须按账号统计默认挂载中个人目录的托管内容与个人回收站容量；首版不存在托管共用挂载。
- `FR-071`：系统管理存储的配额必须包含回收站未清理内容；达到配额后拒绝上传和增加占用的复制操作。
- `FR-072`：外部挂载不维护 Omnora 写入归属账本，也不提供应用级成员配额；容量治理依赖 NAS 配额，所有可写挂载仍受磁盘安全水位保护。
- `FR-073`：系统必须记录登录、权限变更、挂载变更、文件写删、分享访问、Token 使用和敏感 API/MCP 操作。
- `FR-074`：审计记录不得包含密码、明文 Token、分享密钥或文件正文。
- `FR-075`：成员只能查看与自己创建的协作、分享和 Token 相关的记录；管理员可以查看其治理范围内的安全审计，但个人目录和受限挂载仍受发现与内容隐私边界约束。

## 6. 非功能需求

### 6.1 性能与资源

- `NFR-001`：在极空间 8 GB RAM 设备上，空闲内存目标为 100 至 300 MB，普通浏览、搜索和文件传输时目标不超过 500 MB。
- `NFR-002`：上传、下载、目录遍历和索引的内存占用不得随文件大小或文件总数线性增长。
- `NFR-003`：后台扫描只允许一个低优先级批次同时运行，并可限制在最多半个 CPU 核的处理能力内。
- `NFR-004`：系统不得依赖 GPU，不得要求常驻的 Office 转换、视频转码、全文搜索或语义分析服务。
- `NFR-005`：百万级元数据下，分页浏览、文件名搜索和后台扫描必须能够同时工作，后台任务不得长时间阻塞交互请求。

### 6.2 部署与兼容性

- `NFR-010`：默认安装必须通过标准容器编排完成，并提供极空间与通用 Linux NAS 的部署说明。
- `NFR-011`：必须发布 `linux/amd64` 与 `linux/arm64` 版本。
- `NFR-012`：默认安装不得要求用户额外部署数据库、搜索引擎、转码服务或后台 Worker。
- `NFR-013`：系统不得要求特权容器、Host 网络或访问容器管理接口。
- `NFR-014`：NAS 上已有的 SMB 或 NFS 目录由宿主机负责挂载，Omnora 只使用宿主机提供的目录和权限。

### 6.3 网络与安全

- `NFR-020`：首次部署不得自动配置 UPnP 或开放公网端口。部署者必须通过 Docker 端口发布、宿主防火墙、安全组或反向代理显式决定访问范围。
- `NFR-021`：系统只提供单一 HTTP 监听地址；不得在应用内维护额外的局域网或代理入口开关。
- `NFR-022`：系统不得根据来源 IP、私网地址、Host 或客户端提交的转发头自动判断请求是否来自公网；公网 HTTPS 由部署者在反向代理层配置。
- `NFR-023`：密码、分享密码和 Token 验证必须具备分层限速，防止暴力尝试。
- `NFR-024`：所有文件访问必须防止路径穿越、符号链接逃逸、挂载边界越权和伪造文件类型。
- `NFR-025`：公开分享页面不得依赖第三方脚本，并应避免通过来源信息、缓存或日志泄露分享凭证。
- `NFR-026`：文件内容始终视为不可信数据。文件中的提示词不得扩大 AI Token 权限或自动触发写入、删除和分享操作。
- `NFR-027`：管理端、成员 Web、分享、REST、MCP 和 OpenAPI 的路由组必须独立控制；启用一个路由组不得隐式开启其他路由组。

### 6.4 可靠性与可恢复性

- `NFR-030`：文件系统是文件内容的真实来源；索引偏差必须通过可恢复的对账任务收敛。
- `NFR-031`：上传中断不得生成对用户可见的半成品文件；恢复或取消后必须可清理临时数据。
- `NFR-032`：挂载离线、权限变化、磁盘不足和索引失败必须有明确状态，不得导致过期索引被误判为有效文件。
- `NFR-033`：后台任务必须保存进度、失败原因和有限重试状态，服务重启后能够继续未完成任务。
- `NFR-034`：系统必须提供配置、业务数据和系统管理文件的备份恢复说明；外部挂载只备份配置与业务元数据，不重复备份原文件。
- `NFR-035`：升级失败不得继续带错误数据运行，且不得静默跨越不受支持的重大版本。
- `NFR-036`：从旧备份恢复后，旧会话、Token、分享、下载票据和上传会话必须全部失效；成员必须在首次登录前重设密码。普通挂载可由任一管理员重新验证，受限挂载和默认个人挂载只允许初始管理员处理。

### 6.5 可用性与可解释性

- `NFR-040`：用户必须能够区分“我的文件”、共用挂载、协作、索引状态和挂载读写模式。
- `NFR-041`：搜索结果不完整、文件已变化、分享失效、挂载离线和权限不足时，界面与 API 必须给出可理解且可操作的原因。
- `NFR-042`：预览、索引或缩略图失败只能影响对应能力，不得阻止有权限用户执行其他文件操作。

## 7. 首版非目标

以下能力不进入第一版：

- Word、Excel、PowerPoint 在线预览或编辑。
- 服务端视频转码、多码率播放和文件夹压缩打包下载。
- OCR、文件正文索引、向量检索、RAG 和内置 AI 问答。
- 匿名上传、公开收件箱和公开可写目录。
- WebDAV、S3、SMB 等存储协议网关。
- 跨 NAS 同步、跨节点集群、对象存储迁移和多副本高可用。
- 多租户、组织层级、复杂审批流和独立服务账号。
- 解除共用挂载时一并永久删除服务器真实目录或文件的流程。
- 原生移动端、桌面同步客户端和插件市场。
- 文件去重、版本历史和应用层自建端到端加密。
- Office 转换、视频转码、全文搜索等重型可选服务的编排。

## 8. 首版成功标准

首版只有同时满足以下条件才视为完成：

1. 用户可以在极空间 8 GB RAM 设备和普通 Linux NAS 上完成安装、初始化、升级与恢复演练。
2. 系统只有一个受保护默认挂载；新增账号自动获得个人目录，后续共用挂载逐个配置读写、索引、治理类型和账号授权，且允许零授权。
3. 管理员在未获内容授权时无法查看个人目录或共用挂载内容；普通管理员也不能通过常规产品入口直接发现或治理受限挂载，已知候选资源的主动占用探测按 `FR-013` 验收。
4. `viewer`、`editor`、个人目录所有者、匿名分享和 AI Token 在各自支持入口得到一致验证；目录协作通过 Web 与会话 REST 验证，并确认 MCP/AI Token 始终拒绝协作源。
5. 用户可以完成上传续传、分段下载、文件整理、跨挂载移动、协作文件保存、个人回收站恢复和超过 200 MB 文件的永久删除确认。
6. 文件与文件夹分享支持密码可选、有效期、访问限制和撤销；同一挂载内部移动后分享保持，跨挂载或外部移动、替换、删除后分享失效。
7. 图片、PDF、文本、Markdown 和浏览器原生音视频可以按首版规则预览；Office 文件始终进入下载流程。
8. 已索引挂载支持元数据搜索；未索引挂载仍可浏览，并在全局搜索中明确显示被排除原因。
9. 在百万级合成元数据下，分页浏览、文件名搜索、后台索引和文件传输不会相互长时间阻塞。
10. 极空间实机测量达到空闲内存 100 至 300 MB、普通操作不超过 500 MB 的目标，且不使用 GPU 或重型内容处理服务。
11. 挂载离线、磁盘不足、任务中断、外部文件移动或删除等故障不会造成越权访问或数据误删，并能给出明确恢复路径。
12. REST 与 OpenAPI 契约可供客户端接入；MCP 仅以 MCP Inspector Modern 和协议测试验收，不绑定具体客户端，且 Token scope、限额、过期、撤销和审计均可验证。
