# Omnora / 万境首版产品需求

日期：2026-08-02
状态：已确认，待实施规划
适用对象：产品、设计、研发、测试与运维团队

## 1. 产品定位

Omnora（万境）是面向个人、家庭和小团队的轻量自托管数字空间。首版以 NAS 文件为核心，让用户能够在自己的设备上管理、查找、预览和分享文件，并通过受控接口允许 AI 客户端访问明确授权的内容。

首版优先服务低功耗 NAS，极空间是第一验证平台，同时兼容其他支持容器部署的 NAS 与普通 Linux 主机。产品支持局域网使用、成员账号访问和受控公网分享，但不以企业多租户、跨设备同步或内容智能分析为目标。

### 1.1 首版价值

- 将系统托管文件与 NAS 已有目录统一组织到空间中。
- 在不暴露宿主机真实路径的前提下，为成员、访客和 AI 提供一致的授权访问。
- 提供带密码或无密码的文件、文件夹分享。
- 使用浏览器完成常见格式预览，不依赖 NAS 进行重型格式转换。
- 在约 100 万文件规模下提供可控、可暂停的元数据搜索能力。
- 保持安装简单和资源占用可预测，不影响 NAS 的主要存储职责。

### 1.2 首版规模边界

- 单台 NAS。
- 个人、家庭或小团队使用。
- 1 至 20 TB 文件数据。
- 约 100 万个文件和目录条目。
- 低并发成员访问，不承诺企业级高并发或跨节点扩展。

## 2. 核心概念

### 2.1 空间

空间是成员授权、文件分享和 AI 授权的边界。首版支持两类空间：

- 个人空间：系统为每位成员创建，成员本人默认拥有 `manager` 权限。
- 共享空间：由管理员创建，通过空间权限分配给一个或多个成员。

一个空间可以包含一个或多个挂载。空间权限作用于该空间内的全部挂载，但任何写入仍受具体挂载的只读或读写模式限制。挂载属于系统控制面资源；空间 `manager` 可以管理空间 ACL、分享和文件内容，但不能新增、修改、停用、删除或重新验证挂载。

### 2.2 挂载

挂载是空间中的一个文件来源，可以是由 Omnora 管理的存储目录，也可以是 NAS 上已有的目录。每个挂载必须：

- 归属一个且仅一个空间；
- 具有空间内唯一且稳定的显示名称；
- 明确设置为只读或读写；
- 由管理员单独决定是否建立元数据索引；
- 在离线、权限不足或只读状态变化时显示独立状态。

首版不允许不同挂载指向相同或重叠的物理目录。相同路径、双向父子路径、符号链接或 magic link、指向同一目录的 bind alias，以及 bind 源之间的父子关系均视为冲突。系统无法证明候选挂载与已有挂载相互独立时，必须拒绝激活，避免同一文件通过不同空间获得相互冲突的权限。

### 2.3 文件对象

用户、分享链接和 AI 使用稳定的内部文件对象标识访问文件。产品不得向外暴露 NAS 的真实绝对路径。

文件系统中的实际文件是内容的真实来源。元数据索引用于搜索和加速发现，不能代替文件在访问时的权限和存在性检查。

## 3. 用户与权限

### 3.1 用户类型

- 管理员：初始化系统，管理成员、共享空间、挂载、系统策略、配额、索引任务、分享治理、凭证治理和全局审计。
- 成员：管理个人空间，并按空间权限访问共享空间。
- 匿名访客：通过有效分享链接访问分享范围内的文件，不拥有系统账号。
- AI 客户端：不是独立用户。它使用绑定到成员账号的专用 Token，代表该成员执行有限操作。

### 3.2 空间权限

| 能力 | `viewer` | `editor` | `manager` |
| --- | --- | --- | --- |
| 浏览、搜索、预览、下载 | 是 | 是 | 是 |
| 上传、新建目录、复制 | 否 | 是 | 是 |
| 移动、改名、删除 | 否 | 是 | 是 |
| 创建和管理自己的分享 | 否 | 否 | 是 |
| 管理空间成员权限 | 否 | 否 | 是 |
| 新增或配置挂载 | 否 | 否 | 否 |

只读挂载拒绝所有写入操作，即使操作者在空间中是 `editor`、`manager` 或系统管理员。

挂载配置不属于空间 ACL。只有系统管理员可以新增、改名、迁移、停用、删除或重新验证挂载，以及修改根路径、读写模式和索引模式。管理员配置个人空间的挂载不等于获得该空间的文件名、目录或内容权限。

### 3.3 管理员隐私边界

- 管理员可以查看个人空间的容量、挂载健康状态、索引状态和安全事件，但默认不能查看文件名、目录结构或文件内容。
- 管理员只有在个人空间所有者显式授予空间权限后，才能按该权限访问内容。
- 首版允许受审计的应急访问。管理员必须重新认证并填写原因；应急权限只授予目标个人空间最长一小时的临时只读访问，到期后自动撤销，并向个人空间所有者显示访问记录。
- 管理员可以撤销违规或泄露的分享与 Token，但不能查看其明文密钥。

### 3.4 Token 权限

AI Token 的有效权限始终取以下条件的交集：

1. 所属成员账号当前状态；
2. 所属成员当前拥有的空间权限；
3. Token 明确配置的操作范围；
4. Token 明确配置的挂载与目录边界；
5. 目标挂载当前的只读或读写能力。

成员权限被收回或挂载变为只读后，相关 Token 必须立即降权，不得保留原授权。成员只能创建和管理自己的 Token；管理员可以查看 Token 元数据并撤销 Token，但不能恢复或查看明文 Token。

## 4. 核心使用场景

### 4.1 初始化与接入 NAS 目录

管理员在局域网完成首次初始化，创建成员和空间，将 NAS 已有目录接入指定空间，并为每个挂载确认读写模式与索引开关。接入完成后，成员只能看到自己获得授权的空间。

### 4.2 成员管理和查找文件

成员进入个人空间或共享空间，在多个挂载之间浏览、上传、下载、复制和整理文件。已启用索引的挂载可参与跨目录搜索；未启用索引的挂载仍可正常逐目录浏览。

### 4.3 对外分享

拥有 `manager` 权限的成员为文件或文件夹创建分享链接，按需要设置密码、有效期、预览和下载权限以及访问次数限制。访客无需注册即可在分享范围内访问内容。

### 4.4 AI 受控访问

成员创建限定空间、目录、操作和有效期的 AI Token。AI 客户端通过 REST 或 MCP 浏览目录、搜索文件、读取受限文本或发起上传，所有操作使用与 Web 相同的权限结果并进入审计。

### 4.5 低负载索引

管理员只为确实需要搜索的挂载开启索引。首次扫描和后续对账在后台低优先级运行，可暂停和恢复，不应阻塞目录浏览、上传或下载。

## 5. 功能需求

### 5.1 初始化、账号与会话

- `FR-001`：系统必须通过一次性初始化凭证创建首个管理员；初始化完成后不得再次开放无鉴权初始化入口。
- `FR-002`：管理员必须能够创建、停用和恢复成员账号。
- `FR-003`：管理员必须启用双因素认证；成员可以自行启用。
- `FR-004`：用户必须能够撤销自己的活跃会话；管理员可以撤销指定账号的全部会话。
- `FR-005`：唯一管理员丢失密码或双因素认证时，系统必须提供需要 NAS 本地控制权的恢复流程，不得提供远程无鉴权重置。

### 5.2 空间与挂载

- `FR-010`：每位成员必须拥有一个个人空间，并自动获得该空间的 `manager` 权限。
- `FR-011`：管理员必须能够创建和停用共享空间，并管理其成员权限。停用后，成员、分享和 Token 均不能继续访问该空间，但原文件不得被自动删除。
- `FR-012`：一个空间必须能够包含多个挂载；每个挂载只归属一个空间。
- `FR-013`：只有系统管理员可以添加或修改挂载。添加时必须明确选择只读或读写模式以及是否启用索引；未完成选择和身份验证前不得激活挂载或开始扫描。
- `FR-014`：应用内权限不得高于 NAS 实际提供的文件权限。宿主机以只读方式提供的目录不能在应用内提升为读写。
- `FR-015`：系统必须识别并拒绝相同路径、双向父子路径、符号链接别名、bind alias 和 bind 源父子关系。无法可靠验证挂载身份时必须拒绝激活，并返回稳定错误 `mount_identity_unverifiable`；首版不提供管理员绕过。
- `FR-016`：挂载离线、身份漂移、身份无法验证、与其他挂载发生冲突、权限不足或变为只读时，系统必须显示原因并自动停用不再安全的能力；过期索引不得继续参与搜索或文件访问。

### 5.3 文件管理

- `FR-020`：成员必须能够浏览有权限空间中的挂载、目录和文件。
- `FR-021`：具备写权限的成员必须能够上传文件和目录、新建目录，以及复制、移动、改名和批量处理对象。
- `FR-022`：大文件上传必须支持中断后继续，上传和下载不得要求将完整文件载入内存。
- `FR-023`：下载必须支持断点继续和浏览器原生音视频拖动播放所需的分段读取。
- `FR-024`：系统管理的存储必须提供回收站和恢复；回收站对象计入空间配额。
- `FR-025`：读写外部挂载上的删除为永久删除，操作前必须明确提示，首版不为外部挂载提供 Omnora 回收站。
- `FR-026`：跨挂载复制要求源端至少有读取权限、目标端至少有写入权限。跨挂载移动还要求源端具有删除权限且可写。
- `FR-027`：磁盘空间不足时必须拒绝新增内容，但仍允许浏览、下载和管理员清理。

### 5.4 索引与搜索

- `FR-030`：索引必须按挂载独立启用、暂停、恢复和关闭，不得自动为所有挂载开启全量扫描。
- `FR-031`：索引只处理文件名、相对路径、文件类型、大小和修改时间等元数据，不读取文件正文，不默认计算内容哈希。
- `FR-032`：已启用索引的挂载必须支持按文件名、扩展名、类型、大小、修改时间和所在目录搜索。
- `FR-033`：索引关闭或暂停的挂载仍必须支持当前目录浏览，但不得参与跨目录或全局搜索。
- `FR-034`：搜索界面和 API 必须明确列出因索引关闭、暂停、离线或尚未完成首次扫描而被排除的挂载。
- `FR-035`：索引结果允许最终一致，但用户打开、下载、分享或通过 AI 读取文件时，系统必须回到文件系统重新确认对象仍存在且当前身份仍有权限。
- `FR-036`：发现过期搜索结果时，系统必须提示文件已变化或不存在，并安排清理对应元数据，不得返回另一个同路径替换文件的内容。
- `FR-037`：扫描与对账必须低优先级、可暂停、可恢复、不可重叠；长任务必须分批让出资源，避免阻塞其他后台维护任务。

### 5.5 文件预览

| 文件类型 | 首版行为 |
| --- | --- |
| 图片 | 浏览器直接显示；可选缩略图默认关闭 |
| PDF | 在浏览器端预览 |
| 纯文本 | 限制读取大小后在浏览器显示 |
| Markdown | 清洗危险内容后在浏览器渲染 |
| 音频、视频 | 仅播放浏览器原生支持的编码 |
| Word、Excel、PowerPoint | 显示文件信息并提供下载，不提供预览 |
| 其他格式 | 显示文件信息并提供下载 |

- `FR-040`：预览失败不得影响有下载权限的用户下载原文件。
- `FR-041`：文本和 Markdown 预览必须限制最大读取量；Markdown 不得执行脚本、原始 HTML 或不安全链接。
- `FR-042`：首版不得为预览执行 Office 转换、视频转码、OCR 或内容分析。

### 5.6 文件分享

- `FR-050`：文件和文件夹必须能够创建分享链接，创建者必须在目标空间拥有 `manager` 权限。
- `FR-051`：分享必须支持可选密码、有效期、预览开关、下载开关、访问次数上限、下载次数上限和主动撤销。
- `FR-052`：分享文件夹时，访客可以浏览授权子树并逐个下载允许的文件；首版不生成服务端压缩包。
- `FR-053`：关闭下载只隐藏直接下载能力，不得宣称能够阻止访客保存已经预览的内容。
- `FR-054`：分享创建者可以查看自己分享的访问记录并撤销分享；管理员可以查看分享元数据并撤销任意分享。
- `FR-055`：对象在同一挂载内通过 Omnora 改名或移动时，原分享保持有效并跟随对象。
- `FR-056`：对象被 Omnora 移动到其他挂载时，原分享必须失效；目标位置如需分享，必须由拥有目标空间 `manager` 权限的成员重新创建。
- `FR-057`：对象在 Omnora 外部被移动、替换或删除后，原分享必须失效。即使原路径出现新文件，也不得让旧分享自动指向新内容。
- `FR-058`：分享创建者失去目标空间的 `manager` 权限、账号被停用或删除时，相关分享必须立即失效；恢复账号或权限不得自动恢复旧分享。

### 5.7 REST、OpenAPI 与 MCP

- `FR-060`：系统必须提供版本化 REST API、可供客户端生成代码和调试的 OpenAPI 文档，以及通过 HTTP 访问的 MCP 服务。
- `FR-061`：Web、REST 和 MCP 对相同身份、空间和文件必须返回一致的权限结果。
- `FR-062`：首版 AI 能力必须覆盖空间列表、目录列表、元数据搜索、文件元数据读取、受限文本读取、短期下载地址和上传会话创建。
- `FR-063`：AI Token 默认只读；上传必须单独授权，并且只对成员本人具有写权限的目录生效。
- `FR-064`：首版不得向 AI Token 开放删除文件、管理权限或创建公开分享。
- `FR-065`：MCP 不得直接内联返回大型二进制文件；大文件必须通过受限、短期的下载方式访问。
- `FR-066`：所有接口必须限制单次结果数、文本读取量、并发请求和流量，超限时返回可识别的错误。

### 5.8 配额、审计与治理

- `FR-070`：系统必须支持为使用托管挂载的个人空间和共享空间设置容量配额。
- `FR-071`：系统管理存储的配额必须包含回收站未清理内容；达到配额后拒绝上传和增加占用的复制操作。
- `FR-072`：外部挂载不维护 Omnora 写入归属账本，也不提供应用级成员配额；容量治理依赖 NAS 配额，所有可写挂载仍受磁盘安全水位保护。
- `FR-073`：系统必须记录登录、权限变更、挂载变更、文件写删、分享访问、Token 使用、管理员应急访问和敏感 API/MCP 操作。
- `FR-074`：审计记录不得包含密码、明文 Token、分享密钥或文件正文。
- `FR-075`：成员只能查看与自己创建的分享和 Token 相关的记录；管理员可以查看全局治理与安全审计，但个人空间内容仍受隐私边界约束。

## 6. 非功能需求

### 6.1 性能与资源

- `NFR-001`：在极空间 8 GB RAM 设备上，空闲内存目标为 100 至 300 MB，普通浏览、搜索和文件传输时目标不超过 500 MB。
- `NFR-002`：上传、下载、目录遍历和索引的内存占用不得随文件大小或文件总数线性增长。
- `NFR-003`：后台扫描只允许一个低优先级批次同时运行，并可限制在最多半个 CPU 核的处理能力内。
- `NFR-004`：系统不得依赖 GPU，不得要求常驻的 Office 转换、视频转码、全文搜索或语义分析服务。
- `NFR-005`：百万级元数据下，分页浏览、文件名搜索和后台扫描必须能够同时工作，后台任务不得长时间阻塞交互请求。

### 6.2 部署与兼容性

- `NFR-010`：默认安装必须通过标准容器编排完成，并提供极空间与通用 Linux NAS 的部署说明。
- `NFR-011`：必须发布 `linux/amd64` 与 `linux/arm64` 版本。
- `NFR-012`：默认安装不得要求用户额外部署数据库、搜索引擎、转码服务或后台 Worker。
- `NFR-013`：系统不得要求特权容器、Host 网络或访问容器管理接口。
- `NFR-014`：NAS 上已有的 SMB 或 NFS 目录由宿主机负责挂载，Omnora 只使用宿主机提供的目录和权限。

### 6.3 网络与安全

- `NFR-020`：首次部署不得自动配置 UPnP 或开放公网端口。部署者必须显式启用至少一个有效入口；入口未启用或配置无效时，受保护端点必须失败关闭。
- `NFR-021`：`lan_http` 入口仅用于直接局域网访问。管理员必须显式启用并配置允许的 IPv4/IPv6 LAN CIDR；系统根据该入口的直接对端地址准入，忽略全部转发头，并持续提示连接未加密。
- `NFR-022`：`proxy_https` 入口仅用于可信反向代理。系统不得根据来源 IP、私网地址、Host 或客户端提交的转发头自动判断请求是否来自公网；只有直接对端属于可信代理 CIDR，且可信代理声明外部协议为 HTTPS 时，才允许认证和文件访问。
- `NFR-023`：密码、分享密码和 Token 验证必须具备分层限速，防止暴力尝试。
- `NFR-024`：所有文件访问必须防止路径穿越、符号链接逃逸、挂载边界越权和伪造文件类型。
- `NFR-025`：公开分享页面不得依赖第三方脚本，并应避免通过来源信息、缓存或日志泄露分享凭证。
- `NFR-026`：文件内容始终视为不可信数据。文件中的提示词不得扩大 AI Token 权限或自动触发写入、删除和分享操作。
- `NFR-027`：`lan_http` 与 `proxy_https` 可以同时启用，但必须使用独立入口和信任规则。网络入口合法与路由组已暴露是两个必须同时满足的条件。

### 6.4 可靠性与可恢复性

- `NFR-030`：文件系统是文件内容的真实来源；索引偏差必须通过可恢复的对账任务收敛。
- `NFR-031`：上传中断不得生成对用户可见的半成品文件；恢复或取消后必须可清理临时数据。
- `NFR-032`：挂载离线、权限变化、磁盘不足和索引失败必须有明确状态，不得导致过期索引被误判为有效文件。
- `NFR-033`：后台任务必须保存进度、失败原因和有限重试状态，服务重启后能够继续未完成任务。
- `NFR-034`：系统必须提供配置、业务数据和系统管理文件的备份恢复说明；外部挂载只备份配置与业务元数据，不重复备份原文件。
- `NFR-035`：升级失败不得继续带错误数据运行，且不得静默跨越不受支持的重大版本。
- `NFR-036`：从旧备份恢复后，旧会话、Token、分享、下载票据和上传会话必须全部失效；成员必须在首次登录前重设密码，外部挂载必须由管理员重新验证后才能启用。

### 6.5 可用性与可解释性

- `NFR-040`：用户必须能够区分空间、挂载、索引状态和挂载读写模式。
- `NFR-041`：搜索结果不完整、文件已变化、分享失效、挂载离线和权限不足时，界面与 API 必须给出可理解且可操作的原因。
- `NFR-042`：预览、索引或缩略图失败只能影响对应能力，不得阻止有权限用户执行其他文件操作。

## 7. 首版非目标

以下能力不进入第一版：

- Word、Excel、PowerPoint 在线预览或编辑。
- 服务端视频转码、多码率播放和文件夹压缩打包下载。
- OCR、文件正文索引、向量检索、RAG 和内置 AI 问答。
- 匿名上传、公开收件箱和公开可写目录。
- WebDAV、S3、SMB 等存储协议网关。
- 跨 NAS 同步、跨节点集群、对象存储迁移和多副本高可用。
- 多租户、组织层级、复杂审批流和独立服务账号。
- 共享空间及其文件的一键永久删除流程。
- 原生移动端、桌面同步客户端和插件市场。
- 文件去重、版本历史和应用层自建端到端加密。
- Office 转换、视频转码、全文搜索等重型可选服务的编排。

## 8. 首版成功标准

首版只有同时满足以下条件才视为完成：

1. 用户可以在极空间 8 GB RAM 设备和普通 Linux NAS 上完成安装、初始化、升级与恢复演练。
2. 管理员可以创建成员和空间，在一个空间中接入多个挂载，并逐个决定读写模式和是否索引；包括个人空间 `manager` 在内的成员不能自助配置挂载。
3. 管理员在未获授权时无法查看个人空间的文件名、目录和内容；应急访问限于最长一小时的临时只读权限，并具有重新认证、原因和审计记录。
4. `viewer`、`editor`、`manager`、匿名分享和 AI Token 的权限边界通过 Web、REST 与 MCP 得到一致验证。
5. 用户可以完成上传续传、分段下载、文件整理、托管存储回收站恢复和外部挂载永久删除确认。
6. 文件与文件夹分享支持密码可选、有效期、访问限制和撤销；同一挂载内部移动后分享保持，跨挂载或外部移动、替换、删除后分享失效。
7. 图片、PDF、文本、Markdown 和浏览器原生音视频可以按首版规则预览；Office 文件始终进入下载流程。
8. 已索引挂载支持元数据搜索；未索引挂载仍可浏览，并在全局搜索中明确显示被排除原因。
9. 在百万级合成元数据下，分页浏览、文件名搜索、后台索引和文件传输不会相互长时间阻塞。
10. 极空间实机测量达到空闲内存 100 至 300 MB、普通操作不超过 500 MB 的目标，且不使用 GPU 或重型内容处理服务。
11. 挂载离线、磁盘不足、任务中断、外部文件移动或删除等故障不会造成越权访问或数据误删，并能给出明确恢复路径。
12. REST、OpenAPI 与 MCP 能被常见 AI 客户端使用，Token 权限、限额、过期、撤销和审计均可验证。
