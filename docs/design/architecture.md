# Omnora 技术架构

状态：目标架构基线，账号—挂载模型待实施
日期：2026-08-08

> 本文描述账号—挂载模型的现行架构；详细产品边界见[账号、挂载与内容授权设计](../superpowers/specs/2026-08-08-account-mount-access-design.md)。

## 1. 架构目标

第一版优先满足低功耗 NAS 上的可部署性、可恢复性和权限一致性。目标规模为单机 1 至 20 TB、约 100 万个文件、家庭或小团队并发；不设计多节点横向扩展。

## 2. 部署单元

默认 Docker Compose 只运行一个 `omnora` 容器：

- Go 进程提供 Web、REST/OpenAPI、MCP、文件传输和后台任务。
- React、TypeScript、Vite 构建出的静态资源嵌入 Go 可执行文件。
- SQLite WAL 保存业务数据、元数据索引、审计和任务检查点。
- 文件内容始终保留在 NAS 文件系统，不写入 SQLite。

首版不引入 PostgreSQL、Redis、OpenSearch、MinIO、LibreOffice、OnlyOffice 或 FFmpeg，不使用 GPU。

## 3. 模块边界

- Identity：账号、密码、TOTP、会话和 Token。
- Access Policy：系统角色、个人目录所有权、挂载授权、协作授权、凭证 scope、目录边界和挂载模式的统一判定。
- Storage：受目录文件描述符约束的文件系统访问与挂载能力检测。
- Catalog：对象记录、轻量元数据、扫描、对账和搜索。
- Transfer：分片上传、原子落盘、Range、ETag 和短期下载地址。
- Share：分享生命周期、密码、次数、派生会话和撤销。
- Preview：浏览器可预览类型判定、受限内容输出和可选缩略图。
- MCP Adapter：把应用服务映射为受限 MCP 工具，不直接访问 Storage。
- MCP Transfer Gateway：使用短期 Transfer Ticket 提供受限 Range 下载和 multipart 上传；每个字节请求都回到 AccessGuard、AI Token 与挂载身份校验。
- Jobs：持久化任务、优先级、检查点、重试和公平调度。
- Audit：只追加安全与业务事件、脱敏、保留和导出。

数据模型以账号为身份主体。系统初始化时建立唯一受保护默认挂载，每个账号在其中拥有隔离个人根；其他挂载是按账号独立授权的共用挂载。普通挂载由全部管理员治理，受限挂载只有初始管理员能够通过治理控制面直接发现和治理；已知候选资源的主动占用探测按安全模型作为残余侧信道处理。治理权限不进入文件内容授权链。

Web、REST、MCP 和分享入口只能调用同一应用服务与 AccessGuard，不能分别实现权限规则。MCP
工具目录由 `internal/mcpapi/catalog.go` 生成。工具、scope 和高风险工具数量以当前 catalog 为准，并通过 MCP 协议测试和文档同步校验。

## 4. SQLite

SQLite 使用 WAL 模式，并遵守以下约束：

- 一个受控写入队列，避免无界写竞争。
- 读取使用短事务；禁止在文件 I/O 或网络 I/O 期间持有数据库事务。
- 设置有限 `busy_timeout`，超时返回可重试错误，不无限等待。
- 页缓存目标 32 至 64 MB。
- WAL 检查点有大小和时间上限，避免长期占用交互请求。
- 数据库迁移必须可检测版本；迁移失败时停止启动并保留原数据。控制面迁移不实现旧 Token、分享或 ID 兼容层，但不得删除外部挂载真实文件。

热备份使用 SQLite Online Backup API 或等价的一致性方案，不能把“执行 WAL checkpoint”当作完整备份。

## 5. 挂载注册与身份

应用只接受部署者预先映射到容器的目录，不接受宿主机绝对路径，也不在容器内执行 mount。唯一默认挂载是系统管理目录；其他共用挂载全部接入既有 NAS 目录，不创建托管共用挂载。注册时所选目录本身就是挂载根，不创建隐式业务子目录。挂载注册和配置变更通过全局串行锁与 SQLite 事务执行，并在激活前对所有未删除挂载重新检查，防止两个管理员并发注册冲突目录。

系统默认挂载在首次初始化时创建，物理数据源为持久化的 `/srv/omnora/managed`。它不能通过普通挂载接口删除、主动停用、改根、改为只读或授权；配置模式固定 `read_write`，实际不可写、离线或身份异常时进入系统判定的 `unavailable`。账号创建与个人目录可用必须形成一个完整业务结果；跨数据库和文件系统的部分失败使用显式准备、补偿和重试状态处理。

默认挂载使用按账号个人根裁剪的元数据索引，支持“我的文件”与 Web 全局搜索，同时禁止跨账号结果和通过索引推断兄弟目录。

个人目录物理名称使用稳定账号 ID。账号删除时保留目录和文件并保留不可复用 tombstone。默认挂载或个人目录异常时 fail-closed，只允许初始管理员通过显式修复流程验证身份和映射，不能静默创建空目录。

挂载治理类型创建后不可切换。激活后的 `root_path`、`purpose`、`storage_kind` 和 `governance` 不可修改；显示名称、应用读写模式、索引开关和授权可以由有治理权管理员修改。活跃显示名称规范化后全局唯一且忽略大小写；解除要求精确名称确认并永久保留挂载 tombstone，审计按安全保留策略保存，同一路径以后可用新的挂载 ID 重新注册，旧授权不恢复。

首版按以下顺序验证候选挂载：

1. 规范化容器绝对路径，按路径组件边界比较完全相同和双向父子关系；`/data/a` 与 `/data/a/b` 冲突，`/data/a` 与 `/data/ab` 不冲突。
2. 从预声明目录逐级以目录文件描述符、`O_NOFOLLOW` 和等价约束打开，候选根或父组件包含符号链接、magic link 时拒绝。
3. 使用 `statx` 或等价接口采集设备号、inode 和 mount ID；根目录对象身份相同即拒绝。
4. 解析 `/proc/self/mountinfo`，使用文件系统 `major:minor` 与 mount root 按路径组件比较 bind 来源；来源相同或构成父子关系时拒绝。
5. 无法获得足够身份信息或无法证明与已有挂载相互独立时，返回 `mount_identity_unverifiable` 并拒绝激活，不提供确认绕过。

系统保存验证后的 `mount_identity`。启动、备份恢复、重新启用和每次扫描前复核；实际文件访问使用受根目录文件描述符约束的解析器并复核根身份。身份变化、无法验证或产生新冲突时使挂载进入 `unavailable`，排除其搜索结果并拒绝分享和文件访问，保留索引仅用于诊断。普通挂载可由任一管理员重新验证，受限挂载和默认个人挂载只能由初始管理员处理。

## 6. 文件身份与访问

API 使用不可猜测的内部对象 ID，不接收宿主机绝对路径。共用挂载对象映射到 `mount_id + relative_path + identity_fingerprint`；“我的文件”绑定当前账号个人根且不接受客户端账号 ID；协作对象额外绑定 `collaboration_id` 和授权根，但只通过成员 Web 和会话 REST 暴露。MCP 文件工具显式区分 `personal` 与 `common_mount`，拒绝协作源。对象记录不再保存 `space_id`。

所有实际访问在最终打开时重新执行：

1. 账号、实时内容权限来源、凭证和挂载权限校验。
2. 规范化相对路径校验。
3. 以挂载根目录文件描述符为起点解析目标。
4. 拒绝越出根目录、magic link、异常挂载跨越和不允许的符号链接。
5. 比对对象身份，确认不是同路径替换对象。

Linux 优先使用 `openat2` 与 `RESOLVE_BENEATH`、`RESOLVE_NO_MAGICLINKS` 等约束；不可用时使用逐级目录文件描述符和 `O_NOFOLLOW` 的安全回退。不能采用“先检查字符串路径，再按路径打开”的实现。

## 7. 索引与对账

默认个人挂载使用按账号根裁剪的元数据索引；共用挂载索引由有治理权的管理员逐挂载启用。索引只保存名称、相对路径、类型、大小、修改时间和必要身份字段，不读取正文、不计算内容哈希。

- 初始扫描：单并发、分页遍历、200 至 1000 个对象一批、可暂停和续跑。
- 增量更新：文件事件可用时使用；Docker bind mount、SMB/NFS 事件不可靠时自动降级。
- 全量对账：上次完整对账结束后至少间隔 24 小时；任务不得重叠，仅在资源策略允许时运行。
- 一致性：搜索最终一致，文件访问实时回源。
- 成员 Web 搜索在索引结果上追加当前有效协作边界过滤、来源标记和对象去重；MCP 搜索不包含收到的协作。

百万文件对账可能持续超过一天，因此调度器不能按固定时刻重复创建全量任务。

## 8. 后台任务调度

后台任务整体并发为 1，但采用优先级和协作式让出：

1. 恢复、数据一致性修复和安全清理。
2. 上传收尾、跨挂载操作和回收站恢复。
3. 回收站清理与临时分片清理。
4. 增量索引与全量对账。
5. 可选缩略图。

扫描任务每批完成后保存检查点并让出执行权，避免长任务阻塞高优先级工作。所有任务必须幂等，重启后从持久化状态恢复；永久失败进入可见失败状态，不无限重试。

## 9. 文件传输

- 上传按固定分片流式写入同挂载临时目录，完成后原子 rename。
- 创建上传会话时预占配额；失败、过期或取消后释放。
- 临时分片具有过期时间，并由高优先级清理任务处理。
- 下载支持 HTTP Range、ETag 和条件请求，内存占用不随文件大小线性增长。
- 文件名、响应头和 `Content-Disposition` 必须安全编码，拒绝 CR/LF。

删除者个人回收站使用默认挂载中的受保护区域。单个文件不超过 200 MB 且批次不含超限文件时，外部共用挂载或协作内容通过“预留删除者个人配额、复制到受保护回收站、校验、持久化 journal、删除源”的持久化任务处理；任何阶段失败都不能丢失唯一副本，并进入可重试或人工清理终态。超过阈值只允许明确永久删除。恢复优先原位并重验权限，失败时写入删除者“我的文件/从回收站恢复”且不覆盖；进入回收站立即撤销公开分享、下载票据和活动写入，恢复不自动恢复旧分享。跨挂载移动复用“复制、校验、删除源”，而从收到的协作“保存到我的文件”只复制，不删除源。

跨挂载复制使用固定缓冲区流式传输；移动遵守领域模型定义的“复制、校验、删除源”。

## 10. 预览

- 图片由浏览器直接显示；可选缩略图默认关闭、并发为 1。
- PDF 由浏览器端 PDF.js 渲染。
- 文本和 Markdown 限制最大读取字节数；Markdown 严格清洗。
- 音视频仅播放浏览器原生编码。
- Office 和未知格式只提供下载。

不可信主动内容不能与认证应用同源直接执行。详细响应头、隔离源和 sandbox 规则由安全模型定义。

## 11. HTTP 入口与路由组

Omnora 只启动一个 HTTP 监听地址。是否允许局域网或公网访问由 Docker 端口发布、宿主防火墙、安全组和反向代理配置决定；应用不再提供独立的 LAN 或代理入口开关，也不根据来源 IP、私网地址、Host 或客户端提交的转发头自动判断信任。

公网 Web、公开分享、远程 REST 和远程 MCP 应经 Lucky、极空间反向代理、Caddy、Nginx 或等价入口提供 HTTPS。推荐拓扑为：

`公网 HTTPS:443 -> 反向代理 -> HTTP 127.0.0.1:8080 -> Omnora`

反向代理后端端口应只对代理可达。公网 `80` 只执行同域名 `301`/`308` HTTPS 跳转，不能直接反向代理 Omnora；未匹配 Host 应拒绝。代理需要保留 Host，并支持流式响应、Range、WebSocket 和 MCP 长连接，不得缓冲完整文件。

管理端、成员 Web、分享、REST、MCP 和 OpenAPI 具有六个独立暴露开关。路由组开关只控制应用内路由是否可达；启用分享不能连带启用其他路由组。默认 Compose 不自动配置 UPnP，不使用 Host 网络或 Docker Socket。

## 12. 资源目标

- 发布 `linux/amd64` 与 `linux/arm64` 镜像。
- 极空间 8 GB RAM 为首要验证环境。
- 空闲内存目标 100 至 300 MB。
- 普通浏览、搜索和传输不超过 500 MB。
- 扫描最多使用半个 CPU 核并受 I/O 限速。
- 内存统计区分应用不可释放内存与 Linux 可回收页缓存。

支持 `PUID`、`PGID`、`TZ` 和 `UMASK`。SQLite 与配置建议放在 SSD 或系统盘，文件内容可以放在机械盘。

## 13. 备份与恢复

备份包括一致性 SQLite 快照、应用配置、密钥和默认个人挂载文件。首版不存在托管共用挂载；外部挂载只备份配置与对象元数据，不复制其文件内容。

恢复旧备份后必须：

- 提升全局凭证代际，使旧浏览器会话、Token、公开分享、分享派生会话、下载票据和上传会话失效；
- 要求管理员与成员通过本地恢复流程重设密码，并清除旧 TOTP 状态；TOTP 保持可选，不强制重新登记；
- 要求管理员重新验证外部挂载的宿主路径、文件系统身份和读写模式后再启用；
- 校验 SQLite 完整性和托管文件可达性；
- 记录恢复审计事件。

## 14. 标准 MCP 与秘密隔离

`/mcp` 是官方 SDK `Streamable HTTP` transport，协商首选协议 `2026-07-28`，并保留经过
协议测试的 `2025-11-25` 兼容路径。它只负责 JSON-RPC transport，不复制 OpenAPI 中的
工具 schema，也不保留早期 `{method,params}` 私有 envelope。AI Token、MRTR challenge 和
Transfer Ticket 是三种互相隔离的秘密类型：前者用于 MCP 认证，后者用于一次性人机确认，
最后一种只用于 `/mcp/transfers/*` 字节流。

AI Token 可以动态覆盖当前账号自己的个人目录和全部获权共用挂载，新授权自动进入、撤销立即失效；收到的协作不进入 MCP boundary 或 MCP 搜索。

大文件通过 `GET /mcp/transfers/{publicId}` 和
`PUT /mcp/transfers/{publicId}/parts/{partNumber}` 处理；请求使用票据 Bearer、Range/ETag
和原子字节预算。每次请求重做 Token、账号实时内容权限、边界、挂载身份和对象指纹检查，票据不能绕过
AccessGuard。终态审计写入失败会标记 readiness 风险并让 `/readyz` 返回 `503`，从而避免
“文件已变更但无审计记录”的静默成功。
