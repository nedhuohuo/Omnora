# Omnora 技术架构

状态：第一版设计基线
日期：2026-08-02

## 1. 架构目标

第一版优先满足低功耗 NAS 上的可部署性、可恢复性和权限一致性。目标规模为单机 1 至 20 TB、约 100 万个文件、家庭或小团队并发；不设计多节点横向扩展。

## 2. 部署单元

默认 Docker Compose 只运行一个 `omnora` 容器：

- Go 进程提供 Web、REST/OpenAPI、MCP、文件传输和后台任务。
- React、TypeScript、Vite 构建出的静态资源嵌入 Go 可执行文件。
- SQLite WAL 保存业务数据、元数据索引、审计和任务检查点。
- 文件内容始终保留在 NAS 文件系统，不写入 SQLite。

首版不引入 PostgreSQL、Redis、OpenSearch、MinIO、LibreOffice、OnlyOffice 或 FFmpeg，不使用 GPU。

## 3. 模块边界

- Identity：账号、密码、TOTP、会话和 Token。
- Access Policy：系统角色、空间 ACL、凭证 scope、目录边界和挂载模式的统一判定。
- Storage：受目录文件描述符约束的文件系统访问与挂载能力检测。
- Catalog：对象记录、轻量元数据、扫描、对账和搜索。
- Transfer：分片上传、原子落盘、Range、ETag 和短期下载地址。
- Share：分享生命周期、密码、次数、派生会话和撤销。
- Preview：浏览器可预览类型判定、受限内容输出和可选缩略图。
- MCP Adapter：把应用服务映射为受限 MCP 工具，不直接访问 Storage。
- Jobs：持久化任务、优先级、检查点、重试和公平调度。
- Audit：只追加安全与业务事件、脱敏、保留和导出。

Web、REST、MCP 和分享入口只能调用同一应用服务与 Access Policy，不能分别实现权限规则。

## 4. SQLite

SQLite 使用 WAL 模式，并遵守以下约束：

- 一个受控写入队列，避免无界写竞争。
- 读取使用短事务；禁止在文件 I/O 或网络 I/O 期间持有数据库事务。
- 设置有限 `busy_timeout`，超时返回可重试错误，不无限等待。
- 页缓存目标 32 至 64 MB。
- WAL 检查点有大小和时间上限，避免长期占用交互请求。
- 数据库迁移必须可检测版本；迁移失败时停止启动并保留原数据。

热备份使用 SQLite Online Backup API 或等价的一致性方案，不能把“执行 WAL checkpoint”当作完整备份。

## 5. 文件身份与访问

API 使用不可猜测的内部对象 ID，不接收宿主机绝对路径。对象 ID 映射到 `space_id + mount_id + relative_path + identity_fingerprint`。

所有实际访问在最终打开时重新执行：

1. 账号、ACL、凭证和挂载权限校验。
2. 规范化相对路径校验。
3. 以挂载根目录文件描述符为起点解析目标。
4. 拒绝越出根目录、magic link、异常挂载跨越和不允许的符号链接。
5. 比对对象身份，确认不是同路径替换对象。

Linux 优先使用 `openat2` 与 `RESOLVE_BENEATH`、`RESOLVE_NO_MAGICLINKS` 等约束；不可用时使用逐级目录文件描述符和 `O_NOFOLLOW` 的安全回退。不能采用“先检查字符串路径，再按路径打开”的实现。

## 6. 索引与对账

索引由管理员逐挂载启用。索引只保存名称、相对路径、类型、大小、修改时间和必要身份字段，不读取正文、不计算内容哈希。

- 初始扫描：单并发、分页遍历、200 至 1000 个对象一批、可暂停和续跑。
- 增量更新：文件事件可用时使用；Docker bind mount、SMB/NFS 事件不可靠时自动降级。
- 全量对账：上次完整对账结束后至少间隔 24 小时；任务不得重叠，仅在资源策略允许时运行。
- 一致性：搜索最终一致，文件访问实时回源。

百万文件对账可能持续超过一天，因此调度器不能按固定时刻重复创建全量任务。

## 7. 后台任务调度

后台任务整体并发为 1，但采用优先级和协作式让出：

1. 恢复、数据一致性修复和安全清理。
2. 上传收尾、跨挂载操作和回收站恢复。
3. 回收站清理与临时分片清理。
4. 增量索引与全量对账。
5. 可选缩略图。

扫描任务每批完成后保存检查点并让出执行权，避免长任务阻塞高优先级工作。所有任务必须幂等，重启后从持久化状态恢复；永久失败进入可见失败状态，不无限重试。

## 8. 文件传输

- 上传按固定分片流式写入同挂载临时目录，完成后原子 rename。
- 创建上传会话时预占配额；失败、过期或取消后释放。
- 临时分片具有过期时间，并由高优先级清理任务处理。
- 下载支持 HTTP Range、ETag 和条件请求，内存占用不随文件大小线性增长。
- 文件名、响应头和 `Content-Disposition` 必须安全编码，拒绝 CR/LF。

跨挂载复制使用固定缓冲区流式传输；移动遵守领域模型定义的“复制、校验、删除源”。

## 9. 预览

- 图片由浏览器直接显示；可选缩略图默认关闭、并发为 1。
- PDF 由浏览器端 PDF.js 渲染。
- 文本和 Markdown 限制最大读取字节数；Markdown 严格清洗。
- 音视频仅播放浏览器原生编码。
- Office 和未知格式只提供下载。

不可信主动内容不能与认证应用同源直接执行。详细响应头、隔离源和 sandbox 规则由安全模型定义。

## 10. 网络模式

### 10.1 局域网 HTTP

管理员可以显式启用局域网 HTTP，并配置允许的 LAN CIDR。该模式：

- 只用于可信局域网；界面持续显示不安全提示。
- Cookie 使用 `HttpOnly` 与 `SameSite`，但无法使用 `Secure`。
- 不允许作为公网基线配置。

### 10.2 HTTPS

公网 Web、公开分享、远程 REST 和远程 MCP 必须经极空间反向代理、Caddy、Nginx 或等价入口提供 HTTPS。可信代理 CIDR、外部 URL 和转发头必须显式配置。

管理端、成员 Web、分享、REST、MCP 和 OpenAPI 具有独立暴露开关。默认 Compose 不自动配置 UPnP，不使用 Host 网络或 Docker Socket。

## 11. 资源目标

- 发布 `linux/amd64` 与 `linux/arm64` 镜像。
- 极空间 8 GB RAM 为首要验证环境。
- 空闲内存目标 100 至 300 MB。
- 普通浏览、搜索和传输不超过 500 MB。
- 扫描最多使用半个 CPU 核并受 I/O 限速。
- 内存统计区分应用不可释放内存与 Linux 可回收页缓存。

支持 `PUID`、`PGID`、`TZ` 和 `UMASK`。SQLite 与配置建议放在 SSD 或系统盘，文件内容可以放在机械盘。

## 12. 备份与恢复

备份包括一致性 SQLite 快照、应用配置、密钥和托管文件。外部挂载只备份配置与对象元数据，不复制其文件内容。

恢复旧备份后必须：

- 提升全局凭证代际，使旧浏览器会话、Token、公开分享、分享派生会话、下载票据和上传会话失效；
- 要求管理员通过本地恢复流程重设密码和 TOTP，并要求其他成员在首次登录前重设密码；
- 要求管理员重新验证外部挂载的宿主路径、文件系统身份和读写模式后再启用；
- 校验 SQLite 完整性和托管文件可达性；
- 记录恢复审计事件。
