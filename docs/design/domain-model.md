# Omnora 领域模型

状态：目标设计基线，待实施
日期：2026-08-08

> 本文描述账号—挂载模型的现行领域模型；迁移边界和授权决策以[账号、挂载与内容授权设计](../superpowers/specs/2026-08-08-account-mount-access-design.md)为准。

## 1. 概念速查

| 概念 | 解决的问题 | 谁负责 |
| --- | --- | --- |
| 账号 | 谁在登录、谁获得系统角色和内容授权 | 系统管理员 |
| 个人空间 | 当前账号唯一的个人目录的产品展示名 | 系统自动创建；账号本人管理内容 |
| 默认挂载 | 所有账号个人目录的系统管理存储根 | 系统保护，不按普通挂载管理 |
| 团队空间 | 当前账号获权共用挂载集合的产品展示名 | 面向成员展示；不表示团队级 ACL |
| 共用挂载 | 团队空间中的实际存储根、读写模式、索引和账号授权边界 | 管理员配置；按账号独立授权 |
| 个人目录协作 | 个人根或子目录对另一个登录账号的定向授权 | 个人目录所有者 |
| 文件对象 | 挂载或个人目录中的实际文件或目录 | 按实时内容权限操作 |

`个人空间` 和 `团队空间` 是成员端产品展示名，不是旧 Space 领域对象。服务端、数据库、REST、MCP 和 Token 契约仍不得恢复 `spaces`、`space_members`、`spaceId`、空间成员、空间 ACL 或“一套权限覆盖多个挂载”。

```text
账号
├── 个人空间：默认挂载内的一个隔离个人目录
├── 团队空间：获权的 0..N 个共用挂载
└── 协作：收到和发出的个人目录协作
```

## 2. 核心对象

### 2.1 账号

系统角色为：

- 初始管理员 `initial_admin`；
- 普通管理员 `admin`；
- 普通成员 `member`。

匿名访客不是账号，只能通过有效公开分享会话访问分享目标。AI 客户端不是独立账号，使用绑定账号的 AI Token。

初始管理员与普通管理员对普通业务资源的日常治理能力相同；初始管理员额外拥有初始身份保护权和受限挂载独占治理权。任一管理员可以把成员提升为普通管理员，停用、恢复或删除普通成员，并降级、停用、恢复或删除其他普通管理员；普通管理员不能操作初始管理员身份，任何管理员都不能提升、降级、停用或删除当前登录的自己。

### 2.2 默认挂载与个人目录

系统初始化时创建一个且仅一个 `personal_default` 挂载。初始管理员和以后新增的每个账号，都在该挂载内自动获得一个隔离个人目录。

- 个人目录不是挂载。
- 个人目录所有者拥有隐式完整内容权限。
- 默认挂载不能删除、由管理员主动停用、改根、转为共用挂载或写入普通挂载授权。
- 默认挂载配置模式固定为 `read_write`，不允许管理员主动改为只读；底层不可写、离线或身份异常时进入系统判定的 `unavailable`，并 fail-closed 地停止相关访问。
- 默认挂载使用按账号个人根裁剪的元数据索引，使“个人空间”参加全局搜索但不能跨账号返回结果。
- 服务端把“个人空间”解析为当前账号个人根；客户端不能选择其他账号根。
- 管理员身份不允许在认证成员内容入口浏览其他账号个人目录；只能通过目录所有者发出的协作获得账号内容权限。独立匿名公开分享会话不改变该规则。
- 账号创建与个人目录可用必须形成一个完整业务结果，不允许可登录的半成品账号。
- 个人目录使用稳定 `account_id` 作为物理名称；修改账号显示名称不改物理目录名。
- 账号删除是不可逆身份删除：保留账号 tombstone、`personal_directories` 绑定、个人目录和物理文件，同时撤销会话、`mount_grants`、发出与收到的协作、Token、分享、上传会话和 Transfer Ticket；保留目录不能自动分配给新账号。

### 2.3 共用挂载

除唯一默认挂载外，后续挂载全部是接入既有 NAS 目录的外部共用挂载。Omnora 不创建托管共用挂载。共用不表示自动公开；每个挂载独立向账号授予 `viewer` 或 `editor`，并允许保持零授权。

挂载的三个维度必须分离：

| 维度 | 值 |
| --- | --- |
| 用途 `purpose` | `personal_default \| common` |
| 存储来源 `storage_kind` | 默认挂载固定 `managed`；共用挂载固定 `external` |
| 治理方式 `governance` | `system \| normal \| restricted` |

创建共用挂载时必须设置：

- 容器内已映射且可验证的根路径；
- 显示名称；
- 只读或读写模式；
- 加入索引或不加入索引；
- 普通或受限治理方式；
- 可为空的账号授权列表。

注册外部目录时，所选目录本身就是挂载根。系统不得创建 `<space-id>`、账号 ID 或其他隐式业务子目录。目录中的既有文件在授权和身份验证通过后直接可见。

有效写能力等于“内容权限 ∩ 容器文件系统能力 ∩ Omnora 挂载模式”。宿主机以 `:ro` 提供的目录不能在应用内提升为读写。

每个挂载保存 `mount_identity`，至少包括规范化容器路径、根目录对象身份、设备/文件系统身份和可用的挂载来源信息。相同路径、双向父子路径、符号链接或 magic link、指向同一目录的 bind alias、bind 来源父子关系都视为冲突。无法证明身份和独立性时必须拒绝激活，不提供管理员绕过。

### 2.4 普通与受限挂载

普通挂载由所有管理员共同治理。管理员可以看配置、健康、索引和授权名单，但没有 `viewer/editor` 内容授权时不能浏览文件。

受限挂载采用方案 B：

- 只有初始管理员能通过治理控制面直接发现、创建、配置、重新验证、解除和管理授权；
- 普通管理员未获内容授权时不能从管理列表、直接 ID、统计、审计、索引任务、备份清单或普通错误信息直接发现它；
- 普通管理员获 `viewer/editor` 后只能在成员内容面使用文件，仍不能查看或修改授权名单；
- 初始管理员没有内容授权时也不能浏览文件；
- 该隐藏只针对 Omnora 普通管理员，不对 NAS root、容器 root 或数据库访问者作保密承诺。

普通管理员创建或重命名普通挂载时仍需对全部活跃挂载执行路径重叠和显示名称唯一校验。命中受限挂载或其他不可用条件时统一返回不含对象信息的 `mount_unavailable` 并限速、审计；系统不承诺抵御对已知候选名称或路径的主动资源占用探测，但不得通过列表、直接对象请求或普通系统输出泄露受限挂载信息。

普通/受限治理方式创建后不可切换。挂载激活后，`root_path`、`purpose`、`storage_kind` 和 `governance` 不可修改；需要改变时解除注册并以新挂载 ID 重新注册同一物理路径。显示名称、应用读写模式、索引开关和账号授权可由有治理权的管理员修改；真实文件不移动，旧授权和派生能力不恢复。

### 2.5 文件对象

被编目、分享或进入传输流程的文件对象获得不可猜测的 `file_id`。对象记录至少包含：

- 内容来源类型：个人目录、共用挂载或协作；
- `mount_id`；
- 个人目录或协作边界标识（适用时）；
- 规范化相对路径；
- 文件类型、大小、修改时间和对象身份指纹。

对象不再保存 `space_id`。所有打开、下载、预览和写操作必须回到文件系统复核路径边界、对象类型和身份指纹；数据库索引不是访问授权或文件存在性的最终依据。

### 2.6 个人目录协作

个人目录所有者可以把整个个人根或任意子目录授权给其他活跃账号：

- 每个接收账号独立获得 `viewer` 或 `editor`；
- 协作引用原目录，不复制、不移动文件，也不创建挂载；
- 接收者从“协作 / 与我协作”进入，不出现在共用挂载列表；
- 分享个人根时，当前和未来新增内容均在授权范围内，界面必须强提示；
- 撤销、接收账号停用、来源对象失效或边界变化后，后续访问立即失败。
- `editor` 只能修改协作根内内容，不能改名、移动或删除协作根本身。
- 同一接收账号的父子目录授权不得重叠。
- 收到的协作不能创建匿名公开分享、再授权第三人或建立 MCP Token boundary。
- “保存到个人空间”是复制，不从所有者目录移除原对象。

协作记录必须保存来源与接收账号、来源个人目录、根相对路径、根对象身份、权限、撤销状态和审计字段。

## 3. 权限模型

### 3.1 内容权限

| 能力 | `viewer` | `editor` |
| --- | --- | --- |
| 浏览、授权范围搜索、预览、下载 | 允许 | 允许 |
| 上传、新建目录、复制到目标 | 禁止 | 允许 |
| 修改、移动、改名、删除 | 禁止 | 允许 |

所有写操作仍要求目标挂载实际可写。个人目录所有者等价于其个人根内的隐式完整内容权限，但不生成可跨账号复用的普通挂载授权。

### 3.2 权限来源

- 个人目录本人：所有者隐式权限。
- 共用挂载：`mount_grants` 中的 `viewer/editor`。
- 个人目录协作：`folder_collaborations` 中的 `viewer/editor` 和目录边界。
- 匿名访客：公开分享会话的只读边界。
- AI 客户端：只使用账号自己的个人目录权限和当前有效 `mount_grants`，明确排除 `folder_collaborations`，再与 Token scope 和 boundary 求交集。

### 3.3 系统治理权限

管理员治理权限与内容权限是两条独立权限链：

- 普通挂载：全部管理员可治理。
- 受限挂载：仅初始管理员可治理。
- 默认挂载：只能执行系统明确提供的保护性维护流程。
- 个人目录协作：由个人目录所有者管理，不由挂载授权替代。

管理账号、挂载、索引或审计都不会自动增加内容权限。挂载创建者也不会自动获得内容权限。

### 3.4 有效权限

每次内容操作至少同时满足：

```text
路由组 ∩ 主体和凭证有效
       ∩ 实时内容权限来源
       ∩ Token scope 和资源边界（使用 Token 时）
       ∩ 挂载身份、状态和读写模式
       ∩ 路径边界、对象状态和保留命名空间
       ∩ 配额、限速和并发限制
```

任一条件撤销或降级后，活动 MCP 连接、上传会话和短期下载票据的后续请求都必须按新权限拒绝。缓存不能保留已失去的授权。

## 4. 索引与搜索

每个共用挂载独立选择是否加入索引。个人目录搜索必须被裁剪到当前账号个人根。

| 能力 | 加入索引 | 不加入或已暂停 |
| --- | --- | --- |
| 当前目录浏览 | 可用 | 可用，实时读文件系统 |
| 元数据搜索 | 当前账号有权时包含 | 排除并明确提示 |
| 后台扫描与对账 | 执行 | 不执行 |

搜索必须先按账号实时内容权限过滤。未授权挂载不能通过结果、命中数、过滤器、排除原因、统计或过期索引泄露存在；索引关闭、暂停、离线或未完成首扫等排除原因只列出当前账号已获权且可发现的挂载。成员 Web 全局搜索覆盖自己的个人目录、获权共用挂载和当前有效的收到协作；协作结果标记来源、实时复核并按对象去重。“我发起的协作”不重复加入。

## 5. 删除、移动与解除挂载

### 5.1 文件删除

| 删除情形 | 删除行为 | 恢复方式 |
| --- | --- | --- |
| 不超过 200 MB 且通过批次阈值检查的可写内容 | 进入删除者自己的个人回收站 | 保留期内由删除者恢复 |
| 超过 200 MB 的文件 | 明确二次确认后永久删除 | 依赖 NAS 快照或备份 |
| 外部只读挂载 | 拒绝 | 不适用 |

200 MB 按 `200 × 1024 × 1024` 字节计算。回收站对象计入删除者个人目录容量；收到协作的对象进入回收站后不能公开分享或再授权。从共用挂载或协作进入个人回收站时，系统必须先预留个人配额，复制到受保护回收站、校验并持久化 journal，再删除源；部分失败不得丢失唯一副本，并进入可重试或人工清理终态。恢复优先回到原位置并重验 `editor`，原位置或权限不可用时恢复到删除者“个人空间/从回收站恢复”，且不能覆盖现有对象。目录或批量选择只要包含超过阈值的文件，整批不能进入回收站，只能拆分或明确永久删除。进入回收站立即使该对象的公开分享、下载票据和活动写入失效，恢复后不自动恢复旧分享。`.omnora` 是保留命名空间，用户不能创建、改名、移动、上传覆盖、分享或通过 AI Token 访问。

### 5.2 同挂载与跨挂载

- 同挂载移动和改名使用文件系统原子 rename，成功后保留 `file_id`。
- 复制要求源端 `viewer+`，目标端 `editor` 且可写。
- 移动要求源端 `editor` 且可写，目标端 `editor` 且可写。
- 跨挂载移动按“复制、校验目标、删除源”执行，部分完成状态必须可审计、可重试和人工清理。
- 从收到的协作保存到自己的文件只允许复制；不能以跨挂载移动为名删除所有者原对象。

### 5.3 解除共用挂载

解除共用挂载要求精确输入当前显示名称，只删除 Omnora 控制面注册，不删除 NAS 真实目录或文件。活跃挂载显示名称规范化后全局唯一且忽略大小写。挂载 tombstone 永久保留，审计记录按安全保留策略保存；授权、Token boundary、分享、Transfer Ticket、上传会话、索引和活动任务必须同步失效，并记录 `dataDeleted: false`。失效上传会话的临时分片由幂等清理流程处理。

同一物理路径以后可以重新注册，但使用新的挂载 ID，旧授权和派生能力不能恢复。

默认挂载不得解除。受限挂载只能由初始管理员解除，且不能经普通管理员可见的全局结果泄露对象存在。

## 6. 分享生命周期

账号间目录协作与匿名公开分享是两种不同能力。协作面向登录账号并使用实时 `viewer/editor`；公开分享使用独立匿名访客主体和短期分享会话。认证成员只能经所有权或协作进入个人根，公开分享会话不会给该成员账号增加个人目录权限。

公开分享绑定稳定文件或目录对象身份，不绑定裸路径：

- 同挂载内移动或改名同一对象，分享保持有效；
- 跨挂载移动、外部替换、删除或对象身份不匹配时失效；
- 创建者账号停用或删除、内容权限撤销时立即失效；
- 管理员可以按治理权限撤销分享，但不能读取分享密码或秘密。

个人文件由所有者创建公开分享。共用挂载默认允许 `editor` 创建公开分享，但有该挂载治理权的管理员可以关闭此能力；关闭后既有分享及派生会话立即失效。挂载分享只能由对应治理范围内的管理员查看和撤销，受限挂载相关元数据仅初始管理员可见；所有管理员可以查看并撤销个人目录公开分享的最小安全元数据，但不能查看路径、文件正文、密码或分享秘密。收到的协作禁止创建公开分享。全局公开分享路由组仍必须启用。

## 7. AI Token 与 MCP

AI Token 是绑定账号、可撤销、可过期的受限凭证。Token 只能缩小账号实时权限，不能扩大权限。

- 普通共用挂载对象由 `mount_id + relative_path` 定位。
- “个人空间”由账号作用域个人根和相对路径定位，不允许客户端选择其他账号。
- 协作对象只由成员 Web 和会话 REST 使用 `collaboration_id + relative_path` 定位；MCP/AI Token 不接受该内容源。
- boundary、分享、上传、索引、文件对象和 Transfer Ticket 不再保存 `space_id`。
- 目标 MCP 删除 `spaces.list`，将 `spaces:read` 改为 `mounts:read`，并移除所有 `spaceId` 输入。
- AI Token 可以选择动态的“当前账号全部内容源”边界，覆盖自己的个人目录和当前获权共用挂载；新授权自动进入、撤销后立即失效，但不包含收到的协作。
- 新 MCP 文件工具显式使用 `{source: "personal", path}` 或 `{source: "common_mount", mountId, path}`；个人源不能携带账号 ID 或默认挂载 ID，协作源始终拒绝。
- AI Token 只认证 MCP、Transfer Ticket 和新 OpenAPI 明确白名单化的文件 REST 路由，不能进入账号、会话或管理员控制面；AI Token REST 也拒绝协作源。
- 所有管理员可以查看账号 Token 的通用安全元数据并撤销 Token，但普通管理员无权查看的资源边界必须统一脱敏，不能通过字段或数量差异发现受限挂载。

迁移完成前，MCP 文档中的 25 个工具和 15 个 scope 仍是当前实现事实；新模型实施时必须按实际 catalog 重新计算，不能把旧计数直接复制到新验收标准。

Transfer Ticket 绑定一个账号、AI Token、操作、资源边界、对象指纹和字节预算。每个下载 Range 或上传 part 都重新验证 Token、内容权限、边界、挂载身份、对象指纹和票据状态。

## 8. 配额

- 默认挂载中的个人目录可按账号统计托管文件与回收站大小；具体物理命名不参与配额身份。
- 外部挂载不维护 Omnora 写入归属账本，也不提供应用级账号配额；容量治理依赖 NAS 配额。
- 所有可写挂载受磁盘安全水位保护，空间不足时停止新增占用，但继续允许浏览和下载。

## 9. 默认挂载修复

默认挂载离线、身份漂移、个人目录丢失或初始化部分失败时必须 fail-closed，不得静默创建同名空目录。仅初始管理员可以执行修复：重新验证默认挂载身份、核对账号映射、选择恢复原目录或明确建立替代目录、处理孤立准备状态并审计。删除账号的保留目录不能自动绑定给新账号。
