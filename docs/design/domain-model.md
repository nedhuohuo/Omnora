# Omnora 领域模型

状态：第一版设计基线
日期：2026-08-02

## 1. 核心对象

### 1.1 账号

首版只有两种系统角色：

- 管理员：管理账号、空间、挂载、全局策略、审计和安全治理。
- 成员：拥有个人空间，并按空间 ACL 使用共享空间。

匿名访客不是账号，只能通过有效分享会话访问分享目标。AI 客户端不是独立账号，使用绑定成员的专用 Token。

### 1.2 空间

空间是成员关系与 ACL 的逻辑边界：

- 个人空间：创建成员时自动创建；该成员自动拥有 `manager`。
- 共享空间：由管理员创建；成员通过 ACL 获得权限。

一个空间可以包含多个挂载。空间 ACL 统一作用于空间下全部挂载；首版不提供挂载级 ACL。

空间 `manager` 管理空间成员、分享和文件内容，不管理挂载。挂载是系统控制面资源，只能由系统管理员配置；管理员配置个人空间挂载不因此获得个人空间内容权限。

### 1.3 挂载

挂载是空间内的实际文件系统根。每个挂载只能属于一个空间，并在该空间内使用唯一显示名称。新增、改名、变更空间归属、修改根路径或模式、停用、删除和重新验证挂载都要求系统管理员权限，不经过空间 ACL 授权。

创建挂载时必须设置：

- 宿主机已映射到容器的根路径；
- 空间内显示名称；
- 应用模式：只读或读写；
- 索引模式：加入索引或不加入索引。

挂载分为：

- 托管挂载：由 Omnora 管理内容，支持回收站和应用配额。
- 外部挂载：接入 NAS 已有目录，默认只读；读写模式不提供 Omnora 回收站。

有效写能力等于“容器挂载能力 ∩ Omnora 应用模式”。Omnora 不能在 Web 中把 Docker `:ro` 提升为读写。宿主机操作者必须先修改 Compose 为 `:rw` 并重建容器，管理员随后才能在应用中确认启用写操作。

每个挂载还具有由系统验证的 `mount_identity`，至少描述规范化容器路径、根目录对象身份、文件系统/设备身份和可用的挂载来源信息。以下任一关系都视为重叠，且与挂载所属空间、读写模式或启用状态无关：

- 容器路径相同或按路径组件构成双向父子关系；
- 候选根或其父路径包含符号链接、magic link 或其他不允许的间接解析；
- 不同容器路径实际指向同一根目录对象；
- bind mount 的来源相同，或来源目录按路径组件构成父子关系。

系统必须将候选挂载与所有未删除挂载比较。无法可靠获得身份、无法证明相互独立或发现冲突时，挂载不能激活，首版不提供管理员绕过。启动、备份恢复、重新启用和扫描前发现挂载身份漂移时，该挂载进入不可用状态，等待管理员重新验证。

### 1.4 文件对象

每个被 Omnora 编目或首次引用的文件对象获得不可猜测的 `file_id`。对象记录至少包含：

- `space_id`
- `mount_id`
- 规范化相对路径
- 文件类型、大小和修改时间
- 文件系统可提供的对象身份指纹

对未加入全局索引的挂载，目录浏览直接读取文件系统；当对象被分享、加入传输流程或通过 API 引用时，只创建该对象的最小记录，不触发全树索引。

所有打开、下载、预览和分享访问必须回到文件系统复核路径边界、对象类型和身份指纹。数据库索引不是访问授权或文件存在性的最终依据。

## 2. 权限模型

### 2.1 空间 ACL

| 能力 | `viewer` | `editor` | `manager` |
| --- | --- | --- | --- |
| 浏览、搜索、预览、下载 | 允许 | 允许 | 允许 |
| 上传、新建目录、复制到目标 | 禁止 | 允许 | 允许 |
| 移动、改名、删除 | 禁止 | 允许 | 允许 |
| 创建和管理自己的分享 | 禁止 | 禁止 | 允许 |
| 管理空间成员 ACL | 禁止 | 禁止 | 允许 |

所有写操作还要求目标挂载实际可写。

### 2.2 系统管理员

管理员拥有系统治理权限，但默认没有成员个人空间的内容权限。管理员可以：

- 管理成员状态、空间配置和挂载；
- 查看权限与凭证元数据，但不能查看密码、Token 明文或 TOTP 密钥；
- 撤销任意会话、Token 和分享；
- 查看全局审计。

管理员访问个人空间内容必须使用安全模型定义的应急访问流程。该授权只提供目标空间最长一小时的临时 `viewer` 权限，需重新认证和填写原因，并产生完整审计。管理员账号锁定恢复与个人空间应急访问是两个独立流程。

### 2.3 有效权限

每次请求的有效权限为以下条件的交集：

`账号当前状态 ∩ 空间 ACL ∩ 凭证 scope ∩ 凭证目录边界 ∩ 挂载模式`

任一条件被撤销或降级，后续请求立即按新权限判断。缓存、活动 MCP 连接、上传会话和短期下载地址不能保留已失去的权限。

该公式只授权文件内容操作。挂载控制面操作始终要求当前主体为系统管理员，不能由空间 `manager`、应急 `viewer`、分享会话或 Token 获得。

## 3. 索引语义

每个挂载独立选择“加入索引”或“不加入索引”，管理员后续可以暂停、开启或关闭。

| 能力 | 加入索引 | 不加入或已暂停 |
| --- | --- | --- |
| 当前目录浏览 | 可用 | 可用，实时读取文件系统 |
| 全局元数据搜索 | 包含该挂载 | 排除该挂载并明确提示 |
| 后台扫描与对账 | 执行 | 不执行 |
| 已有索引记录 | 正常更新 | 保留但不参与搜索结果 |

全局搜索允许最终一致。目录打开、文件读取、下载、分享和写操作必须实时回源复核。发现失效索引记录时，本次请求返回“对象已变化或不存在”，并异步标记记录等待修复。

## 4. 删除与移动

### 4.1 删除

| 挂载类型 | 删除行为 | 恢复方式 |
| --- | --- | --- |
| 托管挂载 | 移动到保留目录 `.omnora/trash/` | 保留期内由 Omnora 恢复 |
| 外部读写挂载 | 明确二次确认后永久删除 | 依赖 NAS 快照或备份 |
| 外部只读挂载 | 拒绝 | 不适用 |

`.omnora` 是保留命名空间，用户不能创建、改名、移动、上传覆盖、分享或通过 AI Token 访问。回收站内容计入托管空间配额。

### 4.2 同挂载操作

同挂载移动和改名使用文件系统原子 rename。成功后保留 `file_id` 并更新相对路径；失败时不得更新数据库为成功状态。

### 4.3 跨挂载操作

- 复制：源空间需要 `viewer+`，目标空间需要 `editor+`，目标挂载必须可写。
- 移动：源空间需要 `editor+` 且源挂载可写，目标空间需要 `editor+` 且目标挂载可写。
- 跨挂载移动按“复制、校验目标、删除源”执行。删除源之前必须确认目标可读且内容长度符合预期。
- 部分完成状态必须可审计、可重试，并给出人工清理入口。

## 5. 分享生命周期

只有目标空间的 `manager` 可以创建分享。分享绑定 `file_id` 或目录对象 ID，而不是裸路径。

- 通过 Omnora 在同一挂载内移动或改名同一对象：分享继续有效。
- 通过 Omnora 跨挂载移动：原分享失效，避免跨越挂载与权限边界。
- 对象被外部移动、删除或替换：身份复核失败，分享立即失效。
- 创建者失去目标空间 `manager`、账号被禁用或删除：其分享立即失效。
- 管理员可以撤销任意分享，但不能读取分享密码或明文 Token。

分享状态、过期时间、访问次数和下载次数在每次派生会话及实际读取时重新检查。次数限制必须在授权时通过 SQLite 原子事务预占，不能在下载结束后才计数。

## 6. Token 生命周期

个人访问令牌和 AI Token 都绑定成员账号，但使用不同用途标识和 scope。首版 AI Token 不允许删除文件或创建公开分享。

- 成员只能创建、查看元数据和撤销自己的 Token。
- 管理员只能查看 Token 元数据和撤销，不能读取明文。
- 账号禁用或删除、ACL 降级、Token 过期或撤销后，派生会话和短期 URL 立即失效。
- Token 目录边界必须位于账号当前可访问的空间和挂载内。

## 7. 配额

- 托管挂载按空间统计文件与回收站总大小，超配额后拒绝上传和占用新空间的复制。
- 外部挂载首版不维护“由 Omnora 写入”的归属账本，也不提供应用级用户配额；容量治理依赖 NAS 配额。
- 所有可写挂载都受磁盘安全水位保护，空间不足时停止新上传、复制和缩略图任务。
- 缩略图使用独立缓存配额，不计入用户空间配额。
