# Omnora / 万境安全模型

日期：2026-08-02
状态：首版安全基线
适用范围：Omnora Web、REST、MCP、公开分享、文件传输、后台任务与备份恢复

## 1. 目的与原则

本文定义首版必须实现的安全边界和可验证行为。产品设计说明“提供什么”，本文说明“在什么信任条件下提供、如何授权、何时失效以及怎样验收”。若其他文档与本文的安全规则冲突，以更严格且可实现的规则为准，并在实现前修正文档冲突。

首版遵循以下原则：

1. 默认拒绝。内部文件 ID、已建立会话、索引记录和管理员系统角色都不能替代对象级授权。
2. 每次访问都按当前状态重新计算权限。不能只在创建 Token、分享、上传会话或下载地址时检查一次。
3. 文件系统是内容真实来源，索引是可丢弃缓存；索引中的路径或元数据不能作为文件系统安全证明。
4. 文件名、文件内容、浏览器请求、代理头、AI 输入和外部挂载都视为不可信输入。
5. 撤销优先于便利。账号禁用、ACL 降级、Token 撤销和分享撤销必须使派生能力及时失效。
6. 不声明无法在首版兑现的安全保证。Omnora 不防御已取得 NAS root 权限的攻击者，也不承诺恶意软件检测、端到端加密或不可篡改审计。

## 2. 信任边界与威胁范围

### 2.1 受信任组件

- NAS 宿主机、宿主机管理员及容器运行时属于信任根。宿主机 root 可以读取或修改挂载文件、SQLite、配置和密钥，Omnora 首版不能对其隐藏内容。
- 官方发布镜像及其锁定版本的依赖在供应链校验通过后视为受信任代码。
- 明确配置的反向代理可以提供 TLS 终止和真实来源地址；只有配置的代理地址或 CIDR 才是可信代理。

### 2.2 不受信任边界

- 浏览器、REST/MCP 客户端、匿名访客及其提交的所有参数。
- AI 客户端及其读取的文件内容。文件内提示词不能改变服务端权限，也不能自行触发工具调用。
- 文件名、路径片段、MIME、扩展名、Markdown、图片、PDF、媒体和下载文件。
- 外部挂载的目录结构及外部程序对它的并发修改。
- 未列入可信代理的 `Forwarded`、`X-Forwarded-*`、`X-Real-IP` 和 `Host` 值。
- SQLite 中的索引记录。文件可能已被宿主机上的其他程序移动、替换或删除。

### 2.3 首版明确不提供

- 不扫描病毒、木马或恶意文档，不保证下载文件安全。
- 不抵御宿主机 root、被攻陷的容器运行时或物理磁盘访问者。
- 不提供应用层端到端加密，也不替代 NAS 自身的磁盘加密和备份。
- 不把“关闭下载按钮”描述为防止访客保存已预览内容。
- 审计记录只在应用层追加；宿主机管理员仍可修改数据库或日志。

## 3. 网络与端点暴露

### 3.1 网络模式

Omnora 首版只提供一个 HTTP 监听地址。私网 IP、Host、客户端提交的转发头和应用监听 `0.0.0.0` 都不能证明请求属于安全局域网。是否可被公网访问由 Docker 端口绑定、宿主防火墙、安全组和反向代理共同决定。Omnora 不配置 UPnP，不自动开放路由器端口。

公网访问应由 Lucky、极空间反向代理、Caddy、Nginx 或等价入口终止 HTTPS 后转发到 Omnora HTTP 后端。公网 `80` 只能跳转到 HTTPS，不得直接代理受保护端点；代理后端端口不能直接暴露到公网，未匹配 Host 必须拒绝。

### 3.2 端点分组

端点至少分为以下可独立发布的路由组：

- 公开分享入口：可由管理员显式通过 HTTPS 对外发布。
- 成员 Web：默认局域网可用；公网发布需要显式启用。
- REST：默认不经公网代理发布；需要远程 API 访问时单独启用。
- MCP：默认不经公网代理发布；需要外部 AI 访问时单独启用。
- OpenAPI：独立控制文档是否暴露，不随 REST 自动公开。
- 管理端与初始化/恢复入口：默认不对公网发布。初始化和恢复不能因开启分享而自动暴露。

反向代理模板必须允许按路由组控制暴露范围。启用一个路由组不得隐式启用其他组。

### 3.3 HTTP 防护

- HTTPS 响应启用 HSTS；所有模式设置 `X-Content-Type-Options: nosniff`、适当的 CSP、`Referrer-Policy` 和点击劫持防护。
- 浏览器状态变更使用 CSRF Token，并配合 `SameSite=Lax` 或更严格的会话 Cookie。Bearer Token 不使用 Cookie 传递。
- CORS 默认为关闭；启用时使用显式来源白名单，不允许 `*` 携带凭据。
- MCP Streamable HTTP 和浏览器可调用 API 校验 `Origin` 与允许的 `Host`，防止跨站请求和 DNS rebinding。MCP session ID 不是认证凭证。
- 只有来自可信代理的转发头参与来源 IP、限速和 HTTPS 判断。其他请求忽略并覆盖这些头。
- 应用和推荐代理配置必须对分享令牌、下载票据、密码和 Authorization 头进行日志脱敏。

## 4. 认证与账号安全

### 4.1 首次初始化

- 不提供默认账号或默认密码。
- 初始化令牌至少包含 256 位安全随机值，只保存哈希，并通过宿主机本地命令或权限为 `0600` 的一次性文件交付；不得写入 URL、普通访问日志或镜像。
- 初始化令牌有短期有效期且只能使用一次。首个管理员创建与初始化关闭必须在同一 SQLite 原子事务中完成。
- 两个并发初始化请求最多一个成功。初始化完成后，网络初始化路由永久返回不可用，除非创建全新数据库。
- 管理员完成密码设置和 TOTP 登记前，只能访问初始化步骤，不能配置公网、分享、Token 或挂载。

### 4.2 密码、TOTP 与密钥

- 账号密码和分享密码分别使用带独立随机盐的 Argon2id。参数应在目标 NAS 上标定，使验证成本可接受且不造成拒绝服务；不得使用快速哈希保存低熵密码。
- 管理员强制使用 TOTP，成员可选。TOTP 密钥在数据库中加密保存；加密主密钥位于独立配置文件，权限限制为应用用户可读。
- 登录、TOTP、分享密码和初始化验证按来源 IP 与账号/分享主体双维度渐进限速。响应不能泄露账号、分享或第二因素是否存在。
- 修改密码、TOTP、账号邮箱/名称等敏感身份信息前需要近期重新认证。管理员敏感操作还必须验证 TOTP。
- 账号被禁用或删除时，立即撤销其会话、Token 和由该账号创建的活动分享。
- 管理员发起的密码/TOTP 重置或账号锁定恢复视为凭证可能泄露：除旧会话失效外，还要撤销该账号的 PAT/AI Token 和活动分享。成员主动修改已知密码时至少撤销其他浏览器会话，并允许其显式选择同时撤销 Token 与分享。

### 4.3 浏览器会话

- 会话使用至少 256 位随机的不透明 ID，数据库只保存哈希。
- HTTPS 下 Cookie 使用 `HttpOnly`、`Secure`、`SameSite=Lax` 或更严格值，限制 `Path`，不设置宽泛 `Domain`。
- 登录成功、权限提升、密码/TOTP 变更后轮换会话 ID，防止会话固定。
- 会话同时具有空闲超时和绝对有效期，均可由管理员在安全上限内收紧。退出登录、账号禁用、密码重置和管理员锁定恢复使相关会话立即失效。
- 每个受保护请求均检查会话撤销状态、账号状态和当前权限，不能把角色与 ACL 永久缓存到 Cookie。

## 5. 管理员权限与个人空间隐私边界

系统管理员角色默认是控制面权限，不自动获得成员个人空间的内容权限。管理员可以管理账号、挂载、系统策略、全局审计和撤销任意分享，但在没有空间 ACL 时不能浏览、搜索、预览、下载或修改个人空间内容。

管理员访问个人空间内容必须通过该空间的普通 ACL 显式授权，且受统一授权模型约束。系统不提供绕过 ACL 的临时内容访问入口。

管理员账号锁定恢复只恢复管理员身份，不授予个人空间内容权限，也不重新开放初始化入口。

## 6. 统一授权模型

### 6.1 有效权限公式

每次操作的有效权限按以下交集计算：

```text
有效权限 =
  路由组已启用
  ∩ 主体当前有效
  ∩ 凭证当前有效
  ∩ 当前空间 ACL
  ∩ Token / 分享的 scope 与目录边界
  ∩ 挂载读写模式
  ∩ 对象状态与保留命名空间规则
  ∩ 操作级配额、限速和并发限制
```

任何一项不满足即拒绝。系统管理员的控制面能力不能替代空间 ACL；只读挂载模式不能被管理员、REST、MCP 或后台任务覆盖。

授权必须在以下时点重新执行：

- 开始浏览、搜索、预览或下载时，以及每个 Range 请求。
- 创建上传会话时、接收每个分片时和最终提交前。
- 创建短期下载地址时和该地址实际使用时。
- MCP 工具调用时，而不是只在建立 MCP 会话时。
- 后台复制、移动、恢复或清理任务领取任务时及破坏性步骤执行前。

### 6.2 Token scope

AI Token 是绑定成员账号的受限 PAT。首版仅允许以下能力组合：

- 列出空间、目录与文件。
- 搜索已授权且已索引的范围。
- 读取文件元数据。
- 受限读取允许预览的文本内容。
- 创建绑定单一对象的短期下载地址。
- 在额外启用上传 scope 后创建上传会话。

AI Token 首版不得删除、永久移动、恢复、管理 ACL、创建或管理公开分享、访问回收站、执行管理员操作。上传 scope 不隐含覆盖既有文件；覆盖必须是独立能力，首版不向 AI Token 开放。

目录边界使用挂载 ID 与规范化相对路径保存。Token 对目录的授权包含当时和以后位于该目录子树的对象，但仍受账号当前 ACL、挂载模式和对象状态约束。

## 7. 凭证与派生能力生命周期

### 7.1 通用规则

- Token 和分享令牌采用 `公开 ID + 随机秘密` 形式；公开 ID 用于查找，数据库只保存随机秘密的哈希。明文秘密只展示一次。
- 所有凭证具有创建时间、有效期、最后使用时间、撤销时间和可审计标识。有效期必须存在；管理员只能在配置的安全上限内调整。
- 日志、错误、审计和遥测只能记录凭证标识，不能记录明文秘密、URL 片段或 Authorization 头。
- 账号禁用/删除、ACL 降级、挂载变为只读、Token 撤销或系统凭证代际变化后，派生能力不能继续使用旧授权。

### 7.2 生命周期矩阵

| 能力 | 创建时绑定 | 每次使用检查 | 立即失效条件 |
| --- | --- | --- | --- |
| 浏览器会话 | 账号、会话代际 | 账号、会话撤销、当前 ACL | 退出、超时、密码/TOTP 重置、账号禁用、恢复代际变化 |
| AI Token | 账号、scope、挂载/目录、有效期 | 账号、Token、当前 ACL、挂载模式 | 撤销/过期、账号禁用、账号凭证恢复、ACL 不再覆盖、恢复代际变化 |
| 分享 | 创建者、目标对象、能力、限制 | 分享状态、目标边界、挂载可用性 | 撤销/过期、创建者禁用或凭证恢复、失去目标 `manager`、跨挂载移动、对象删除或替换、恢复代际变化 |
| 分享会话 | 分享、分享代际、密码验证状态 | 分享仍有效、对象范围、会话期限 | 分享变化、撤销/过期、密码变更、会话超时、恢复代际变化 |
| 下载票据 | 主体/分享、单一对象、动作、短期有效期 | 原始授权、对象身份、使用状态 | 原始授权失效、对象替换、使用/过期、恢复代际变化 |
| 上传会话 | Token/会话、目标目录、文件名、声明大小、配额预占 | 原始授权、挂载模式、分片与配额状态 | 原始授权失效、过期、提交/取消、恢复代际变化 |

短期下载地址和上传会话使用服务端保存的不透明票据，不能使用撤销后仍可离线验证通过的长期自包含签名 URL。

## 8. 公开分享安全

### 8.1 分享创建与范围

- 只有目标空间当前 `manager` 可以创建分享。分享保存目标内部 ID 及创建时的对象身份，不接受宿主绝对路径。
- 文件夹分享仅覆盖该目录当前子树；每次请求都重新验证后代关系。`..`、符号链接、回收站及其他保留目录不能扩展范围。
- 对象经 Omnora 在同一挂载内改名或移动时分享继续有效；跨挂载移动、外部移动、替换或删除时分享立即失效。
- 创建者账号被禁用/删除或失去目标空间 `manager` 时，分享立即失效。重新获得账号或权限不会自动恢复旧分享，必须重新创建。
- “允许预览、禁止下载”只影响产品入口；文档和 UI 必须提示已展示内容可能被保存。

### 8.2 令牌、密码与分享会话

- 分享令牌至少包含 256 位随机秘密。首版把秘密放在 URL fragment 中，由前端通过 `POST` 请求体交换短期分享会话。
- 服务端不得要求或接受位于 URL 路径、查询参数或 `Referer` 中的分享秘密；若请求试图通过这些位置提交秘密，必须拒绝换票，不得建立分享会话，也不得将其记为一次成功访问。
- 推荐代理配置不得把 fragment 转发到上游；应用日志、错误响应和审计只能记录公开 ID 等非秘密标识。
- 分享密码使用独立 Argon2id 哈希。失败验证按 IP 与分享 ID 限速，响应不区分令牌错误、密码错误、过期或已撤销。
- 分享会话 Cookie 为 HttpOnly；HTTPS 模式启用 Secure。会话最长不得超过分享剩余有效期，并绑定分享代际。
- 修改分享密码、范围、预览/下载能力或次数限制时递增分享代际，使现有会话和下载票据失效。

### 8.3 次数限制与并发

次数限制通过 SQLite 条件更新在授权事务中原子预占，不能在内容传输完成后才累加：

```sql
UPDATE shares
SET used = used + 1
WHERE id = ? AND revoked_at IS NULL AND used < max_uses;
```

实际实现还需同时检查有效期和分享代际。未更新任何行即拒绝请求。

- “访问次数”固定定义为成功交换令牌并建立一次新的分享会话。同一分享会话内的页面刷新、目录浏览和预览不重复计数；会话过期后重新交换令牌会再次计数。
- “下载次数”在创建单次下载票据时预占。网络中断不退还次数，避免并发退款竞态；UI 应明确该语义。
- 一个下载票据绑定分享、会话、单一文件身份和短期有效期。Range 请求可以复用同一票据，但不能改换文件，也不能创建第二次完整下载。
- 并发请求在上限只剩一次时，最多一个事务成功。

## 9. 文件系统边界

### 9.1 挂载与路径解析

- 宿主目录必须先由部署者 bind mount 到预声明的容器路径。Web、REST 和 MCP 不接受任意宿主路径，也不能在容器内执行 mount。
- 挂载配置属于系统控制面，只允许系统管理员操作。空间 `manager`、应急 `viewer`、分享和 Token 不能新增、修改、停用、删除或重新验证挂载；管理员配置挂载不授予个人空间内容权限。
- 注册前按路径组件拒绝相同路径和双向父子路径；候选根及其父组件包含符号链接或 magic link 时拒绝。安全打开根目录后比较设备号、inode、mount ID，并结合 `/proc/self/mountinfo` 的文件系统设备与 mount root 识别相同 bind 来源和来源父子关系。
- 候选挂载与所有未删除挂载比较，不因只读、停用或属于同一空间而放宽。身份信息不足或无法证明互不重叠时返回 `mount_identity_unverifiable` 并拒绝激活，不允许管理员确认绕过。
- 启动、备份恢复、重新启用、扫描和实际访问时复核根身份。身份漂移、不可验证或新冲突使挂载立即不可用；搜索排除其索引，所有入口拒绝分享和文件访问，直到管理员重新验证。
- 内部文件 ID 只是定位信息，不是授权证明。访问时从挂载根目录文件描述符开始解析规范化相对路径。
- 首版默认不跟随符号链接。Linux 上优先使用 `openat2`，至少启用 `RESOLVE_BENEATH`、`RESOLVE_NO_MAGICLINKS`、`RESOLVE_NO_SYMLINKS`，并按根策略阻止跨文件系统边界。
- 若运行环境不支持 `openat2`，必须逐级使用目录文件描述符和 `openat`/`O_NOFOLLOW` 安全解析，并验证每一级类型；不得退化为字符串前缀检查加普通 `open`。
- 列表、预览、下载、上传提交、改名、移动、删除和后台扫描使用同一安全解析器。

### 9.2 TOCTOU 与对象身份

- 权限检查和文件操作尽量基于已经安全打开的文件描述符执行，避免“检查路径后再次按字符串打开”。
- 使用索引结果访问文件时，在打开后比较必要的文件系统身份和类型。对象已被替换时刷新索引并重新授权，不能继续使用旧下载票据。
- 同挂载临时文件使用不可预测名称和排他创建，并与目标位于同一文件系统后再原子 rename。
- 跨挂载移动按复制后删除处理；删除源之前重新检查源身份和删除权限。部分完成状态必须可审计且可人工处理。

### 9.3 挂载模式与保留目录

- 外部挂载默认以容器 `:ro` 挂载，应用层也拒绝所有写操作。管理员身份不能绕过任一层。
- 托管挂载的 `.omnora/` 是保留命名空间。所有普通用户、分享和 AI Token 均不能列出、读取、创建、覆盖、改名或移动对象到该路径。
- 回收站恢复属于写操作，要求当前目标空间至少 `editor` 且目标挂载可写；清理与永久删除属于高风险操作，必须审计。
- 外部读写挂载的永久删除不提供 Omnora 恢复。Web 要求明确确认；REST 使用明确的永久删除操作而不是普通删除参数隐式升级。

## 10. 不可信内容与浏览器预览

文件扩展名和客户端 MIME 只能帮助选择体验，不能授予安全能力。服务端检查内容特征并采取以下响应策略：

- HTML、SVG、XML、Office 文件、未知格式和无法安全分类的文件一律作为附件下载，不在 Omnora 应用源执行或内联打开。
- 所有文件响应设置 `X-Content-Type-Options: nosniff`。下载文件名按标准方式编码，移除控制字符、CR/LF 和路径分隔符。
- Markdown 只读取有限字节，禁用原始 HTML，使用允许列表清洗标签、属性和 URL scheme。外部链接使用安全的 `rel`，不得继承应用权限。
- 文本预览按字节数和编码限制处理，作为文本节点渲染，不使用未经清洗的 HTML 注入。
- PDF.js 及其他预览容器使用严格 CSP 和 sandbox，不向文件内容暴露应用 Cookie、Token、父页面 DOM 或任意网络访问。
- 栅格图片和浏览器原生媒体可以内联，但仍经过类型、大小、Range 和授权检查。服务端不解码转码，不把解析器隔离承诺扩大到不存在的 Worker。
- 分享页面不加载第三方脚本，不发送包含分享信息的 Referer，不允许第三方分析代码读取分享状态。

## 11. 上传、临时文件与配额

- 创建上传会话时必须声明目标目录、规范化文件名、预期大小和覆盖意图。文件名拒绝 NUL、控制字符、路径分隔符、`.`、`..`、保留名称和超过文件系统限制的值。
- 首版 AI Token 不允许覆盖现有对象。浏览器/API 覆盖必须具有 `editor` 权限并显式请求，提交前再次确认目标身份。
- SQLite 事务在创建上传会话时预占声明大小。多个并发会话不能共同超过托管空间配额或系统临时文件预算；外部挂载不维护应用级用户配额，但仍检查 NAS 可用容量和磁盘安全水位。
- 每个分片限制大小、序号和总量；写入采用流式处理，内存不得随文件大小线性增长。累计字节超过声明大小立即终止。
- 上传会话有短期有效期。完成、取消、超时和异常恢复任务会释放配额并清理临时文件；清理必须幂等。
- 提交前重新检查账号、凭证、ACL、挂载模式、目标状态、配额和磁盘安全水位。只有落盘成功后才把预占转为实际占用。
- 磁盘低于安全水位时停止新上传、复制和缩略图生成，但保留下载、回收站清理和管理员恢复入口。
- Omnora 不解压上传包、不执行上传文件，也不声明恶意软件扫描能力。

## 12. 备份、恢复与凭证代际

### 12.1 一致性备份

- SQLite 使用 Online Backup API、停机快照或经验证的等价方式生成一致副本；仅执行 WAL checkpoint 后复制单个数据库文件不视为完整方案。
- 备份包含 SQLite、一致时点的托管挂载、配置和恢复所需密钥。备份文件本身应由部署者加密并限制权限。
- 外部挂载只记录配置和业务元数据，不复制内容。备份文档必须明确该限制。

### 12.2 恢复隔离

恢复后的服务先进入仅本地可访问的恢复模式，完成以下步骤前不得经普通 Web、分享、REST 或 MCP 提供服务：

1. 校验 SQLite 完整性、迁移版本、托管挂载与数据库一致性。
2. 为本次实例生成新的凭证代际。
3. 删除所有浏览器会话和派生分享会话，撤销所有 PAT/AI Token、公开分享、下载票据和上传会话。
4. 将管理员标记为需要重新设置密码并重新登记 TOTP；其他账号至少标记为需要在首次登录时重设密码，防止旧快照中的密码重新生效而不被察觉。
5. 外部挂载保持禁用，直到管理员重新验证容器路径、文件系统身份和读写模式。
6. 写入恢复事件并由管理员明确结束恢复模式。

首版选择“恢复后全部撤销外部 Bearer 能力”，不尝试跨备份保留 Token 和分享链接。这增加恢复后的重新配置成本，但避免已撤销凭证因恢复旧快照而复活。

### 12.3 管理员账号锁定恢复

账号锁定恢复要求宿主机本地访问和一次性恢复材料。恢复材料短期有效、权限受限、使用后删除或失效。恢复操作轮换管理员会话代际，使旧会话失效，撤销该管理员的 PAT/AI Token 和活动分享，强制设置新密码并重新登记 TOTP，不重新开放网络初始化入口。

若 SQLite 可写，恢复事件写入应用审计；数据库不可用时写入权限受限的本地恢复日志，并在数据库修复后导入或关联。文档只能承诺应用层无法删除该记录，不能声称宿主机管理员无法篡改。

## 13. 审计与日志

### 13.1 审计范围

高优先级审计至少包括：

- 初始化、登录成功/失败、TOTP 和密码变更、会话撤销、账号锁定恢复。
- 个人空间应急授权的创建、使用、到期和撤销。
- 用户状态、角色、空间 ACL、挂载配置和挂载读写模式变更。
- Token、分享及其密码/能力/限制的创建、使用、变更、过期和撤销。
- 文件上传提交、覆盖、移动、删除、恢复和回收站清理。
- REST/MCP 的内容读取、短期下载地址和上传会话操作。
- 备份恢复、凭证代际变化、数据库迁移及关键安全配置变化。

### 13.2 记录内容与脱敏

审计记录操作者类型与 ID、凭证标识、目标对象 ID、动作、结果、来源 IP、时间、请求 ID 和必要的失败分类。不得记录密码、TOTP 密钥、明文 Token、分享秘密、Authorization、Cookie、文件正文或完整敏感查询参数。

文件系统错误对用户返回通用信息；宿主绝对路径、数据库语句、堆栈和密钥位置只能进入受限诊断日志，并继续脱敏。

### 13.3 保留、容量与可信度

- 审计按可配置保留期和磁盘上限清理，清理策略本身要审计。来源 IP 属于敏感数据，应限制访问和保留时间。
- ACL、Token、分享、永久删除和恢复等高风险写操作若无法写入审计，应失败关闭。普通读取可继续，但必须产生显著健康告警，避免磁盘故障扩大为全站不可用。
- 应用不提供修改既有审计事件的接口。管理员可导出审计；导出操作也要记录。
- 审计不是对宿主机 root 的防篡改证明。需要更高保证时由部署者把日志转发到独立只写或远端系统，首版不强制部署该组件。

## 14. 防护验收

首版发布前至少通过以下自动化或可重复手工测试。

### 14.1 身份与授权

- 两个并发初始化请求只能有一个成功；完成后初始化入口不能通过网络重新开启。
- 密码、TOTP 和分享密码验证受到主体/IP 双维度限速，错误响应不形成账号或分享枚举。
- 账号禁用、ACL 降级、会话/Token 撤销后，下一次 Web、REST、MCP、Range、上传分片和下载票据请求均被拒绝。
- 同一身份、对象和操作通过 Web、REST 与 MCP 得到一致授权结果。
- 无个人空间 ACL 的管理员无法浏览或搜索内容；管理员账号锁定恢复不得授予个人空间内容权限。
- AI Token 无法删除、覆盖、分享、访问回收站或越过其目录边界。

### 14.2 分享

- 带密码、无密码、过期、撤销、能力变更和创建者失权场景均正确失效。
- 在剩余次数为一时发起并发请求，最多一个成功；Range 请求不能重复消耗或绕过下载次数。
- 分享会话和下载票据不能改换目标对象，并在分享撤销或代际变化后失效。
- 通过 URL 路径、查询参数或 `Referer` 提交分享秘密的换票请求被拒绝；合法流程仅接受 fragment 读取后经 `POST` 请求体提交的秘密，成功后前端清理地址栏 fragment。
- 分享秘密、密码和下载票据不出现在应用日志、默认代理日志、Referer、错误响应或审计中。

### 14.3 文件与内容

- 个人空间 `manager` 通过 Web、REST 或 MCP 新增、修改、停用或删除挂载均被拒绝；系统管理员配置挂载后仍不能读取无 ACL 的个人空间内容。
- 重叠挂载测试覆盖相同路径、双向父子路径、符号链接根和父组件、两个容器路径 bind 到同一来源、bind 来源父子关系、身份无法读取、并发注册和运行中替换 bind 来源。
- 覆盖路径穿越、绝对路径、编码变体、Unicode/大小写边界、符号链接、嵌套链接和检查后替换对象的竞态测试。
- 不支持 `openat2` 的环境使用安全的逐级文件描述符解析；禁止退化为字符串边界检查。
- 只读挂载不能通过 Web、REST、MCP、后台任务或跨挂载操作写入。
- 用户不能创建、读取、分享、覆盖或通过 AI Token 访问 `.omnora/` 保留命名空间。
- HTML、SVG、XML、伪造 MIME 和包含脚本的 Markdown 不能在应用源执行脚本、读取 Cookie 或访问父页面。
- 下载文件名中的 CR/LF、路径分隔符和控制字符不能注入响应头或改写目标路径。

### 14.4 上传、配额与资源

- 并发上传不会超卖配额；分片总量超过声明大小、会话过期和凭证撤销均停止上传并最终清理临时文件。
- 在上传提交前撤销权限、切换根为只读或替换目标对象时，提交失败且不覆盖目标。
- 大文件上传与下载使用固定缓冲，内存不随文件大小线性增长。
- 磁盘低水位停止新增占用，但管理员仍能清理回收站和执行恢复。

### 14.5 网络、恢复与审计

- Docker 端口绑定、非法 `Host`/`Origin` 和六个路由组的独立开关通过正反向测试。开启分享不能隐式开启管理端、成员 Web、REST、MCP 或 OpenAPI。
- 反向代理参考配置验证公网 `80` 仅跳转 HTTPS、`443` 终止 TLS、代理后端端口不对公网开放，并能正确传输 Range、流式响应和 MCP 长连接。
- 从旧备份恢复后，旧会话、Token、分享、下载票据和上传会话全部无效；外部挂载在重新验证前不可访问。
- SQLite 备份可通过完整性检查并完成恢复演练；只复制主数据库文件的错误流程会被测试拒绝。
- 敏感值和文件正文不进入日志；高风险操作在审计不可写时失败关闭；宿主机可篡改边界在管理员文档中明确说明。

## 15. 实施约束

安全关键逻辑必须集中在可复用的 Identity、Access Policy、Storage Resolver、Share 和 Audit 模块中。Web、REST、MCP、后台任务不得各自实现一套简化判断。权限、路径、次数和配额的关键状态变更使用 SQLite 原子事务；跨文件系统操作无法原子化时，必须保留明确的中间状态和补救路径。

任何为了兼容 NAS 而采取的降级都必须失败安全：可以关闭某项能力或提示不支持，但不能退化为不校验路径、忽略撤销、明文传输公网凭证或绕过只读边界。
