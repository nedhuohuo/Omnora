# 挂载插槽（slot1–slot9）

状态：现行注册规则

Omnora 的外部挂载采用预制插槽布局：容器内预留 `/mnt/omnora/slot1` … `/mnt/omnora/slot9`，部署者可以把不同 NAS 文件夹逐个 bind mount 到这些位置。插槽只解决“容器能访问哪些宿主目录”，不负责权限分组或创建业务子目录。

`/srv/omnora/managed` 不属于插槽：它固定承载唯一 `personal_default` 挂载、各账号隔离个人目录和个人回收站，必须持久化、备份，并禁止通过共用挂载注册接口选择。`slot1`–`slot9` 只承载外部共用挂载。

> 2026-08-08 已确认采用账号—挂载模型。注册挂载时，管理员选中的目录本身就是挂载根，系统不会创建隐式业务子目录。

## 设计思路

| 问题 | 插槽方案的回答 |
| --- | --- |
| 容器如何访问 NAS 目录 | 部署时把 NAS 文件夹逐个 bind mount 到固定插槽 |
| 应用如何判断插槽可用 | 读取 `/proc/self/mountinfo`；插槽是独立挂载点才显示，读取失败则 fail-closed |
| 注册后真实根在哪里 | 所选插槽或更深层目录本身就是挂载根 |
| 如何隔离账号 | 由该共用挂载的独立 `viewer/editor` 授权实现，不靠物理目录层级 |
| 未配置目录如何避免暴露 | 未绑定插槽不进入建议列表；绑定的空目录可以注册 |

关键不变量：

1. **一对一映射**：每条 Compose volume 都是一个宿主目录到一个容器插槽的独立映射。
2. **整根映射与插槽检测互斥**：保留 `./mounts:/mnt/omnora:rw` 时，slot 不再是独立挂载点，不会被判定为已绑定。
3. **精确目录注册**：选中 `/mnt/omnora/slot1` 就注册该目录；选中 `/mnt/omnora/slot1/photos` 就注册 `photos`。不自动创建任何业务子目录。
4. **挂载路径不得重叠**：同一路径、父子路径、符号链接别名、bind alias 和 bind 来源父子关系都拒绝，不能把 slot 根和它的子目录同时注册成两个挂载。
5. **授权不改变文件系统**：共用挂载可以零授权，也可以独立授予多个账号；授权变更不移动或复制真实文件。

## 配置方式

在 Compose 的 `volumes` 中为每个 NAS 文件夹单独映射，未使用的插槽整行不写：

```yaml
volumes:
  - /volume1/photo:/mnt/omnora/slot1:rw
  - /volume1/music:/mnt/omnora/slot2:rw
  # slot3 ~ slot9 按需添加
```

不要同时保留 `- ./mounts:/mnt/omnora:rw`。宿主源路径可以直接写死，也可以用带必填校验的变量：

```yaml
volumes:
  - ${MOUNT_1:?set MOUNT_1 to the host folder for slot1}:/mnt/omnora/slot1:rw
```

## 注册挂载

映射完成并重建容器后，由管理员在“挂载管理”注册：

1. 选择“外部目录”。
2. 从已绑定插槽或其允许的更深层目录中选择精确目录。
3. 设置显示名称、只读/读写、是否索引，以及普通/受限治理类型；受限选项仅初始管理员可见。
4. 可选设置账号 `viewer/editor`；允许暂时不授权任何账号。
5. 服务端验证路径、身份、重叠和实际写能力后，直接把所选目录登记为挂载根。

显示名称规范化后在所有活跃挂载中全局唯一且忽略大小写。普通挂载由全部管理员治理；受限挂载只有初始管理员能够发现和治理，治理类型创建后不能切换。无论哪一种，管理员没有内容授权时都不能浏览文件。MCP 不提供挂载注册工具。

## 使用边界

- **软链接无效**：文件操作默认不跟随符号链接，不能用软链接把插槽指向其他目录。
- **换源即身份漂移**：更换 slot 的宿主源后，原挂载进入 `unavailable`，需要有治理权限的管理员 reverify。
- **写权限取交集**：`Docker 卷模式 ∩ Omnora 挂载模式 ∩ 账号内容权限`。任一只读都不能写。
- **数量不是业务上限**：九个插槽只是默认部署模板；需要更多独立 NAS 根时，应显式扩展 Compose 映射并同步 allowlist。
- **解除不删文件**：解除要求精确输入当前显示名称，只移除 Omnora 注册和派生授权，必须保留 NAS 真实目录和文件。同一路径可以用新的挂载 ID 重新注册，旧授权不恢复。

## 排查清单

| 现象 | 原因与处理 |
| --- | --- |
| 管理端看不到某个插槽 | 未绑定，或保留了整根 `/mnt/omnora` 映射导致 slot 不是独立挂载点 |
| 插槽内容不对 | 核对宿主源与 Compose；换过源时执行 reverify |
| 返回 `mount_conflict` | 目标与已注册挂载相同、父子重叠或指向同一 bind 来源 |
| 返回 `mount_not_writable` | Docker、宿主目录或 Omnora 模式没有提供写能力 |
| 成员端看不到挂载 | 账号没有该挂载的 `viewer/editor`；零授权挂载只在有权管理的控制面存在 |
