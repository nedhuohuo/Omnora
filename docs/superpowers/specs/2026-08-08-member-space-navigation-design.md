# 成员空间目录导航设计

状态：已被取代

> 本文的“个人空间 / 团队空间”导航已被[账号、挂载与内容授权设计](2026-08-08-account-mount-access-design.md)中的成员端方案 A 取代，不得再作为实施依据。

## 目标

成员文件区不再以笼统的“文件”作为入口。左侧纵向导航直接提供“个人空间”和“团队空间”两个入口；点击入口后，内容区先以文件夹形式展示当前成员拥有或可访问的空间，再由成员进入具体空间浏览文件。

## 导航结构

成员端左侧主导航按以下顺序展示：

1. 个人空间
2. 团队空间
3. 回收站（仅在已经进入支持回收站的存储位置时显示）
4. 分享
5. AI Token
6. 文档
7. 账户

原“文件”Tab 移除。“个人空间”和“团队空间”是文件浏览的两个入口，不额外保留“文件”父级或空间子导航。

## 浏览层级

文件浏览采用三个明确层级：

1. 空间分类：个人空间或团队空间。
2. 空间目录：内容区展示当前分类下可访问的空间。
3. 空间内容：进入具体空间后，沿用现有挂载、目录、搜索、上传、预览和文件操作能力。

分类规则使用服务端已经返回的空间类型：

- `personal` 对应“个人空间”。
- `shared` 对应“团队空间”。

不得根据空间名称、角色或内部 ID 推断类型。

## 空间目录视图

点击“个人空间”或“团队空间”后，内容区展示对应类型的空间卡片。每个卡片采用文件夹视觉，展示：

- 空间名称；
- 当前成员在该空间中的可读权限名称；
- 文件夹图标或等价的目录视觉。

界面不展示 `spc_` 等内部 ID。点击空间卡片后进入该空间，并按现有逻辑选择可用存储位置和加载根目录。

若分类下没有空间，内容区分别展示“暂无个人空间”或“暂无团队空间”，空间 Tab 仍保持可见和可切换。

## 状态与返回行为

成员点击任一空间分类 Tab 时：

- 激活对应纵向 Tab；
- 返回该分类的空间目录视图；
- 清空当前文件搜索结果、路径、挂载选择、文件列表、回收站列表和页面错误；
- 不自动进入该分类的第一个空间。

进入空间后，面包屑显示：

`空间分类 / 空间名称 / 当前目录`

点击面包屑中的空间分类返回对应空间目录；点击空间名称返回该空间根目录；其余路径层级沿用现有目录导航行为。

切换空间分类或返回空间目录后，回收站入口隐藏。只有进入具体空间且当前挂载支持 Omnora 回收站时，才显示回收站入口。

## 现有能力保持

进入具体空间后，以下能力保持现有行为和权限判断：

- 存储位置加载与切换；
- 搜索、上传、新建文件夹；
- 列表与网格视图；
- 预览、下载、移动、复制、改名和删除；
- 分享与回收站；
- 只读、挂载不可用和空间角色限制。

空间目录仅负责选择空间，不伪装成后端文件条目，也不调用文件目录接口。

## 状态模型

前端增加空间分类状态 `personal | shared`，并允许在分类目录视图下没有活动空间。现有 `activeSpaceId` 仅在成员进入空间后赋值。

空间目录视图从已加载的 `spaces` 按 `space.type` 派生，不复制或改写接口返回数据。管理员入口不受影响。

## 错误处理

- 空间列表加载失败时沿用现有全局错误提示。
- 进入空间后挂载或目录加载失败时沿用现有错误状态，同时保留面包屑返回空间目录的能力。
- 未知空间类型不显示在个人或团队目录中，也不把它静默归入任一分类。

## 验证

自动化测试至少覆盖：

1. `personal` 与 `shared` 空间被正确分组。
2. 两个纵向 Tab 存在且原“文件”Tab 不再渲染。
3. 点击空间 Tab 展示对应空间卡片，而不是自动进入第一个空间。
4. 点击空间卡片进入现有文件浏览流程。
5. 面包屑可以从空间内容返回空间目录。
6. 空分类展示对应空状态。
7. 切换分类清理上一个空间的路径、搜索、挂载和回收站状态。
8. 管理端导航和现有文件操作测试不回归。

前端验证执行聚焦测试、完整 Vitest 测试和生产构建。若浏览器环境可用，再用成员账号人工验证个人空间、团队空间、进入空间和面包屑返回的完整交互。
