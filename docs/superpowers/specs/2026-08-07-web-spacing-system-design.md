# Omnora Web 全站间距系统设计

日期：2026-08-07
状态：设计已确认，待规格文档复核
适用范围：`web/src/` 全部前端，包括成员端、管理端、登录态、公开分享页

## 1. 背景与目标

Omnora 当前已经定义了 4px 基础间距阶梯，但页面布局仍混用基础令牌、局部硬编码值和组件内部尺寸。尤其是页面标题区没有统一的下方间距，导致副标题、操作按钮、表格和空状态之间的节奏不稳定。

本设计的目标是建立一套中等密度的全站间距系统：

- 页面外边距、区块间距、组件内边距、元素组间距分别有明确职责。
- 页面标题区、工具栏、表格、卡片、表单、弹窗和公开分享页使用同一套语义规则。
- 控件高度与页面间距分离，避免用 `34px`、`37px`、`39px` 等局部值修视觉问题。
- 保留文件管理工作台的效率，但增加可读的留白和稳定的视觉层级。
- 为后续静态检查建立允许例外清单。

不在本设计范围内：重新设计颜色、字体、图标、业务流程、API、路由和组件功能。

## 2. 设计决策

### 2.1 采用语义化间距层

保留现有 4px 基础阶梯，并增加语义别名。页面和组件优先使用语义令牌，只有令牌定义本身使用基础值。

```css
/* 基础阶梯 */
--space-1: 4px;
--space-2: 8px;
--space-3: 12px;
--space-4: 16px;
--space-5: 20px;
--space-6: 24px;
--space-7: 32px;
--space-8: 40px;

/* 页面与组件语义层 */
--layout-page-inline: var(--space-7);
--layout-page-block-start: var(--space-6);
--layout-section: var(--space-6);
--layout-section-compact: var(--space-5);
--layout-component: var(--space-4);
--layout-group: var(--space-3);
--layout-inline: var(--space-2);
--layout-micro: var(--space-1);
```

语义含义固定如下：

| 层级 | 值 | 使用场景 |
| --- | ---: | --- |
| 微距 | 4px | 图标与文字、状态点与标签 |
| 紧凑组 | 8px | 表单 label、按钮组、导航项内部 |
| 常规组 | 12px | 面包屑、表格局部内容、提示条之间 |
| 组件内 | 16px | 工具栏到主体、组件内部区块 |
| 区块间 | 20px | 标题区到第一块主体内容 |
| 页面内 | 24px | 页面顶部、卡片内边距、独立区块 |
| 页面外框 | 32px | 桌面页面左右边缘 |
| 大阶段 | 40px | 分享页等需要更强呼吸感的主体顶部 |

核心层级关系：

```text
页面外框 > 页面内 > 区块间 > 组件内 > 常规组 > 紧凑组 > 微距
32/24px > 20/16px > 12/8px > 4px
```

### 2.2 控件几何独立管理

控件高度不是页面间距，不直接使用 `--space-*` 表达。

```css
--control-xs: 28px;
--control-sm: 32px;
--control-md: 36px;
--control-lg: 40px;
--table-header-height: 40px;
--table-row-min-height: 52px;
--shell-topbar-height: 64px;
--layout-content-bottom-reserve: 112px;
```

约定：

- 紧凑操作、徽标操作使用 `--control-xs`。
- 管理子导航、紧凑次级操作使用 `--control-sm`。
- 默认按钮、普通工具栏操作使用 `--control-md`。
- 表单控件、主按钮、登录操作使用 `--control-lg`。
- 表头统一 40px，普通数据行最低 52px；内容较多的行允许由内容撑开。
- `--shell-topbar-height` 是桌面成员端和公开分享页的 64px 顶栏基线；成员端窄屏搜索框换行时允许顶栏自然增高，内部行间距仍遵守 8px。
- 底部预留空间是固定传输浮层的布局保留值，使用专用语义令牌，不计入普通间距阶梯。

## 3. 页面层级与纵向节奏

### 3.1 成员端与管理端

页面内容统一按以下顺序建立间距：

```text
页面壳 / 管理子导航 → 页面内容：24px
面包屑 → 页面标题：12px
标题 → 副标题：8px
标题区 → 第一块主体内容：20px
工具栏按钮之间：8px
工具栏 → 文件表格、网格或空状态：16px
卡片内部：24px
卡片内字段组：16px
字段标签 → 控件：8px
同类提示条之间：12px
独立区块之间：24px
```

`.member-heading` 的行为必须统一：

- 操作区与标题行顶部对齐，不再使用 `align-items: end` 让按钮跟副标题底部对齐。
- 标题使用 `margin: 0`，副标题距离标题 8px。
- 标题区拥有统一 20px 下方间距。
- 空状态、表格、表单不再通过偶然的上边距补偿标题区。

文件页额外规则：

```text
面包屑 → 标题：12px
标题区 → 工具栏：20px
工具栏按钮之间：8px
工具栏 → 文件内容：16px
```

管理页额外规则：

```text
标题区 → 表格或空状态：20px
标题区 → 表单卡片：20px
表单卡片 → 后续表格或结果：24px
表格单元格水平内边距：12px
```

账户页保留 24px 区块间距。文档页的 Markdown 正文、代码块和内容表格可以有独立内容节奏，但文档页外层仍遵守统一标题区规则。

### 3.2 登录页与无权限页

- 登录面板使用 24px 内边距和 16px 内部区块间距。
- 登录标题不使用负 margin，通过父级 gap 建立节奏。
- 无权限页使用专用居中布局，不使用 `90px auto` 作为普通页面 margin。

### 3.3 公开分享页

公开分享页只共享全局令牌，不依赖成员端局部选择器。

- 桌面顶栏高度统一为 64px；成员端窄屏因搜索框换行允许自然增高。
- 桌面主体左右 32px、顶部 40px；40px 作为大阶段留白特例。
- 分享面板内边距 24px。
- 表单字段间距 8px。
- 文件操作与 Markdown 预览间距 16px。

## 4. 响应式规则

| 视口 | 页面左右内边距 | 页面顶部内边距 |
| --- | ---: | ---: |
| `> 900px` | 32px | 24px |
| `561–900px` | 24px | 20px |
| `≤ 560px` | 16px | 20px |

其他约定：

- 移动端可点击控件不低于 40px，关键操作不低于 44px。
- 侧栏转为横向导航时，导航项之间仍保持 8px；页面内容与导航区之间保持 20px。
- 标题区在窄屏下允许纵向排列，但标题、副标题和操作区仍遵守 8/20px 节奏。
- 表格在窄屏下可隐藏次要列或滚动，但不得通过压缩核心操作区间距解决溢出。

## 5. 允许的物理值例外

以下值可以保留，但必须属于明确的组件几何或内容排版用途：

- 边框 `1px`。
- 图标、状态点、文件徽标等固定几何尺寸。
- 控件高度、表格行高、顶栏高度、侧栏宽度、弹层宽度。
- 控件水平内边距，通过控件令牌统一管理。
- viewport 相关的 `calc()`、百分比、`auto`、`min()`、`max()`。
- Markdown 引用线、代码块、内容表格等内容型组件的局部排版值。

以下值不应再用于页面级布局：

- `margin: 4px 0 -12px` 等负 margin。
- `90px auto` 等无法表达语义的页面 margin。
- `2px`、`3px`、`6px`、`9px`、`11px` 等局部布局间距。
- 通过 `34px`、`37px`、`39px` 等控件高度修正页面对齐。

## 6. 实施边界

实施时只修改与间距系统直接相关的：

- `web/src/styles.css`：新增语义令牌、控件几何令牌和全局基础约束。
- `web/src/member/member-files.css`：迁移成员端、管理端、登录态、弹层和内容组件的间距使用。
- `web/src/share-portal.css`：迁移公开分享页，并保持选择器独立。
- 必要的 TSX：仅为建立稳定的页面标题/内容容器或消除不安全的宽泛选择器增加语义 class，不改变业务行为。
- `docs/design/ui-design-system.md`：同步最终生效规则，保持它作为全站视觉唯一权威。

不修改：API、业务状态、路由、权限逻辑、用户数据、部署配置，以及工作区中原有的 README/部署文档改动。

## 7. 验收标准

### 静态验收

- 页面级 margin/padding/gap 全部使用语义令牌。
- 非令牌物理值只出现在允许例外清单中。
- 不再存在标题区负 margin、页面 `90px` margin、标题区缺失下方节奏的问题。
- 成员端和分享端顶栏高度、页面边缘、卡片内边距符合规则。

### 工程验收

- `cd web && npm test -- --run`
- `cd web && npm run build`
- `git diff --check`

### 页面验收

至少检查以下页面和状态：

- 文件列表、网格、空文件夹、回收站。
- 分享、AI Token、文档、账户。
- 管理概览、用户、空间、挂载、索引、路由组、分享治理、Token 治理、备份、审计。
- 登录、无权限、公开分享密码页、公开分享浏览页、Markdown 预览。
- 桌面、平板、手机三档视口下的标题区、工具栏、表格、空状态、表单和弹窗。

目标不是让所有页面使用同一个间距，而是让每个层级使用正确且可解释的间距。
