# Omnora / 万境设计规格

日期：2026-08-02  
状态：已确认，待实施计划

## 1. 产品定义

Omnora（万境）是一个可持续扩展的自托管数字空间。第一版面向个人、家庭和小团队，聚焦 NAS 文件管理、安全分享、浏览器预览和受控 AI 访问。系统优先保证极空间 NAS 上的低资源运行，同时通过标准 Docker Compose 兼容其他支持容器的 NAS 和普通 Linux 主机。

系统支持局域网访问、成员账号访问和受控的公网分享，并向 AI 客户端提供 REST/OpenAPI 与 MCP 接口。所有入口共用同一套身份、授权和审计逻辑。

首版目标数据规模为 1 至 20 TB、约 100 万个文件。系统不承诺跨节点横向扩展。

## 2. 设计原则

1. 文件系统是文件内容的真实来源，数据库只保存业务数据和文件索引。
2. Web、REST、MCP 和分享访问必须经过同一套对象级授权。
3. 外部 NAS 目录默认只读，并同时使用容器挂载权限和应用权限保护。
4. 首版优先低 CPU、低内存和低磁盘放大，不执行非必要的内容处理。
5. 后台任务必须可限速、暂停、重试和断点恢复，不能阻塞交互请求。
6. 对公网和 AI 的能力默认最小授权，并且可过期、可撤销、可审计。
7. 第一版保持单进程和单容器部署；只有实际负载证明必要时才拆分外部服务。

## 3. 用户与角色

### 3.1 系统角色

- 管理员：管理成员、存储空间、挂载目录、系统策略、配额、分享、AI 凭证和审计。
- 成员：管理个人空间及获得授权的目录，执行允许的文件操作和分享操作。
- 匿名访客：通过受控分享链接预览或下载文件，不需要注册账号。

AI 客户端不是独立用户角色。它使用绑定成员或服务账号的专用 Token，且权限不得超过 Token 明确授权的目录和操作范围。

### 3.2 空间权限

- `viewer`：浏览、搜索、预览和下载。
- `editor`：包含 `viewer` 权限，并允许上传、复制、移动、改名和删除。
- `manager`：包含 `editor` 权限，并允许管理空间成员和创建分享。

只有管理员可以创建和配置存储挂载、管理系统级策略以及查看全局审计。

## 4. 首版范围

### 4.1 文件管理

- 目录浏览与基于元数据的搜索。
- 文件和目录上传。
- 大文件分片上传与断点续传。
- 支持 HTTP Range、ETag 和条件请求的下载。
- 新建目录、复制、移动、改名、批量操作、删除与回收站恢复。
- 成员个人空间、共享空间和空间配额。
- 托管空间与 NAS 既有目录挂载。
- 挂载目录后台初始扫描、增量更新和定期对账。

搜索范围包括文件名、扩展名、类型、大小、修改时间和所属目录。首版不搜索文件正文。

### 4.2 文件分享

- 文件和文件夹均可创建分享链接。
- 分享密码可选。
- 支持有效期、预览开关、下载开关、访问次数上限和下载次数上限。
- 分享创建者可以随时撤销链接并查看访问记录。
- 匿名访客只能在分享绑定的文件或目录子树内访问。

“允许预览但关闭下载”只表示隐藏直接下载入口，不构成无法保存内容的安全承诺。

### 4.3 文件预览

首版采用轻量预览策略，不在 NAS 上执行 Office 转换、视频转码、OCR 或内容分析。

| 文件类型 | 首版行为 | 服务端重处理 |
| --- | --- | --- |
| 图片 | 浏览器直接显示 | 无；可选低优先级缩略图 |
| PDF | 浏览器端 PDF.js 渲染 | 无 |
| 纯文本 | 限制大小后在浏览器显示 | 无 |
| Markdown | 清洗后在浏览器渲染 | 无 |
| 音频、视频 | 仅播放浏览器原生支持的编码 | 无转码 |
| Word、Excel、PowerPoint | 显示文件信息并提供下载 | 无预览、无转换 |
| 其他格式 | 显示文件信息并提供下载 | 无 |

文本和 Markdown 预览必须限制最大读取字节数。Markdown 不允许执行原始 HTML、脚本或不安全 URL。

### 4.4 AI 接入

系统提供版本化 REST API、OpenAPI 3.1 规范和 Streamable HTTP MCP 服务。

首版 MCP 工具集：

- `list_spaces`
- `list_files`
- `search_files`
- `get_file_metadata`
- `read_text_file`
- `create_download_url`
- `create_upload_session`

MCP 不直接内联返回大型二进制文件。AI Token 默认只授予列表、搜索和读取权限；上传需要独立授权。首版不向 AI 开放删除文件或创建公开分享。

## 5. 非目标

以下能力不进入第一版：

- Word、Excel、PowerPoint 在线预览或编辑。
- 服务端视频转码和多码率播放。
- OCR、文件正文索引、向量检索、RAG 和内置 AI 问答。
- 匿名上传、公开收件箱和公开可写目录。
- WebDAV、S3 或 SMB 网关。
- 跨 NAS 同步、跨节点集群和对象存储迁移。
- 多租户、组织层级和复杂审批流。
- 原生移动端、桌面同步客户端和插件市场。
- 去重、版本历史和应用层自建端到端加密。

## 6. 总体架构

默认 Compose 部署只包含一个 `omnora` 应用服务。该 Go 进程提供 Web 静态资源、认证、文件传输、分享、REST/OpenAPI、MCP 和低优先级后台任务。

SQLite 使用 WAL 模式保存账号、权限、空间、文件元数据、分享、Token、持久化任务和审计记录。数据库只允许一个受控写入队列，高并发读取使用独立只读连接；忙等待、事务时长和检查点行为必须有明确上限。

前端采用 React、TypeScript 和 Vite，构建后的静态资源嵌入 Go 可执行文件。系统不引入 PostgreSQL、Redis、OpenSearch、MinIO、LibreOffice、OnlyOffice 或 FFmpeg。

后台任务保存在 SQLite 任务表中，由进程内单并发执行器领取。进程重启后可以从检查点恢复未完成任务。未来如需拆分 Worker 或外部数据库，模块接口和数据迁移必须保持兼容，但首版不提前部署这些组件。

## 7. 模块边界

- Identity：账号、密码、TOTP、浏览器会话、个人访问令牌和服务账号。
- Access Policy：系统角色、空间 ACL、分享能力和 AI Token 的统一授权判断。
- Storage：托管空间和外部挂载的统一文件系统抽象。
- Catalog：文件元数据、目录树、扫描、对账和搜索。
- Transfer：分片上传、原子落盘、下载、Range 和短期下载地址。
- Share：分享创建、验证、访问限制、撤销和记录。
- Preview：判断浏览器可预览能力并提供受限内容；不执行重型格式转换。
- MCP Adapter：将经过授权的应用服务映射为有限 MCP 工具。
- Audit：记录安全和业务事件，并负责脱敏与保留策略。
- Jobs：持久化后台任务、重试、进度、限速和恢复。

REST、Web 和 MCP 只能通过应用服务访问 Storage，不得直接拼接宿主机路径或绕过 Access Policy。

## 8. 存储与索引

### 8.1 存储根

- Managed Root：系统管理的读写目录。上传先写临时文件，校验完成后原子移动到目标位置。
- Mounted Root：NAS 已有目录。默认使用 Docker bind mount 的 `:ro` 选项；管理员显式切换并确认后才能使用读写挂载。

API 只接收和返回内部文件 ID。内部映射使用存储根 ID 与规范化相对路径，绝不暴露宿主机绝对路径。

### 8.2 索引策略

- 默认建立全局轻量元数据索引，但管理员可以按存储根暂停或关闭索引。
- 索引只保存名称、规范化路径、类型、大小、修改时间和必要的文件系统标识，不读取文件正文。
- 初始扫描采用分页遍历、单并发、低 I/O 优先级和检查点续扫。
- 日常更新结合文件事件监听和定期全量对账，不能只依赖文件事件。
- 默认比较路径、大小、修改时间和可用的文件系统标识，不为所有文件计算内容哈希。
- 删除检测先标记缺失，完成一轮扫描后再确认，避免中断扫描导致误删索引。
- 百万级列表使用 keyset pagination，不使用深层 `OFFSET` 分页。
- 缩略图按需生成、并发为 1、可关闭，并受独立磁盘配额约束。
- SQLite 页缓存目标为 32 至 64 MB；扫描批次限制为 200 至 1000 个文件，禁止把完整目录树加载到内存。

## 9. 关键数据流

### 9.1 管理员初始化与挂载

1. 管理员在局域网中使用一次性初始化令牌创建首个账号。
2. 初始化入口永久关闭。
3. 管理员创建存储空间并配置容器内预先声明的挂载根。
4. 系统验证读写能力和边界后创建扫描任务。
5. App 的后台执行器低速建立元数据索引，界面显示进度并允许暂停。

### 9.2 文件上传

1. 客户端请求上传会话并通过对象级权限检查。
2. 数据以固定大小分片流式写入临时目录。
3. 完成后校验分片和目标状态。
4. 使用原子移动完成落盘。
5. 更新 Catalog 并记录审计事件。

上传过程的内存占用不得随文件大小线性增长。

### 9.3 分享访问

1. 成员为文件或目录创建带有限制条件的分享。
2. 系统返回只显示一次的高强度随机链接令牌。
3. 访客打开链接；若设置密码，则完成限速验证。
4. 系统创建短期分享会话，并在每次请求时校验分享状态和对象范围。
5. 预览或下载完成后更新计数并写入审计。

### 9.4 AI 访问

1. 成员创建绑定空间、目录和操作范围的 AI Token。
2. AI 通过 REST 或 MCP 发起结构化请求。
3. Identity 验证 Token，Access Policy 对目标对象执行授权。
4. 应用服务执行带有数量、字节、并发和流量限制的操作。
5. Audit 记录操作者、Token 标识、对象、动作、结果和请求 ID。

文件内容一律视为不可信数据。文件中的提示词不得扩大 Token 权限或自动触发写入、删除和分享操作。

## 10. 安全设计

### 10.1 身份认证

- 密码使用 Argon2id。
- 浏览器使用服务端可撤销的不透明会话。
- Cookie 设置 `HttpOnly`、`Secure` 和合适的 `SameSite` 属性。
- 状态变更请求启用 CSRF 防护。
- 管理员强制开启 TOTP，成员可以选择开启。
- 登录、TOTP 和分享密码验证使用按 IP 与主体分层的渐进限速。

### 10.2 Token 与分享

- API、MCP 和分享令牌使用至少 256 位安全随机值。
- 数据库只保存令牌哈希，明文只展示一次。
- 个人访问令牌包含操作 scope、目录范围、有效期、最近使用时间和撤销状态。
- 无密码分享默认 7 天过期；创建者可以调整，但所有分享必须可撤销。
- 分享页面不加载第三方脚本，并设置严格的 Referrer、缓存和内容安全策略。

### 10.3 文件系统边界

- 规范化相对路径后必须再次验证目标仍处于授权存储根内。
- 阻止 `..`、绝对路径、符号链接逃逸、挂载点越界和路径大小写混淆。
- 外部只读目录同时采用容器 `:ro` 和应用层只读策略。
- 文件类型根据实际内容和扩展名共同判断，不能只信任客户端 MIME。
- Omnora 容器使用非 root 用户和最小 Linux capabilities。

### 10.4 公网暴露

- 默认只监听局域网，不自动配置 UPnP 或开放公网端口。
- 公网访问由管理员显式启用，并必须通过极空间反向代理、Caddy 或 Nginx 提供 HTTPS。
- 仅在明确配置可信代理后接受转发来源 IP 头。
- CORS 使用显式白名单，不允许任意来源携带凭据。

## 11. 错误处理与恢复

- 后台任务记录进度、检查点、重试次数和结构化失败原因。
- 可恢复错误采用有限次数退避重试；永久错误进入失败状态并允许人工重试。
- 挂载离线、权限变化或文件系统变为只读时暂停相关写操作，保留索引并显示异常状态。
- 磁盘空间不足时拒绝新上传和缩略图任务，但保留浏览、下载和管理清理能力。
- 文件预览失败仅影响预览，不影响有权限用户下载原文件。
- 数据库迁移失败时停止启动并保留原数据，不继续带病运行。
- 文件系统和数据库状态不一致时，以文件系统为准，通过幂等对账任务修复。

## 12. 部署与资源预算

### 12.1 NAS 兼容性

- 发布 `linux/amd64` 和 `linux/arm64` 镜像。
- 极空间为第一优先验证平台，同时验证普通 Linux Docker Compose。
- 支持 `PUID`、`PGID`、`TZ` 和 `UMASK`。
- 不使用特权容器、Host 网络或 Docker Socket。
- SMB 或 NFS 由宿主机挂载，再 bind mount 到容器；容器内不执行 mount。
- SQLite 数据库和应用配置建议放在 SSD 或系统盘，文件内容可以放在机械盘。
- 默认 Compose 只运行一个应用容器，不要求单独数据库或后台 Worker。

### 12.2 8 GB RAM 目标

- Go App 与 SQLite 的空闲总内存目标为 100 至 300 MB。
- 普通浏览、搜索和传输时总内存验收目标不超过 500 MB。
- 轻量索引只使用固定批次和受限 SQLite 页缓存，内存不得随文件总数线性增长。
- 扫描任务并发固定为 1，并允许限制为最多半个 CPU 核。
- 服务端不使用 GPU，不运行 Office 转换、视频转码、OCR 或全文内容分析。

内存验收不将 Linux 可回收文件页缓存误计为应用不可释放内存。容器仍需设置合理的硬上限，以防单进程异常占满 NAS 内存。

## 13. 备份、升级与审计

备份范围包括经过一致性检查点处理的 SQLite 数据库、应用配置、密钥和托管文件目录。外部挂载只备份挂载配置和业务元数据，不重复备份其文件内容。

系统提供可执行的备份、恢复和版本升级文档。发布前必须完成一次恢复演练。版本启动时先检查数据库迁移兼容性，不允许静默跨越多个不受支持的大版本。

审计事件至少包括：

- 登录、登录失败、TOTP 变更和会话撤销。
- 用户、空间权限和挂载配置变更。
- 文件上传、移动、改名、删除和恢复。
- 分享创建、验证、访问、下载和撤销。
- API/MCP Token 创建、使用、过期和撤销。
- REST 与 MCP 的敏感读取和写入操作。

审计记录包含操作者、对象 ID、动作、结果、来源 IP、时间和请求 ID，不记录密码、明文 Token、分享密钥或文件正文。

## 14. 测试与验收

### 14.1 功能测试

- 覆盖管理员初始化、成员管理、存储挂载和空间权限。
- 覆盖上传续传、Range 下载、文件管理和回收站恢复。
- 覆盖带密码和无密码分享、过期、次数限制和撤销。
- 覆盖所有首版预览类型，并确认 Office 文件始终走下载逻辑。
- 对同一身份和文件验证 Web、REST 与 MCP 的权限结果一致。

### 14.2 安全测试

- 验证跨空间、跨目录和跨角色越权访问被拒绝。
- 验证路径穿越、符号链接逃逸、伪造 MIME 和失效 Token 被拒绝。
- 验证只读挂载无法通过任何入口修改。
- 验证登录、分享密码和 API/MCP 限速。
- 扫描日志，确认敏感值和文件正文未被记录。

### 14.3 性能与资源测试

- 在极空间 8 GB RAM 设备上完成实际部署和资源测量。
- 验证空闲内存处于 100 至 300 MB 目标范围，普通操作不超过 500 MB。
- 使用百万级合成元数据验证 keyset 分页和文件名搜索。
- 验证扫描任务可暂停、续跑和限速，且不明显影响 NAS 正常文件访问。
- 验证大文件上传和下载采用流式处理，内存不会随文件大小线性增长。
- 验证 SQLite WAL 检查点、并发读取、受控单写入和数据库忙状态不会长时间阻塞请求。

### 14.4 可靠性测试

- 在扫描、上传和索引更新期间重启 Omnora，验证任务恢复和状态一致性。
- 模拟挂载离线、权限变化、磁盘不足和文件被外部移动或删除。
- 验证定期对账可以修复索引漂移而不误删有效记录。
- 完成 SQLite、配置和托管文件的备份恢复演练。
- 完成 `amd64` 与 `arm64` 镜像构建，以及极空间和普通 Linux Compose 部署验证。

## 15. 首版成功标准

1. 家庭或小团队能够在极空间 NAS 上通过 Docker Compose 完成部署和初始化。
2. 百万文件规模下，目录浏览、文件名搜索和后台扫描不会相互阻塞。
3. 成员和匿名访客只能访问明确授权的文件范围。
4. REST 与 MCP 能被 AI 客户端稳定使用，且权限、限额和审计完整。
5. 系统以单应用容器满足 8 GB RAM NAS 的资源目标，不依赖 GPU、外部数据库或重型内容处理服务。
6. 分享、Token、挂载和恢复流程具备清晰的管理员操作路径。

## 16. 许可与贡献模型

Omnora 采用双重许可：
