# 账号级团队空间设计

## 1. 目标

成员端功能归属于账号，空间只负责限定文件内容和权限范围。本次调整完成以下事项：

1. 允许任意有效登录账号创建团队空间；创建者自动成为空间 `manager`。
2. 创建团队空间时自动建立系统托管目录和默认读写挂载，避免产生没有文件内容入口的空壳空间。
3. 空间 `manager` 可以添加、移除成员并设置 `viewer`、`editor`、`manager` 权限。
4. 将成员端“与我共享”区域改为账号级“团队空间”管理区域。
5. 明确 `space_grant + editor + shares:create` 可以通过 MCP 创建公开分享。
6. 两个 P2 问题只登记到问题文档，本次不修改其实现。

## 2. 信息架构

成员端左侧保持原有的单一连续导航样式，不再把空间选择与账号功能渲染成上下分隔的两个导航块。

- “个人空间”和“团队空间”用于选择文件内容范围。
- “文件”“回收站”“分享”“AI Token”“文档”“账户”是账号功能。
- 两个空间范围入口与六个账号功能入口位于同一个连续导航容器，间距和 Tab 样式一致；允许空间范围与当前账号功能各自保留选中态，但不得渲染成上下两个分组。
- 左侧不逐个列出具体空间。进入“个人空间”或“团队空间”后，内容区第一层把该范围内的空间显示成文件夹；点击空间文件夹后再进入其挂载和目录内容。
- 切换空间只改变文件、搜索、挂载和回收站的内容上下文，不改变账号功能的数据归属。
- “分享”页面同时展示账号可管理的公开分享和团队空间，不依赖文件页当前选中的空间。

## 3. 团队空间创建

### 3.1 创建资格

- 任意状态为 `active` 的登录账号均可创建团队空间。
- 创建者写入 `spaces.owner_account_id`，同时写入 `space_members`，权限固定为 `manager`。
- 系统管理员仍可通过现有管理员接口执行全局治理；成员端接口不以系统管理员身份替代空间 manager 身份。

### 3.2 托管目录和默认挂载

团队空间使用 `OMNORA_MANAGED_STORAGE_DIR`，默认根为 `/srv/omnora/managed`。

每个空间创建独立目录：

```text
<managed-root>/team-spaces/<space-id>
```

同时注册一个默认挂载：

- `kind = managed`
- `mode = read_write`
- `status = active`
- 显示名称为 `Team files`
- 挂载身份由服务器创建目录后即时采集

目录路径只使用服务器生成的空间 ID，不接受客户端传入宿主机路径。服务端必须校验最终路径是托管根的严格后代。

创建顺序为：生成 ID、创建专用空目录、采集身份、开启数据库事务、写入空间/manager/挂载/审计、提交事务。数据库失败时仅尝试用非递归删除移除本次新建且仍为空的目录；不得删除非空目录或托管根。

## 4. 成员管理权限

成员端新增团队空间接口：

```text
POST   /api/v1/team-spaces
GET    /api/v1/team-spaces/{spaceId}/members
PUT    /api/v1/team-spaces/{spaceId}/members/{accountRef}
DELETE /api/v1/team-spaces/{spaceId}/members/{accountRef}
```

PUT/DELETE 复用同一个成员详情 path；DELETE 调用方传入成员列表返回的规范账号 ID。

规则：

- 所有接口要求有效浏览器会话；修改接口必须通过现有 CSRF 防护。
- 成员列表及修改操作只允许目标共享空间的当前 `manager`。
- `accountRef` 支持账号 ID 或大小写不敏感的邮箱，并且只能解析状态为 `active` 的账号。
- 权限只允许 `viewer`、`editor`、`manager`。
- 添加成员默认选择 `viewer`。
- 禁止删除或降级空间中的最后一个 manager。
- manager 可以修改自己的权限，但如果自己是最后一个 manager，降级或移除必须返回 `409 last_manager_required`。
- 个人空间不允许通过团队空间接口管理成员，返回 `409 personal_space_protected`。
- 所有成功修改写入审计日志，日志只记录账号 ID、空间 ID 和权限，不记录文件系统绝对路径。

现有 `/api/v1/admin/spaces/...` 接口继续保留给系统管理员，不改变其治理语义。

## 5. 公开分享授权

公开分享按调用身份区分：

- 浏览器会话：仍要求账号在目标空间具有 `manager` 权限。
- `space_grant` AI Token：当 Token 具有 `shares:create` scope、目标空间授权为 `editor`，并且账号实时 ACL 至少为 `editor` 时，可以创建公开分享。
- `viewer` Token、只读挂载、黑名单路径、失效账号或已撤销空间权限必须拒绝。
- 分享创建继续执行 MRTR、高风险确认、挂载身份和路径安全检查。

该例外必须同步写入领域模型、MCP 文档和安全模型，避免再使用笼统的“只有 manager 可以创建公开分享”描述。

## 6. 成员端交互

“分享”页面保留“公开分享”区域，并将原来的“与我共享”替换为“团队空间”。

团队空间区域包括：

- 账号可访问的全部 `shared` 空间列表。
- “创建团队空间”按钮和名称输入弹窗。
- 每个空间展示当前账号角色；成员身份信息只在 manager 打开成员管理后加载。
- “打开文件”操作：切换到文件 Tab，并把该空间设为当前文件上下文。
- manager 额外显示“管理成员”：可按邮箱或账号 ID 添加成员，默认仅查看；可修改角色或移除成员。
- viewer/editor 只能查看空间信息和打开文件，不显示成员管理操作。
- 创建成功后立即刷新账号空间列表，并允许直接进入新空间。

生产文件页与预览页遵循同一层级：空间范围 Tab → 内容区空间文件夹 → 空间内挂载和目录。具体空间名称不占用左侧主导航。

预览页左侧导航必须使用同一个连续导航容器和一致的 Tab 间距，不再显示空间区与账号功能区之间的大块视觉断层。

## 7. 数据与错误处理

不新增数据库表，复用 `spaces`、`space_members`、`mounts` 和 `audit_events`。

新增或明确以下错误码：

- `invalid_input`：空间名、成员引用或权限不合法。
- `forbidden`：当前账号不是目标空间 manager。
- `not_found`：空间、成员关系或目标账号不存在。
- `personal_space_protected`：尝试通过团队接口操作个人空间。
- `last_manager_required`：操作会导致空间没有 manager。
- `managed_storage_unavailable`：托管根不安全、不可写或目录身份无法采集。

空间名称沿用现有规则：去除首尾空白、不能为空、最多 128 个 Unicode 字符、禁止控制字符。

## 8. 延期 P2

本次只在 `docs/design/account-space-known-issues.md` 登记以下问题，不修改实现：

1. 切换到不支持回收站的挂载时，当前 `trash` 状态被保留但导航入口被隐藏，造成导航和内容状态不一致。
2. AI Token 创建/编辑流程在验证账号空间 ACL 之前采集黑名单目录指纹，应调整为先授权、后访问文件系统。

## 9. 测试与验收

后端测试必须覆盖：

- 普通 active 成员创建团队空间成功，成为 manager，并获得可用的 managed/read-write 默认挂载。
- 非登录、停用账号和不安全托管根创建失败。
- manager 可以列出、添加、修改和移除成员。
- viewer/editor 不能管理成员，其他空间的 manager 也不能跨空间操作。
- 最后一个 manager 不能被删除或降级。
- 个人空间拒绝团队成员管理。
- `space_grant + editor + shares:create` 创建公开分享成功，viewer 和黑名单路径失败。

前端测试必须覆盖：

- 分享页显示“团队空间”，不再显示“与我共享”。
- 创建团队空间默认把创建者视为 manager，并刷新列表。
- 只有 manager 显示成员管理入口，新增成员默认 `viewer`。
- “打开文件”切换文件 Tab 和空间上下文。
- 生产左侧只有一个连续导航容器；具体空间在内容区以第一层文件夹展示。
- 预览左侧导航是单一连续 Tab 列表，没有两个独立导航组。

验证命令包括相关 Go 包测试、完整前端测试、生产构建、OpenAPI 嵌入副本一致性检查和 `git diff --check`。

## 10. 不在本次范围

- 不实现个人目录直接授权给成员的旧“目录协作”模型。
- 不允许成员配置宿主机路径或外部 NAS 挂载。
- 不新增邀请邮件、待接受邀请、团队配额、审批流或组织层级。
- 不修改共享空间永久删除的现有全局管理员治理入口。
- 不处理第 8 节两个 P2 的代码修复。
