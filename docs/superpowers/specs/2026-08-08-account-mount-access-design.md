# 账号、挂载与内容授权设计

状态：已确认并实施
日期：2026-08-08
决策：采用账号—挂载模型、受限挂载方案 B 和成员端信息架构方案 A

## 1. 文档地位

本文是 Omnora 账号、个人文件、共用挂载、协作和管理员治理的权威设计。代码、数据库、OpenAPI 和 MCP 契约已按本文实施；仓库中保留的旧坐标仅用于负向拒绝、离线迁移不变量或历史资料。

本文对 Space、账号、个人目录、挂载授权、目录协作及其资源关系具有最高业务模型优先级。安全模型可以增加不改变这些资源关系的 fail-closed 约束；其他文档的职责和冲突裁决统一以[文档地图](../../README.md)为准。

本文取代以下设计中的 Space 相关结论：

- [个人存储、直接挂载与文件夹协作设计](2026-08-07-personal-storage-and-folder-collaboration-design.md)；
- [成员空间目录导航设计](2026-08-08-member-space-navigation-design.md)；
- [共享空间生命周期设计](2026-08-06-shared-space-lifecycle-design.md)。

Omnora 尚未正式发布，本次改造不保留旧 Space 数据、接口、Token、分享或前端状态的兼容层。实施时可以使用破坏性数据库迁移和接口替换，但必须保证文件系统中的真实文件不因控制面迁移或解除挂载而被删除。

## 2. 核心决策

### 2.1 层级

目标模型只有三个业务层级：

```text
账号
├── 我的文件：默认挂载中当前账号唯一的个人目录
├── 共用存储：当前账号获权的 0..N 个共用挂载
└── 协作：当前账号收到或发出的 0..N 个个人目录协作
```

- 账号是身份和授权主体。
- 挂载是独立的存储根和共用内容授权边界。
- 文件或目录是挂载或个人目录中的实际内容对象。
- Space 不再是业务对象，不存在个人空间、团队空间、空间成员或空间 ACL。
- 多个挂载即使服务同一个团队，也分别维护自己的账号授权，不共享一套团队权限。

### 2.2 内容权限与系统权限分离

文件内容权限只有两档：

| 权限 | 能力 |
| --- | --- |
| `viewer` | 浏览、搜索授权范围、预览和下载 |
| `editor` | 包含 `viewer`，并可在授权范围内新建、上传、修改、复制、移动、改名和删除内容 |

不再存在内容层 `manager`。系统管理员管理账号、挂载配置和挂载授权，但管理员身份、挂载创建者身份和治理权限都不会自动授予文件内容权限。

不同入口的内容权来源为：

```text
个人目录本人访问 = 所有者隐式完整权限
共用挂载访问     = mount_grants 中的 viewer/editor
个人目录协作访问 = folder_collaborations 中的 viewer/editor
AI/MCP 访问      = 账号自己的个人目录权限 + 当前有效 mount_grants
                   （明确排除 folder_collaborations）
                   ∩ Token scope ∩ Token 边界
                   ∩ 挂载状态/身份/模式 ∩ 对象状态
```

## 3. 默认个人文件

### 3.1 唯一默认挂载

系统首次初始化时创建且只创建一个受保护的系统默认挂载。该挂载用于承载所有账号的个人目录，不作为普通共用挂载向成员或管理员暴露。

默认挂载必须满足：

- 用途固定为 `personal_default`；
- 存储来源为系统管理目录；
- 配置模式固定为 `read_write`，不允许管理端主动改为只读；底层不可写、离线或身份异常时进入系统判定的 `unavailable` 并 fail-closed；
- 使用按账号个人根裁剪的元数据索引，使“我的文件”可以参加全局搜索而不跨账号泄露；
- 不能删除、由管理员主动停用、改根、改为共用挂载或写入普通挂载授权；
- 成员端只显示“我的文件”，不显示默认挂载名称和其他账号的目录；
- 在认证成员上下文中，任意账号都不能通过猜测兄弟目录路径、文件 ID、搜索、普通文件接口或 MCP 越过自己的个人根；独立匿名公开分享会话只访问分享对象，不给账号增加个人目录权限；
- 管理员没有协作授权时，也不能浏览其他账号的个人文件。

### 3.2 每账号一个个人目录

- 初始管理员在系统初始化时自动获得个人目录。
- 新增账号时自动创建且只创建一个个人目录，不需要额外配置。
- 个人目录是默认挂载中的隔离子树，不是独立挂载记录。
- 个人目录所有者对自己的目录拥有隐式完整内容权限。
- 个人目录物理名称使用稳定 `account_id`，例如 `<personal-root>/<account-id>`。修改账号显示名称只改展示，不改物理目录名和对象边界。

账号记录与个人目录必须作为一个完整业务操作交付。数据库与文件系统无法使用同一个原子事务时，服务端必须有明确的准备、补偿和重试状态，不能留下“账号可登录但没有个人目录”或“孤立目录已可被错误复用”的半成品。

账号删除时保留个人目录和全部物理文件，但立即撤销该账号的登录、Token、分享、协作和内容访问。`personal_directories` 保留不可复用的删除账号绑定或 tombstone；以后使用相同邮箱、登录名或显示名创建的新账号必须获得新的账号 ID 和新个人目录，不能自动继承旧目录。

## 4. 共用挂载

### 4.1 定义和注册

除唯一默认挂载外，后续添加的挂载全部是接入既有 NAS 目录的外部共用挂载。Omnora 不创建托管共用挂载；需要新的共用目录时，管理员先在 NAS 创建并映射目录，再注册为挂载。共用挂载不会因为当前只有一个或零个获权账号而变成个人挂载。

管理员注册外部 NAS 目录时：

- 选中的目录本身就是挂载根；
- 不创建 `<space-id>`、账号 ID 或其他隐式业务子目录；
- 目录中的现有文件在授权和身份校验通过后直接可见；
- 仍必须验证规范化路径、符号链接、bind 来源、路径重叠、读写能力和挂载身份；
- 每个挂载独立设置只读/读写和索引模式；
- 允许创建暂时没有任何账号获得内容权限的挂载。

“共用”描述的是挂载用途，不等于“所有账号都能看”。只有存在有效 `viewer` 或 `editor` 授权的账号才可以在文件页、搜索、REST 和 MCP 中发现并访问它。

### 4.2 独立授权

每个共用挂载使用独立的 `mount_grants`：

- 每条记录只绑定一个挂载和一个账号；
- 同一挂载与账号最多一条有效授权；
- 权限只能是 `viewer` 或 `editor`；
- 新建挂载默认零授权；
- 授权、降权或撤销立即影响 Web、REST、MCP、活动上传和 Transfer Ticket；
- 管理员和挂载创建者也必须显式获得授权才能浏览内容；
- 未授权主体通过直接 ID 请求访问时返回不泄露对象存在性的结果。

## 5. 普通挂载与受限挂载

挂载治理属性与存储来源、内容用途是三个独立维度，不应复用同一个 `kind` 字段：

| 维度 | 固定值 | 说明 |
| --- | --- | --- |
| `purpose` | `personal_default \| common` | 默认个人文件或共用存储 |
| `storage_kind` | `managed \| external` | `personal_default` 固定为 `managed`；`common` 固定为 `external` |
| `governance` | `system \| normal \| restricted` | 系统保护、普通管理或受限管理 |

### 5.1 普通挂载

- 所有系统管理员都能发现并管理挂载控制面。
- 管理员可配置挂载、索引和账号授权。
- 管理权限不等于内容权限；未被授予 `viewer/editor` 的管理员不能浏览文件。

### 5.2 受限挂载：方案 B

受限挂载用于让初始管理员把挂载的存在和治理信息在常规产品入口与被动系统输出中对普通管理员隐藏。

- 只有初始管理员能通过治理控制面发现、创建、配置、重新验证、删除受限挂载并管理其授权名单。
- 普通管理员不能通过管理接口把自己或他人加入受限挂载。
- 普通管理员未获内容授权时，管理列表、详情和直接 ID 请求都不能暴露挂载存在；直接请求应表现为 `404`，而不是“对象存在但无权管理”。
- 普通管理员被授予 `viewer/editor` 后，只在成员内容面获得相应文件权限，仍不能看到治理入口、授权名单或受限状态。
- 初始管理员未被授予内容权限时，只能管理控制面，不能浏览文件。
- 受限挂载的隐藏必须覆盖管理 API、管理列表、索引任务、挂载健康、全局统计、审计视图、备份清单、搜索、MCP 和普通错误信息，不能只隐藏前端卡片。
- 该能力只防止 Omnora 普通管理员发现；不能对 NAS root、容器 root 或数据库直接访问者提供保密承诺。

普通管理员仍可创建普通挂载并修改普通挂载显示名称，因此候选路径必须与包括受限挂载在内的全部活跃挂载做身份重叠校验，候选显示名称也必须满足全局唯一。命中隐藏对象、保留资源、并发冲突或其他不可用条件时统一返回不含对象信息的 `mount_unavailable`，并限速、审计；不得为隐藏性而放行不安全的重叠挂载。本方案不承诺抵御普通管理员对已知候选名称或路径发起的主动资源占用探测，只承诺列表、直接对象请求和普通系统输出不泄露受限挂载身份、名称、路径或治理信息。

普通/受限治理类型在创建挂载时确定，之后不能切换。需要改变治理类型时，先解除 Omnora 挂载注册，再用新的挂载 ID 重新注册同一物理路径；真实目录和文件不移动，旧授权、Token、分享、索引和活动任务不得恢复。

挂载激活后，`root_path`、`purpose`、`storage_kind` 和 `governance` 都不可修改；变更任一字段必须解除并使用新挂载 ID 注册。具有治理权的管理员可以修改显示名称、应用读写模式、索引开关和账号授权，并在需要时重新验证挂载身份。

## 6. 管理员身份

系统身份分为：

- 初始管理员 `initial_admin`；
- 普通管理员 `admin`；
- 普通成员 `member`。

规则如下：

- 初始管理员与普通管理员对普通业务资源和普通挂载具有相同日常管理能力。
- 任一管理员可以把普通成员提升为普通管理员。
- 任一管理员可以停用、恢复或删除普通成员。
- 任一管理员可以降级、停用、恢复或删除其他普通管理员。
- 管理员不能提升、降级、停用或删除当前登录的自己。
- 初始管理员可以操作普通管理员和成员。
- 普通管理员不能降级、停用、删除初始管理员，也不能改变其受保护身份。
- 初始管理员额外拥有受限挂载独占治理权和初始身份保护权；因此不能再笼统表述为“两类管理员权限完全相同”。
- 管理员的系统权限与内容权限始终分离。

## 7. 个人目录协作

### 7.1 基本规则

个人目录所有者可以把整个个人根目录或其中任意子目录授权给其他活跃账号协作：

- 每个接收账号分别获得 `viewer` 或 `editor`；
- 协作指向原目录，不复制、不移动文件，也不创建挂载；
- 接收者只能从独立“协作”入口访问，协作目录不出现在“共用存储”；
- 撤销、接收账号停用、来源对象失效或授权边界变化后立即拒绝后续访问；
- 分享整个个人根目录时，界面必须明确警告：当前内容以及未来新增到个人根的内容都会对接收者可见。
- `editor` 可以修改协作根内的内容，但不能改名、移动或删除协作根本身。
- 同一接收账号不能同时持有父子目录重叠授权；创建重叠授权时直接拒绝。
- 收到的协作不能创建匿名公开分享，也不能再授权给第三人。
- 从收到的协作执行“保存到我的文件”始终是复制，不从所有者目录移除原对象。

账号间协作与匿名公开链接分享是不同能力：前者以登录账号和实时权限为基础，后者以独立的匿名访客主体和短期分享会话为基础。认证成员上下文只能访问自己的个人根或明确收到的目录协作；有效公开分享会话只能访问分享对象，不会给登录账号增加个人目录权限。匿名公开分享继续保留：个人文件由所有者创建；共用挂载默认允许 `editor` 创建，但具有该挂载治理权的管理员可以关闭，关闭后既有分享及派生会话立即失效；收到的协作永远不能创建匿名公开分享。普通挂载分享策略由任一管理员治理，受限挂载只由初始管理员治理；挂载分享只在对应治理范围内可见和撤销。所有管理员可以查看并撤销个人目录公开分享的最小安全元数据，但不能查看路径、文件正文、密码或分享秘密。所有管理员可以查看账号 Token 的通用安全元数据并撤销 Token，但无权资源边界必须统一脱敏，不能据此发现受限挂载。全局公开分享路由组仍是额外门禁。

### 7.2 数据边界

`folder_collaborations` 至少记录：

- 来源账号和来源个人目录；
- 接收账号；
- 授权根相对路径和根对象身份；
- `viewer/editor`；
- 创建、撤销和审计字段。

协作访问必须每次重验接收账号、授权记录、授权根对象、默认挂载身份、读写模式和路径边界。不能只在创建协作时验证一次。

## 8. 成员端信息架构：方案 A

成员端保留一个“文件”入口和一个独立“协作”入口：

```text
文件
├── 我的文件
│   └── 当前账号唯一的个人目录
└── 共用存储
    └── 当前账号获权的共用挂载卡片

协作
├── 与我协作
└── 我发起的协作
```

- 不再展示“个人空间”“团队空间”或空间目录。
- 点击“我的文件”直接进入个人目录。
- 共用存储按挂载列出，只显示当前账号获权的挂载。
- 零授权挂载只存在于有权查看它的管理控制面。
- 受限挂载对普通管理员的成员内容面仍按内容授权显示，不暴露其受限治理属性。

## 9. API、MCP 与 AI Token 目标契约

### 9.1 定位方式

- 普通共用挂载：`mountId + relativePath`。
- 我的文件：账号作用域的个人文件资源，由服务端解析到默认挂载中的当前账号隔离根；客户端不能提交其他账号 ID 来改变根。
- 收到的协作：仅成员 Web 和会话 REST 使用 `collaborationId + relativePath`，由服务端解析来源个人根和授权边界；MCP/AI Token 不接受 `collaborationId`。

默认挂载不应作为普通挂载直接暴露给成员。否则同一个 `mountId` 会对不同账号代表不同根，并与协作来源混淆。

AI Token 可以选择“当前账号全部内容源”边界：它动态覆盖账号自己的个人目录和当前获权的全部共用挂载，新授予挂载自动进入边界，撤销挂载授权后立即失效。收到的协作不是挂载，不进入该广域边界，也不能建立 MCP Token boundary。

新 MCP 文件工具必须使用显式内容源联合类型：个人源为 `{source: "personal", path}`，不能携带账号 ID 或默认挂载 ID；共用源为 `{source: "common_mount", mountId, path}`。`mounts.list` 只列共用挂载，协作源不进入 MCP。最终字段名在迁移实现时与 catalog、OpenAPI 和协议测试一次性冻结，但不得退化为可选 `mountId` 或客户端账号 ID 推断资源类型。

AI Token 用于 MCP、Transfer Ticket，以及新 OpenAPI 逐条白名单化的文件 REST 路由；不得自动进入账号、会话或管理员控制面。成员会话 REST 可以访问收到的协作，AI Token REST 与 MCP 一样拒绝协作源。

### 9.2 破坏性接口调整

实施时必须同步完成：

- 删除 `spaces.list`；
- `mounts.list` 直接返回当前账号可访问的共用挂载；
- 将 `spaces:read` 改为 `mounts:read`；
- 所有 REST/MCP 文件参数删除 `spaceId`；
- AI Token boundary、分享、上传、索引、文件对象、传输票据和文件操作源/目标删除 `space_id`；
- 个人文件与协作使用独立、不接受宿主机绝对路径的资源定位；
- 重新计算 MCP 工具数、scope 数和高风险工具数，并同步工具目录、OpenAPI、Web 类型、Inspector 文档和协议测试。

迁移后的 catalog 中，永久删除、移动、回收站清理、公开分享变更和覆盖已有文件内容等高风险工具必须同时具备显式 scope 和逐次 MRTR；具体工具清单与数量以迁移后的 catalog 为准。

工具和 scope 数量以当前 `internal/mcpapi` catalog 为准；`spaces.list` 和旧资源坐标不属于现行契约。

### 9.3 有效权限

```text
有效内容权限 = 路由组可用
             ∩ 账号有效
             ∩ 当前入口支持的账号实时内容权限来源
               （AI Token 只含个人目录所有权与 mount_grants；会话入口可含协作）
             ∩ Token 有效且用途匹配（使用 Token 时）
             ∩ Token scope 与资源边界（使用 Token 时）
             ∩ 挂载状态、身份和读写模式
             ∩ 路径边界、对象身份与保留命名空间规则
             ∩ 配额、限速和并发限制
```

管理员系统权限不进入内容权限公式。Token 永远不能把账号没有的内容权限放大。

## 10. 搜索、分享与删除

### 10.1 搜索

- “我的文件”只在当前账号个人根内搜索。
- 共用存储搜索只包含当前账号获权且已启用索引的挂载。
- 未授权挂载不得通过命中数、过滤器、错误、统计或过期索引泄露存在。
- 成员 Web 全局搜索覆盖“我的文件 + 当前获权共用挂载 + 当前有效的收到协作”。
- 协作结果必须标记来源账号和“协作”类型，打开时实时复核授权；协作撤销后立即不再返回。
- 同一对象通过多个有效边界可见时只返回一次；“我发起的协作”不重复加入，因为源对象已经在“我的文件”中。
- MCP 搜索只覆盖 Token 允许的个人目录和共用挂载，不因 Web 全局搜索包含协作而扩大 Token 权限。

### 10.2 回收站与跨挂载操作

- 删除者使用自己的个人回收站。删除个人文件、共用挂载文件或收到协作中的文件时，单个文件不超过 200 MB（按 `200 × 1024 × 1024` 字节）才可进入删除者回收站。
- 回收站对象归删除者的回收站界面和容量统计管理；收到协作的文件进入回收站不改变协作根的所有者身份，也不能在回收站中公开分享或再授权。
- 从共用挂载或协作删除到个人回收站是跨存储持久化操作：先预留删除者个人配额，复制到受保护回收站、校验并持久化 journal，再删除源；任何部分失败都不得丢失唯一副本，并必须进入可重试或人工清理终态。
- 恢复时优先回到原位置并重新检查当前 `editor`、挂载和路径状态；原位置或权限已不可用时，恢复到删除者“我的文件/从回收站恢复”，不能覆盖现有对象。
- 超过 200 MB 的文件不能进入回收站；删除时必须转为明确的永久删除流程并再次确认，不能静默永久删除。
- 目录或批量操作只要包含超过 200 MB 的文件，就不能把整批对象放入回收站；用户必须取消、拆分选择，或对整批对象执行带影响摘要的永久删除确认。
- 跨挂载移动要求源端 `editor`、目标端 `editor`，并经过复制、校验、删除源的可恢复流程。
- 从收到的协作保存到自己的个人目录只提供“复制/保存”，不提供移出所有者目录的跨边界移动。
- 进入任何回收站都属于删除状态，立即使该对象的公开分享、下载票据和活动写入失效；恢复后不自动恢复旧分享。

### 10.3 解除共用挂载

解除普通或受限共用挂载要求操作者精确输入当前显示名称，只删除 Omnora 控制面注册，不删除 NAS 上的真实目录和文件。活跃挂载显示名称经过规范化后全局唯一且忽略大小写。挂载 tombstone 永久保留，审计记录按安全审计保留策略保存；挂载授权、Token boundary、分享、Transfer Ticket、上传会话、索引和后台任务同时失效，并记录 `dataDeleted: false`。失效上传会话的临时分片由幂等清理流程处理，不属于必须保留的用户真实文件。

同一物理路径以后允许重新注册，但必须生成新的挂载 ID，旧授权和派生能力不能恢复。

默认个人挂载不得使用该流程。受限挂载只能由初始管理员解除，且相关审计和统计不能向无权普通管理员泄露对象存在。

## 11. 目标数据模型

建议的核心表和约束：

| 表 | 作用 | 关键约束 |
| --- | --- | --- |
| `accounts` | 登录身份与系统角色 | 仅一个受保护的 `initial_admin` |
| `mounts` | 默认挂载和共用挂载 | `purpose/storage_kind/governance` 分离；仅一个 `personal_default` |
| `personal_directories` | 账号到默认挂载隔离根的映射 | `account_id` 唯一；根路径/对象身份唯一 |
| `mount_grants` | 共用挂载内容授权 | `(mount_id, account_id)` 唯一；仅 `viewer/editor`；禁止指向默认挂载 |
| `folder_collaborations` | 个人根或子目录协作 | 来源、接收人、根对象身份、权限和撤销状态 |

必须删除 `spaces`、`space_members` 和业务表中的 `space_id`。由于产品尚未发布，不设计双写、旧 ID 转换或旧 Token 兼容层；测试数据和旧凭据可以随破坏性迁移失效。

## 12. 安全不变量

1. 管理权限从不隐式授予内容权限。
2. 默认挂载的账号隔离根不能通过普通挂载授权绕过。
3. 未授权账号不能从列表、搜索、MCP、审计、统计或错误中发现共用挂载内容。
4. 受限挂载对普通管理员的隐藏是后端授权规则，不是 UI 约定。
5. 初始管理员未获内容授权时也不能读取受限挂载内容。
6. 协作不能越过被授权的个人目录根，撤销后所有派生能力立即失效。
7. AI Token 只能缩小账号的实时权限，不能扩大权限。
8. 解除挂载和控制面迁移不能删除真实外部文件。
9. 所有目录访问继续 fail-closed 地校验路径、对象和挂载身份。
10. 账号删除、解除挂载和治理类型重建都不能自动复用旧授权或对象身份。

## 13. 最低验收

- 初始化只创建一个受保护默认挂载，初始管理员个人目录自动可用。
- 新增账号成功时个人目录一定可用；失败时没有可登录的半成品账号。
- 账号不能猜路径访问默认挂载中的兄弟个人目录。
- 普通管理员没有协作授权时不能读取其他账号的个人目录。
- 个人根和任意子目录都能按 `viewer/editor` 发起协作，撤销即时生效。
- 共用挂载允许零授权；未授权账号在文件列表、搜索、REST、MCP 和直接 ID 请求中均不可发现。
- 普通挂载由所有管理员治理，但内容访问仍要求显式授权。
- 普通管理员不能通过常规产品入口直接发现或管理受限挂载，也不能自授予权限；已知候选资源的主动占用探测仅适用第 5.2 节定义的残余侧信道边界。
- 获权普通管理员只能按内容权限使用受限挂载，不能进入治理面。
- 初始管理员未获内容授权时不能浏览受限挂载文件。
- 普通管理员之间可按规则相互管理，但不能操作初始管理员身份。
- 新 API、MCP、数据库和 Web 状态中不存在 Space 业务实体或空间 ACL。
- 共用挂载解除注册不删除真实文件，但所有派生凭据和任务立即失效。
- 默认挂载的删除、改根、普通授权均被服务端拒绝。
- 删除账号后个人目录和物理文件保留，旧账号所有访问立即失效，新账号不能继承旧目录。
- 协作 `editor` 只能修改根内内容；重叠授权、公开分享和再授权均被拒绝。
- 账号广域 MCP Token 覆盖自己的个人目录和全部获权共用挂载，但不覆盖收到的协作。
- 200 MB 以内的删除进入删除者自己的回收站；更大文件只能走明确永久删除确认。
- Web 全局搜索包含当前有效的收到协作并正确标记、去重和实时复核。
- 普通/受限治理类型创建后不可切换；重新注册同一路径使用新挂载 ID。

## 14. 故障修复

默认挂载离线、身份漂移、个人目录丢失或初始化部分失败时必须 fail-closed：停止相关内容访问、搜索、分享、Token 和写入，并显示可诊断状态。系统不得静默创建同名空目录冒充原数据。

修复流程只允许初始管理员执行，至少包括重新验证默认挂载身份、核对账号与个人目录映射、选择恢复原目录或明确创建替代目录、处理孤立准备状态并写入审计。任何修复都不能把已删除账号的保留目录自动绑定给新账号。
