# 共享空间编辑与永久删除设计

## 目标

为系统管理员提供共享空间重命名和永久删除能力；个人空间继续由系统管理，不允许这两类操作。本功能不提供停用或恢复。

## 语义与边界

- 重命名只修改 `spaces.name`，不改变空间 ID、成员 ACL、挂载归属、分享或 Token 边界。
- 删除只删除 Omnora 控制面记录：空间、成员、挂载注册、文件/目录索引、分享及会话、Token 边界、上传记录和相关任务状态。
- 删除不删除服务器上的真实目录、用户文件或上传临时文件，并以 `dataDeleted: false` 返回和审计。
- 仅系统管理员可调用接口；`personal` 空间返回 `409 personal_space_protected`。
- 删除请求要求提交当前空间名称二次确认；名称不匹配返回 `409 confirmation_required`。
- 所有空间及其挂载/关联控制面清理在一个 SQLite 事务内完成，失败整体回滚；审计保留可读的空间名称和挂载摘要。

## API

- `PATCH /api/v1/admin/spaces/{spaceId}`，请求 `{ "name": "..." }`，返回更新后的 `AdminSpace`。
- `DELETE /api/v1/admin/spaces/{spaceId}`，请求 `{ "name": "当前空间名称" }`，返回 `{ "id", "deleted": true, "deleteData": false, "dataDeleted": false }`。
- 共享空间删除自动清理挂载注册；已有的挂载清理语义（不删除真实文件、撤销分享、清理索引、取消上传和任务）在空间事务中复用等价的事务内逻辑。

## 前端

空间选择器旁仅对 `shared` 空间显示“修改名称”和“永久删除”。重命名弹窗预填名称；删除弹窗要求精确输入当前名称，明确“不可恢复，但服务器文件保留”。成功后刷新列表并选择剩余空间；失败保留弹窗和输入，展示结构化错误。

## 验证

后端测试覆盖管理员权限、个人空间保护、非法名称、重命名持久化、删除确认、级联控制面清理、任务取消、审计保留、宿主文件保留和事务回滚。前端测试/构建覆盖双语文案、API 调用和共享空间按钮条件。OpenAPI 源文件与嵌入副本保持同步，需求、设计、安全和验收文档同步更新。
