# 文档中心左侧分类导航设计

## 背景

当前成员端「文档」页面使用横向按钮组切换 MCP、OpenAPI 和项目问答。三个按钮的命名粒度不一致，选中态使用较重的嵌套蓝色描边，视觉上像独立操作按钮而不是文档目录，导致页面层级和分类关系不清晰。

## 目标

- 将文档分类表现为稳定的目录导航，而不是孤立的按钮组。
- 桌面端提升分类与正文之间的层级关系。
- 移动端保持紧凑，使用下拉选择避免占用横向空间。
- 不改变已有文档内容、路由、接口和主题同步行为。
- 保持 MCP 作为默认分类。

## 非目标

- 不重写 MCP、OpenAPI 或 FAQ 的内容。
- 不增加新的文档分类。
- 不修改全局成员端侧边栏。
- 不改变主题偏好加载与同步逻辑。

## 方案

### 桌面端布局

`MemberDocsPanel` 保留现有标题和描述，在标题区下方将分类控件改为两列布局：

- 左列：文档目录导航，包含三项：
  - MCP 接入
  - REST 契约
  - 项目问答
- 右列：当前分类内容。

左侧目录属于文档页面内部导航，不替代全局成员端导航。当前项采用浅色背景、左侧强调线和高对比文字；普通项使用弱化文字，悬停时提升对比度。移除现有横向按钮组的厚重边框和嵌套选中描边。

### 移动端布局

在窄屏断点下隐藏桌面端左侧目录，显示原生 `<select>` 下拉框。下拉框位于标题描述之后、正文之前，使用明确的无障碍标签。下拉框与桌面目录共享同一个 `DocsTab` 状态，选择后直接渲染对应内容。

### 状态与渲染

继续使用现有 `DocsTab` 类型和 `tab` 状态：

- 初始值保持 `mcp`。
- 桌面端目录项通过 `setTab` 切换。
- 移动端 `<select>` 通过 `setTab` 切换。
- MCP、OpenAPI、FAQ 的现有条件渲染逻辑保持不变。

不引入 URL 查询参数或新的持久化状态，避免文档分类导航与会话主题状态产生耦合。

## 组件与样式边界

- `web/src/member/MemberDocsPanel.tsx`
  - 将现有 `member-admin-subnav` 替换为文档专用的目录结构。
  - 增加桌面导航和移动端下拉控件。
  - 保持现有错误、加载、OpenAPI 表格和 FAQ 渲染逻辑。
- `web/src/member/member-files.css`
  - 增加文档目录两列布局、目录项、当前项和移动端下拉样式。
  - 使用现有主题变量，不写死浅色或深色背景。
  - 在现有成员端窄屏断点下切换为单列布局。
- `web/src/member/i18n.ts`
  - 增加目录项和下拉框标签所需的中英文文案。
  - 不修改已有文档正文文案。

## 可访问性

- 桌面目录使用 `<nav>`，提供文档分类导航标签。
- 当前目录项使用 `aria-current="page"`。
- 移动端下拉框使用 `<label>` 或等效的 `aria-label`。
- 保持键盘可操作，不依赖颜色单独表达选中状态。
- 选中态在白色和深色主题下都满足可读对比度。

## 测试与验收

增加或更新前端测试，至少覆盖：

1. 默认渲染 MCP 内容，并显示三个文档分类。
2. 点击桌面端「REST 契约」后显示 OpenAPI 内容。
3. 点击桌面端「项目问答」后显示 FAQ 内容。
4. 通过移动端下拉框切换分类时，内容与 `DocsTab` 状态一致。
5. 文档页面未引入旧 Space API 请求。
6. 主题同步相关测试继续通过。

验收标准：

- 桌面端分类视觉上属于文档目录，左侧目录与正文关系明确。
- 移动端不出现横向溢出，分类可以通过下拉框完成切换。
- `cd web && npm test -- --run` 通过。
- `cd web && npm run build` 通过。
- `git diff --check` 通过。

2. 修改 `MemberDocsPanel` 的结构与文案。
3. 增加响应式 CSS 和主题变量样式。
4. 运行前端测试、构建和差异检查。
5. 进行本地页面验收后按中文功能提交。
